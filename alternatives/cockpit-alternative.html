Why System Administrators Are Replacing Cockpit with SSH Desktop

A technical architectural breakdown of client-side local rendering vs remote daemon overhead.

🚫

Zero Attack Surface: No Port 9090

Cockpit Project requires opening public web port 9090 (or reverse proxying it through Nginx/Apache), exposing a web login interface to botnets, automated brute-force scripts, and web vulnerabilities. SSH Desktop operates exclusively over standard SSH port 22. If your server is hardened with SSH key-only auth and Fail2ban, your attack surface remains zero.

📉

Zero Idle RAM Overhead on Host

Cockpit runs the cockpit-ws and cockpit-bridge daemons continuously on the remote Linux host, consuming between 60 MB and 150 MB of memory even when no admin is logged in. On cost-sensitive 512 MB or 1 GB cloud VPS instances (AWS t4g.nano, DigitalOcean $4 droplet), this memory waste starves your production databases and Docker containers. SSH Desktop runs 100% locally on your laptop, consuming 0 MB of server RAM.

🖥️

Authentic Desktop Shell vs Web Portal

Cockpit gives you a browser-based web dashboard with basic system gauges. SSH Desktop provides a full macOS Sonoma Cloud Desktop workspace featuring 25 native management apps: Mission Control, Dock, GPU terminal with split panes, dual-pane SFTP, in-place Monaco code editor, visual crontab builder, and 12-engine database studio.

How to Migrate from Cockpit to SSH Desktop in 2 Minutes

Decommissioning Cockpit frees up host memory and instantly closes port 9090 without losing any administrative capabilities.

Step 1: Stop and Disable the Cockpit Socket & Service

Run the following commands on your Linux host to release port 9090 and reclaim RAM:

sudo systemctl stop cockpit.socket cockpit.service
sudo systemctl disable cockpit.socket cockpit.service
sudo ufw delete allow 9090/tcp  # Or remove 9090 from security groups

Step 2: Download and Launch SSH Desktop Locally

Install SSH Desktop on your Windows, macOS, or Linux workstation:

# Or download the desktop installer directly from sshdesktop.com/download.html
curl -fsSL https://sshdesktop.com/install.sh | bash

Step 3: Connect Over Pure SSH Port 22

Enter your server IP and SSH key or credentials. SSH Desktop instantly renders the visual macOS Sonoma desktop shell. You can manage systemd services, restart Docker containers, monitor hardware telemetry, and edit configuration files with zero server daemons.

Cockpit vs SSH Desktop FAQ

Can SSH Desktop manage Docker containers like Cockpit's Podman plugin?

Yes! SSH Desktop features a dedicated visual Docker Container Hub. You can inspect container states, start/stop/restart containers, stream live terminal logs, open interactive docker exec shells, and prune unused images over pure SSH without installing any Podman or Cockpit modules on the server.

Does SSH Desktop work on RHEL, AlmaLinux, and Rocky Linux?

Yes. Cockpit is heavily tied to Fedora and Red Hat Enterprise Linux ecosystems. SSH Desktop is distribution-agnostic: it manages Ubuntu, Debian, CentOS, RHEL, AlmaLinux, Rocky Linux, Fedora, Arch Linux, Alpine, and OpenSUSE out of the box.
