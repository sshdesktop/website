How to Set Up Cloudflare Tunnel for SSH (Zero Trust, No Open Ports): 2026 Guide

Zero Trust Security By SSH Desktop Engineering Team • Updated November 2026 • 10 min read

The gold standard of server security is simple: if an attacker cannot reach your port, they cannot exploit your software. Traditionally, remote SSH administration required opening port 22 through firewalls and routers, exposing systems to ceaseless brute-force scans and zero-day vulnerabilities. Cloudflare Tunnel eliminates open inbound ports entirely.

Executive Summary

Cloudflare Tunnel (cloudflared) establishes a lightweight outbound-only connection from your server to Cloudflare's global edge network. By integrating Cloudflare Access, you can enforce Multi-Factor Authentication (MFA) and Identity Provider (Google, GitHub, Okta) checks before a terminal session is ever permitted to reach your OpenSSH daemon.

1. Installing cloudflared on Linux Server

# Download and install cloudflared on Ubuntu/Debian:
curl -fsSL https://pkg.cloudflare.com/cloudflare-main.gpg | sudo tee /etc/apt/trusted.gpg.d/cloudflare.gpg >/dev/null
echo "deb https://pkg.cloudflare.com/cloudflared bullseye main" | sudo tee /etc/apt/sources.list.d/cloudflared.list
sudo apt update && sudo apt install -y cloudflared

# Authenticate server to your Cloudflare account:
cloudflared tunnel login

2. Creating and Routing the SSH Tunnel

# Create named tunnel (e.g. 'prod-server'):
cloudflared tunnel create prod-server

# Associate a subdomain with the tunnel:
cloudflared tunnel route dns prod-server ssh.yourdomain.com

Configuring /etc/cloudflared/config.yml

tunnel: <TUNNEL_UUID>
credentials-file: /root/.cloudflared/<TUNNEL_UUID>.json

ingress:
  - hostname: ssh.yourdomain.com
    service: ssh://localhost:22
  - service: http_status:404
# Install as systemd service and run:
sudo cloudflared service install
sudo systemctl enable --now cloudflared

3. Configuring Client Workstation (~/.ssh/config)

Install cloudflared on your workstation (Windows, macOS, or Linux). Then configure your SSH client to tunnel requests transparently through Cloudflare Access: 

Host ssh.yourdomain.com
  ProxyCommand cloudflared access ssh --hostname %h
  User deploy
  IdentityFile ~/.ssh/id_ed25519

Now You Can Close Port 22 in UFW!

With Cloudflare Tunnel active, delete your public SSH firewall rule: 

sudo ufw delete allow 22/tcp
sudo ufw status
# Result: Port 22 is completely hidden from Shodan and public port scanners!

4. Frequently Asked Questions

Why is Cloudflare Tunnel safer than standard port forwarding?

Traditional SSH access requires port 22 (or a custom port) to be open in your firewall, leaving it discoverable by Shodan and internet scanning bots. Cloudflare Tunnel opens only outbound lightweight HTTPS/QUIC connections to Cloudflare's edge servers. Your firewall has zero inbound listening ports open.

Can I connect to home lab servers behind Carrier-Grade NAT (CGNAT)?

Yes! Because cloudflared initiates outbound connections to Cloudflare, it seamlessly bypasses CGNAT, dynamic home IP addresses, and restrictive office firewalls without requiring dynamic DNS (DDNS) or port forwarding on your router.

What must be installed on the client machine to connect over the tunnel?

The client machine only needs the cloudflared binary installed. In your ~/.ssh/config file, add a ProxyCommand directive: ProxyCommand cloudflared access ssh --hostname %h. Your regular ssh commands will then tunnel transparently.
