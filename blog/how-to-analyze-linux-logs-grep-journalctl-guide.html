How to Search & Analyze Linux Logs: grep, journalctl & zgrep (2026 Guide)

Published: November 2026 • 10 min read • By SSH Desktop Engineering Team

When an application crashes in production or a suspicious IP address probes your server, the exact cause is always recorded in one place: system and application logs.

However, production servers generate millions of log lines per day across /var/log/ and journald. Sifting through gigabytes of text files to find the proverbial needle in the haystack requires knowing the right tools.

In this guide, you will master essential grep flags, search compressed .gz log archives on the fly with zgrep, extract structured time windows with journalctl, and explore visual multi-file log search in SSH Desktop.

1. The Essential grep Flags Cheatsheet

Flag Meaning Example Use Case
-i Case-insensitive search grep -i "error" app.log
-r or -R Recursive search in directories grep -rn "500" /var/log/nginx/
-n Display line numbers Helps locate code lines in source files
-v Invert match (exclude lines) grep -v "healthcheck" access.log
-E Extended regular expressions (regex) grep -E "(404|500|502)" access.log
-C <N> Context: show N lines before & after grep -C 5 "Exception" app.log
-c Count matching lines instead of printing grep -c "Failed password" /var/log/auth.log

2. Seeing Stack Traces: Context Flags (-B, -A, -C)

Searching for "NullPointerException" or "Fatal error" often only shows the single error line. To see the full stack trace and the events leading up to the crash, use context flags:

# 5 lines Before and 10 lines After the match:
grep -B 5 -A 10 "Fatal error" /var/log/app/error.log

# Or 5 lines of surrounding context on both sides:
grep -C 5 "SQLSTATE" /var/log/mysql/error.log

3. Searching Rotated .gz Archives with zgrep

Linux logrotate automatically compresses older log files using gzip (e.g. syslog.2.gz, access.log.4.gz).

Never waste time running gunzip to decompress files manually. Use zgrep:

# Search all compressed auth log archives for SSH brute-force attempts:
sudo zgrep -i "failed password" /var/log/auth.log.*.gz

# Count failed logins per archive:
sudo zgrep -c "Failed password" /var/log/auth.log.*.gz

4. Filtering systemd Logs with journalctl

For modern services managed by systemd, journalctl allows querying by unit, timestamp, and severity level:

# Show logs for Nginx from the last 2 hours:
sudo journalctl -u nginx --since "2 hours ago"

# Show logs from a specific date window:
sudo journalctl -u myapp --since "2026-11-15 09:00:00" --until "2026-11-15 12:00:00"

# Filter by priority: only Warnings (4) and Errors (3):
sudo journalctl -p warning..err -n 50
