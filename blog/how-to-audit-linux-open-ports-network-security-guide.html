How to Check Open Ports on Linux: ss, lsof & nmap (2026 Security Guide)

Published: November 2026 • 9 min read • By SSH Desktop Engineering Team

In cybersecurity, every open network port is an entry point into your server. If a developer accidentally binds a test database to 0.0.0.0:3306 or a forgotten Node.js debug server is listening on port 9229, your server is vulnerable to remote compromise.

Regularly auditing open TCP and UDP listening ports is a foundational practice in server hardening.

In this guide, you will learn how to inspect active listening sockets using modern ss, find the exact process ID with lsof, verify public exposure with nmap, and audit network ports visually with SSH Desktop.

1. The Gold Standard: ss -tulpn

Legacy tutorials frequently instruct users to run netstat. However, netstat was officially deprecated over a decade ago. The modern, high-speed replacement is ss (Socket Statistics):

sudo ss -tulpn

Flags Breakdown:

  • -t: Display TCP sockets.
  • -u: Display UDP sockets.
  • -l: Show listening sockets only (ignores established client connections).
  • -p: Show the process name and PID.
  • -n: Show numeric port numbers (e.g. 22 instead of translating to ssh).

Reading the Output:

Netid State Recv-Q Send-Q Local Address:Port Peer Address:PortProcess
tcp LISTEN 0 128 0.0.0.0:22 0.0.0.0:* users:(("sshd",pid=912,fd=3))
tcp LISTEN 0 511 127.0.0.1:3306 0.0.0.0:* users:(("mysqld",pid=1420,fd=21))
tcp LISTEN 0 511 0.0.0.0:80 0.0.0.0:* users:(("nginx",pid=1102,fd=6))
Crucial Security Audit Tip: Look at the Local Address column:
  • 127.0.0.1:3306: Safe! Bound to loopback; only accessible from inside the server.
  • 0.0.0.0:80 or :::80: Accessible from the outside world on all network interfaces.

2. Find Which Process Owns a Specific Port: lsof -i

If you encounter an "Address already in use" error when starting a service, find the blocking PID with lsof:

sudo lsof -i :8080

Output:

COMMAND PID USER FD TYPE DEVICE SIZE/OFF NODE NAME
node 19284 ubuntu 23u IPv4 89210 0t0 TCP *:8080 (LISTEN)

Kill the rogue or hung process cleanly:

sudo kill -15 19284 # Graceful SIGTERM
# Or force kill if unresponsive:
sudo kill -9 19284

3. External Audit with nmap (View What the Internet Sees)

Just because a port is listening on 0.0.0.0 does not mean it is reachable from the public internet. External cloud security groups (AWS, GCP) and host firewalls (UFW) may be filtering packets.

From your local laptop, scan your server's public IP using nmap:

nmap -sT -p 1-10000 198.51.100.42

Look for:

  • open: Service is accessible to the public internet (ensure only 22, 80, 443 are open!).
  • filtered: Packets are dropped by a firewall (secure).
  • closed: No service is listening.
