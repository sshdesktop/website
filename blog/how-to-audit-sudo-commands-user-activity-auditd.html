How to Audit Sudo Commands & User Activity with auditd: 2026 Guide

Meeting modern security compliance standards (SOC 2, ISO 27001, HIPAA, PCI-DSS) requires an immutable, tamper-resistant record of every administrative command executed on production servers. Relying on .bash_history is futile because users can clear or alter it at will. The Linux Audit Framework (auditd) operates at the kernel syscall level, capturing every execution, file modification, and privilege escalation. Learn how to configure auditd in 2026.

The Power of the Linux Audit Daemon

The kernel audit subsystem logs critical security events directly to /var/log/audit/audit.log. Even if a rogue employee executes sudo su and runs dangerous commands as root, auditd maintains an unbroken cryptographic link to their original login identity (auid).

Step 1: Install auditd and Utilities

Install the auditing daemon on Ubuntu or Debian:

sudo apt update
sudo apt install -y auditd audispd-plugins

# Enable and start auditd
sudo systemctl enable --now auditd

On RHEL, Rocky Linux, or Fedora:

sudo dnf install -y audit
sudo systemctl enable --now auditd

Step 2: Configure Audit Rules for Sudo & Commands

Create a persistent audit rule file at /etc/audit/rules.d/sudo.rules:

sudo nano /etc/audit/rules.d/sudo.rules

Add rules to track sudo execution, user authentication, and critical file tampering:

# Record all executions of sudo and su
-a always,exit -F path=/usr/bin/sudo -F perm=x -k sudo_exec
-a always,exit -F path=/usr/bin/su -F perm=x -k su_exec

# Monitor modifications to sudoers and SSH configurations
-w /etc/sudoers -p wa -k sudoers_changes
-w /etc/sudoers.d/ -p wa -k sudoers_changes
-w /etc/ssh/sshd_config -p wa -k sshd_config_changes

# Monitor user account database changes
-w /etc/passwd -p wa -k identity_changes
-w /etc/shadow -p wa -k identity_changes

# Make audit configuration immutable until next system reboot
-e 2

Step 3: Load Audit Rules

Load the newly defined rules into the Linux kernel:

sudo augenrules --load
# Verify active rules
sudo auditctl -l

Step 4: Query and Search Audit Logs with ausearch

Search for all sudo commands executed today with human-readable formatting:

sudo ausearch -k sudo_exec --interpret --start today

Search by specific login user (AUID):

# Find all commands executed by user with UID 1001 (even if they ran sudo)
sudo ausearch -ua 1001 -i

Step 5: Generate Compliance Reports with aureport

Generate summary executive reports for security audits:

# Summary of all executable commands run
sudo aureport -x --summary

# Summary of authentication events and failed logins
sudo aureport -au --summary

Frequently Asked Questions

Why is bash history (history command) inadequate for security auditing?

Standard ~/.bash_history can be easily disabled (set +o history), edited, or deleted by any user with write permissions to their home directory. The Linux Audit Framework (auditd) hooks directly into the kernel syscall table, recording tamper-resistant events in /var/log/audit/audit.log before userspace processes can intercept them.

How do I search audit logs for commands executed by a specific user?

Use the ausearch utility: sudo ausearch -ua john_doe -i. The -ua flag filters by original login UID (auid), which persists even if the user ran sudo su or sudo -i to become root.

How does auditd track the true user identity when someone runs sudo su to become root?

auditd tracks the Audit UID (auid), which is immutably set by the Linux PAM login session when the user first authenticates via SSH. Even if the user switches to root (euid=0), the auid remains locked to their original login identity.
