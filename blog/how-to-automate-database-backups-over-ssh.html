How to Automate Database Backups Over SSH (PostgreSQL & MySQL 2026 Guide)

Relying on local database dumps stored on the same physical server or VPS instance is a catastrophic disaster recovery risk. If a disk corrupts, a filesystem panics, or a cloud provider region suffers an outage, both your production database and your backups vanish. Learn how to stream compressed PostgreSQL and MySQL dumps securely over SSH directly to offsite storage in 2026.

The Power of Streamed SSH Pipe Backups

Traditional backup scripts write a 50GB .sql file to /tmp, compress it, copy it over SFTP, and then delete the local file. This requires at least 100GB of available free disk space on the database server.

By utilizing standard UNIX pipelines, output from the database dump utility is compressed on the fly and written directly through an encrypted SSH tunnel into offsite disk storage, requiring 0MB of temporary local storage.

Automating PostgreSQL Backups Over SSH

Create a backup user and configure an automated backup script at /usr/local/bin/backup-postgres-offsite.sh: 

#!/usr/bin/env bash
set -euo pipefail

DB_NAME="production_db"
DB_USER="postgres"
BACKUP_HOST="backup-server.internal"
BACKUP_USER="backup_agent"
BACKUP_DIR="/mnt/secure-backups/postgres"
TIMESTAMP=$(date +"%Y%m%d_%H%M%S")
FILENAME="pg_${DB_NAME}_${TIMESTAMP}.sql.gz"

echo "Starting streamed PostgreSQL backup at $(date)..."

# Stream dump -> gzip -> SSH -> remote file
pg_dump -U "${DB_USER}" -d "${DB_NAME}" -F c -Z 6 \
  | ssh -i /root/.ssh/id_backup -o StrictHostKeyChecking=accept-new "${BACKUP_USER}@${BACKUP_HOST}" \
  "cat > ${BACKUP_DIR}/${FILENAME}"

# Prune backups older than 30 days on remote host
ssh -i /root/.ssh/id_backup "${BACKUP_USER}@${BACKUP_HOST}" \
  "find ${BACKUP_DIR} -name 'pg_*.sql.gz' -mtime +30 -delete"

echo "Backup complete: ${FILENAME}"

Automating MySQL & MariaDB Backups Over SSH

For MySQL/MariaDB with InnoDB storage engines, ensure non-locking transactions: 

#!/usr/bin/env bash
set -euo pipefail

DB_NAME="ecommerce_db"
TIMESTAMP=$(date +"%Y%m%d_%H%M%S")

mysqldump --single-transaction --quick --routines --triggers "${DB_NAME}" \
  | gzip -9 \
  | ssh -i /root/.ssh/id_backup backup_agent@backup-server.internal \
  "cat > /mnt/secure-backups/mysql/mysql_${DB_NAME}_${TIMESTAMP}.sql.gz"

Scheduling Backups with Systemd Timer (or Cron)

Schedule the backup to execute nightly at 02:00 AM via crontab:

# Open root crontab
sudo crontab -e

# Run every night at 2:00 AM
0 2 * * * /usr/local/bin/backup-postgres-offsite.sh >> /var/log/db_backup.log 2>&1

Frequently Asked Questions

Can I stream a database backup directly across SSH without saving it to local disk first?

Yes! Pipelining pg_dump or mysqldump directly through gzip and ssh streams raw database blocks over the network without consuming temporary storage on the database host. For example: pg_dump dbname | gzip -c | ssh backup_user@offsite "cat > backup.sql.gz".

How do I handle database locks during production MySQL backups?

Always pass --single-transaction --quick to mysqldump on InnoDB tables. This creates a point-in-time snapshot within an ACID transaction without acquiring table read locks or freezing production web write traffic.

How do I automatically prune older database backup archives?

Incorporate a find command into your backup script on the storage target: find /backups -type f -name "*.sql.gz" -mtime +30 -delete. This automatically removes archives older than 30 days.
