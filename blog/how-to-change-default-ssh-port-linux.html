How to Change Default SSH Port 22 on Linux: Step-by-Step (2026 Guide)

Published: November 2026 • 10 min read • By SSH Desktop Engineering Team

Within minutes of launching any cloud server on AWS, DigitalOcean, Hetzner, or Linode, inspection of /var/log/auth.log reveals an uncomfortable truth: automated botnets from across the globe are pounding port 22 with hundreds of thousands of dictionary login attempts per hour.

While changing the default SSH port is technically "security through obscurity" and not a substitute for disabling passwords in favor of Ed25519 keys, it provides an immediate, tangible benefit: it cuts down 99.9% of automated botnet noise, frees up system CPU cycles, and prevents authentication logs from bloating to gigabytes.

In this guide, you will learn the safe, foolproof sequence to change your SSH port without accidentally locking yourself out of your server.

The #1 Golden Rule: Never close your existing active SSH terminal session until you have successfully verified the new custom port from a separate, second terminal window!

Step 1: Choose an Unused Port Number

TCP ports range from 1 to 65535:

  • Ports 1–1023: Well-known privileged system ports (e.g. 21 FTP, 22 SSH, 80 HTTP, 443 HTTPS).
  • Ports 1024–49151: Registered user ports.
  • Ports 49152–65535: Dynamic or ephemeral ports (safest choice).

Before choosing a port (e.g., 2222 or 49822), verify nothing is currently listening on it:

sudo ss -tulpn | grep ':2222'

If the output is empty, port 2222 is available.

Step 2: Allow the New Port in Your Firewall (BEFORE changing SSH!)

The most common rookie mistake is editing sshd_config first and restarting the service before opening the firewall, immediately locking the admin out. Always configure the firewall first!

1. Ubuntu & Debian (UFW):

sudo ufw allow 2222/tcp comment 'Custom OpenSSH Port'
sudo ufw reload
sudo ufw status

2. CentOS, RHEL, & AlmaLinux (firewalld):

sudo firewall-cmd --permanent --add-port=2222/tcp
sudo firewall-cmd --reload

3. AWS EC2, GCP, & DigitalOcean Cloud Firewalls:

Remember that cloud providers run external security groups. Open the AWS EC2 or DigitalOcean console and add an Inbound Security Rule for Custom TCP on port 2222.

Step 3: Configure SELinux (RHEL, CentOS, Rocky Linux Only)

On Red Hat family distributions with SELinux enabled in Enforcing mode, the kernel policy will block OpenSSH from binding any port other than 22.

Authorize your new port in SELinux:

# Install semanage tool if missing:
sudo dnf install -y policycoreutils-python-utils

# Add port 2222 to SELinux SSH policy:
sudo semanage port -a -t ssh_port_t -p tcp 2222

# Verify the policy:
sudo semanage port -l | grep ssh

Step 4: Update SSH Daemon Configuration

Edit your SSH configuration file:

sudo nano /etc/ssh/sshd_config

Locate the line containing #Port 22. Uncomment it and change the value:

Port 2222
Pro-Tip (Dual-Port Transition): During the transition, you can list both ports: Port 22 and Port 2222. Once you verify port 2222 works, remove port 22 and close it in UFW!

Test the configuration syntax for errors before restarting:

sudo sshd -t

If it returns no output, your syntax is valid.

Step 5: Handling Ubuntu 22.10 & 24.04 Socket Activation Caveat

If you are on modern Ubuntu (22.10, 23.04, 24.04 LTS), OpenSSH is controlled by systemd socket activation (ssh.socket). Modifying sshd_config alone will NOT change the port!

Check if ssh.socket is active:

sudo systemctl status ssh.socket

If active, create a systemd socket override:

sudo systemctl edit ssh.socket

Paste the following override block into the editor:

[Socket]
ListenStream=
ListenStream=2222

Save and reload systemd:

sudo systemctl daemon-reload
sudo systemctl restart ssh.socket

For traditional distributions (Debian 11/12, CentOS, or earlier Ubuntu), simply restart the service:

sudo systemctl restart ssh # Debian/Ubuntu
sudo systemctl restart sshd # RHEL/CentOS

Step 6: Verify Listening Ports and Test from a New Terminal

Confirm OpenSSH is actively bound to your new port:

sudo ss -tulpn | grep -i ssh

You should see 0.0.0.0:2222 in the listening state.

Now, leaving your current session open, open a second terminal on your local laptop and connect:

ssh -p 2222 user@your-server-ip

Once verified, close old port 22 in UFW: sudo ufw delete allow 22/tcp.
