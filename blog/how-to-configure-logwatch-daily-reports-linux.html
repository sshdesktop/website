How to Configure Logwatch for Daily Linux Email Reports: 2026 Guide

Reviewing raw server logs across gigabytes of journal entries every morning is impractical for system administrators. However, ignoring logs leaves brute-force SSH attacks, kernel disk warnings, and unauthorized sudo attempts undetected. Logwatch is an open-source log analyzer that parses your server logs and generates an organized, human-readable daily email digest. Learn how to configure Logwatch on Linux in 2026.

What Logwatch Summarizes Every Morning

  • SSH Authentication: Successful root logins, accepted public keys, and top IP addresses attempting brute-force logins.
  • Sudo & PAM Activity: Every user executing administrative commands and any failed privilege escalation attempts.
  • Firewall & Fail2ban: Number of blocked connection attempts, banned IP addresses, and dropped port scans.
  • Disk Space & Storage: Partitions exceeding capacity thresholds and filesystem errors.
  • Package Updates: Software packages installed, upgraded, or removed.

Step 1: Install Logwatch and Mail Utilities

Install Logwatch on Ubuntu / Debian:

sudo apt update
sudo apt install -y logwatch mailutils

On RHEL / AlmaLinux / Rocky Linux:

sudo dnf install -y epel-release
sudo dnf install -y logwatch mailx

Step 2: Configure Logwatch Settings

The default configuration resides in /usr/share/logwatch/default.conf/logwatch.conf. Never edit this default file directly; instead, create a local override at /etc/logwatch/conf/logwatch.conf: 

sudo nano /etc/logwatch/conf/logwatch.conf

Insert your customized monitoring configuration:

# Email recipient for reports
MailTo = admin@example.com

# Sender email address
MailFrom = server01-logwatch@example.com

# Format: text or html
Format = html

# Report detail level: Low (0), Medium (5), High (10)
Detail = High

# Timeframe to analyze: Yesterday or Today
Range = yesterday

# Services to monitor: 'All' or specific services like sshd, sudo, ufw
Service = All

Step 3: Test Logwatch Execution Manually

Generate a test report to verify configuration and output:

# Output summary directly to the terminal
sudo logwatch --detail High --range yesterday --output stdout

# Send a test email digest immediately
sudo logwatch --mailto admin@example.com --range yesterday

Step 4: Configure Postfix or msmtp Relay

If your server does not have an external MX record, install msmtp to relay emails through an authenticated SMTP provider: 

sudo apt install -y msmtp msmtp-mta

Configure /etc/msmtprc:

defaults
auth           on
tls            on
tls_trust_file /etc/ssl/certs/ca-certificates.crt
logfile        /var/log/msmtp.log

account        default
host           smtp.sendgrid.net
port           587
from           alerts@yourdomain.com
user           apikey
password       YOUR_SENDGRID_API_KEY

Step 5: Verify the Automated Daily Cron Schedule

Upon installation, Logwatch automatically registers a daily cron script in /etc/cron.daily/00logwatch. Verify that the script exists and is executable: 

ls -la /etc/cron.daily/00logwatch

Every morning at your server's standard cron hour (typically 06:25 AM), Logwatch will parse the previous day's events and deliver an actionable summary directly to your inbox.

Frequently Asked Questions

What is Logwatch and how does it differ from real-time log monitors?

Logwatch is a modular log parsing utility that analyzes system logs over a 24-hour window and compiles a categorized, high-level executive summary. Unlike real-time streaming tools that trigger alert fatigue, Logwatch sends an organized daily digest highlighting security anomalies, failed logins, and disk warnings.

How does Logwatch send email notifications from a server without an SMTP server?

Logwatch utilizes the local system mail transfer agent (MTA) such as Postfix or lightweight relay clients like msmtp or ssmtp configured with third-party SMTP services (e.g., SendGrid, AWS SES, or Gmail).

Can I customize Logwatch detail levels and specific services to monitor?

Yes. Detail levels range from Low (0) to High (10). You can monitor all services or restrict reports to specific critical daemons such as sshd, sudo, ufw, and fail2ban by editing /etc/logwatch/conf/logwatch.conf.
