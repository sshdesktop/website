How to Add & Configure Swap Space on Linux (Ubuntu, Debian, RHEL): 2026 Guide

Memory & Performance By SSH Desktop Engineering Team • Updated November 2026 • 10 min read

Running a virtual private server (VPS) with 1 GB or 2 GB of RAM is cost-effective, but running memory-intensive processes—such as running npm install, compiling code, or handling unexpected traffic surges—can trigger the Linux kernel's dreaded OOM (Out-of-Memory) Killer. When memory is exhausted, the kernel arbitrarily kills vital services like MySQL, Nginx, or Docker.

Executive Summary

Configuring a dedicated swap file gives your server an emergency safety net by offloading inactive memory pages to SSD storage. In this guide, you will learn how to verify current swap usage, create a 4 GB swap file, set secure permissions (chmod 600), persist it in /etc/fstab across reboots, and tune kernel swappiness for peak performance.

1. Check Existing Swap Space

Before creating a new swap file, check if your Linux distribution has pre-allocated swap partitions: 

# Check active swap devices and files
sudo swapon --show

# Check RAM and Swap allocation in megabytes
free -m

If the output for swapon --show is empty and free -m shows Swap: 0 0 0, your server has zero swap enabled and is exposed to abrupt OOM crashes.

2. Step-by-Step: Creating a 4 GB Swap File

Step 1: Check Free Disk Space

Make sure your root filesystem has sufficient space for the new file using df -h.

Step 2: Allocate the File

On modern ext4 and XFS filesystems, fallocate creates a contiguous preallocated file instantly: 

# Allocate a 4GB file named /swapfile
sudo fallocate -l 4G /swapfile

# Fallback using dd if fallocate fails (e.g. on Btrfs):
# sudo dd if=/dev/zero of=/swapfile bs=1M count=4096 status=progress

Step 3: Secure File Permissions

Critical Security Requirement

Swap files contain plaintext memory dumps, which may hold decrypted SSL private keys, database passwords, and user sessions. You must restrict read/write access exclusively to the root user: 

sudo chmod 600 /swapfile
ls -lh /swapfile
# Permissions must display: -rw------- 1 root root 4.0G

Step 4: Format and Enable Swap

# Mark the file as a Linux swap area
sudo mkswap /swapfile

# Enable the swap file
sudo swapon /swapfile

# Verify it is active
sudo swapon --show

3. Persist Swap Across Server Reboots

Without adding the swap file to your filesystem table, it will be deactivated automatically whenever the server is rebooted: 

# Backup your current fstab file
sudo cp /etc/fstab /etc/fstab.bak

# Append the swapfile entry
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

4. Tuning Kernel Swappiness for Production Servers

The kernel swappiness setting (ranging from 0 to 100) dictates how eagerly the OS migrates RAM pages into swap. The default value is 60, which is often too aggressive for low-latency web servers and database instances.

Swappiness Value Recommended Environment Behavior
60 (Default) Desktop Workstations Balances RAM cache and swap actively
10 – 15 Web & API Servers Prioritizes fast RAM; uses swap strictly as an OOM emergency cushion
1 High-Performance Databases (Postgres/MySQL) Avoids disk swap unless RAM is completely exhausted

How to Lower Swappiness Permanently

# Check current swappiness
cat /proc/sys/vm/swappiness

# Change swappiness immediately to 10
sudo sysctl vm.swappiness=10

# Persist across reboots in /etc/sysctl.conf
echo 'vm.swappiness=10' | sudo tee -a /etc/sysctl.conf
echo 'vm.vfs_cache_pressure=50' | sudo tee -a /etc/sysctl.conf

5. Frequently Asked Questions

How much swap space should I allocate on a Linux server?

As a general rule: for systems with less than 2 GB of RAM, allocate equal or double the RAM (e.g. 2 GB to 4 GB swap). For systems with 4 GB to 16 GB RAM, allocate 4 GB to 8 GB swap. On modern SSD/NVMe cloud servers, swap serves as an emergency buffer against Out-of-Memory (OOM) crashes rather than active working memory.

What is swappiness and what value should I set for a production server?

Swappiness is a Linux kernel parameter (0 to 100) determining how aggressively the kernel moves memory pages from physical RAM to swap. The default is 60. For production servers, database hosts, and web servers, lowering swappiness to 10 or 15 keeps active applications in fast physical RAM while reserving swap strictly for sudden spikes.

Why does fallocate fail on some file systems like Btrfs or XFS?

Some Copy-on-Write (CoW) filesystems like Btrfs or certain XFS setups do not support preallocated swap files via fallocate. On these file systems, create the swap file using dd: sudo dd if=/dev/zero of=/swapfile bs=1M count=4096 status=progress.
