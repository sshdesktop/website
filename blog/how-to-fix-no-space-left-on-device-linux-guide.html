How to Fix No Space Left on Device in Linux (Even When df Shows Free Space)

Seeing write error: No space left on device in your terminal or application logs is terrifying—especially when running df -h reports gigabytes of available storage. In Linux filesystems (ext4, XFS), storage capacity is governed by both raw storage blocks and inode metadata structures. Learn the 4 hidden causes of false disk-full errors in 2026 and how to resolve them immediately.

Cause 1: Inode Exhaustion (df -i Shows 100%)

Every file, folder, and symlink on a Linux filesystem requires one inode (index node) to store metadata (permissions, ownership, block locations). If your disk has 500GB of free space but runs out of free inodes, no new files can be created.

Check inode utilization across all mounted filesystems:

df -i

If IUse% is 100%, locate the culprit directory containing millions of tiny files:

# Scan root filesystem and count files per directory
sudo find / -xdev -printf '%h\n' | sort | uniq -c | sort -k 1 -n | tail -20

Common culprits include:

  • /var/lib/php/sessions/ — Millions of abandoned PHP session files.
  • /var/spool/postfix/maildrop/ — Millions of undelivered bounce emails.
  • /tmp/ or /var/tmp/ — Leftover application cache files.

Delete runaway files safely without overloading bash argument limits:

# Use find -delete to safely delete millions of files
sudo find /var/lib/php/sessions -type f -name "sess_*" -delete

Cause 2: Deleted Files Held by Running Processes (lsof)

When you run rm /var/log/application.log, Linux marks the directory entry as deleted. However, if a background daemon (like Nginx, Docker, or Node.js) still has an open file descriptor pointing to that file, the disk space is not reclaimed until the process closes the file or terminates.

Find unlinked open files holding disk space:

sudo lsof +L1

Or filter by deleted files:

sudo lsof | grep deleted | grep -E '(log|txt|dat)'

To release the held disk space immediately without rebooting:

# Preferred: Restart the offending service
sudo systemctl restart nginx

# Or truncate the file descriptor directly (replace PID and FD)
: > "/proc/1234/fd/5"

Cause 3: Files Hidden Underneath Active Mount Points

If files were written to /mnt/storage before a secondary disk or NFS volume was mounted on top of it, those original files are hidden from view. df counts the blocks, but du /mnt/storage only sees the mounted drive!

To reveal hidden files beneath active mounts, create a bind mount of root:

# Bind mount the root filesystem to a temporary inspection directory
sudo mkdir /tmp/root-inspect
sudo mount --bind / /tmp/root-inspect

# Check actual usage in the un-mounted directory
sudo du -sh /tmp/root-inspect/mnt/storage

# Unmount when finished
sudo umount /tmp/root-inspect
sudo rmdir /tmp/root-inspect

Cause 4: Reserved Superuser Blocks (5% Default on ext4)

By default, the ext4 filesystem reserves 5% of all blocks for the root user to prevent system deadlocks. On a 1TB drive, this reserves 50GB that normal unprivileged services (like PostgreSQL, MySQL, or web servers) cannot use.

Reduce reserved blocks to 1% on large data drives:

# Check reserved block percentage
sudo tune2fs -l /dev/sda1 | grep -i "reserved block"

# Reduce reserved blocks to 1%
sudo tune2fs -m 1 /dev/sda1

Frequently Asked Questions

Why does Linux say "No space left on device" when df -h shows 20GB available?

The most common cause is inode exhaustion (df -i shows 100% used), meaning the filesystem has run out of file index pointers due to millions of tiny files (sessions, logs, emails). Another frequent cause is deleted open files still held by running processes (lsof | grep deleted).

How do I find which directory has the most inodes in Linux?

Run: find / -xdev -printf '%h\n' | sort | uniq -c | sort -k 1 -n | tail -20. This lists the top 20 directories containing the highest number of individual files.

How do I free disk space held by deleted open files without rebooting?

Identify the processes holding deleted files with: sudo lsof +L1. Find the PID holding the file and either restart the service (e.g., sudo systemctl restart nginx) or truncate the file descriptor via /proc/$PID/fd/$FD.
