How to Fix 'SSH Connection Timed Out' (Port 22): 6 Proven Fixes (2026 Guide)

Published: November 2026 • 10 min read • By SSH Desktop Engineering Team

You enter ssh user@your-server-ip into your terminal, press Enter, and wait. Ten seconds pass. Thirty seconds pass. Finally, the terminal gives up:

ssh: connect to host 198.51.100.42 port 22: Connection timed out

Unlike Connection refused (where the server is reachable but rejects the port), a Connection timed out error means your packets simply vanished into a digital void. Your client sent TCP SYN packets, but never received an acknowledgment (SYN-ACK) or a rejection (RST).

In this guide, we walk through the step-by-step diagnostic hierarchy to find where packets are getting dropped and fix the problem fast.

Step 0: Ping vs Traceroute Diagnostics

Is the host completely unreachable, or is only port 22 blocked?

# 1. Test basic ICMP reachability:
ping -c 4 198.51.100.42

# 2. Trace route on Windows PowerShell:
tracert 198.51.100.42

# 3. Trace route on Linux/macOS:
traceroute 198.51.100.42

If ping works but SSH times out, the server is alive, but a firewall is silently dropping port 22 traffic.

Cause 1: AWS EC2 / Cloud Security Group Changed

On Amazon Web Services (AWS EC2), Google Cloud, and DigitalOcean, servers sit behind cloud-level security groups.

Most developers restrict port 22 access to My IP in AWS. However, residential internet service providers frequently change your home public IP address!

The Fix:

  1. Check your current public IP at curl ifconfig.me.
  2. Log into the AWS EC2 Console → Select Security Groups.
  3. Click Edit inbound rules.
  4. Update the SSH rule source to your new IP (e.g. 203.0.113.85/32) or temporarily set it to 0.0.0.0/0 while testing.
  5. Click Save rules. Connection will succeed within 5 seconds!

Cause 2: Local ISP or Corporate Wi-Fi Blocks Outbound Port 22

Many hotel Wi-Fi networks, airports, universities, and mobile carriers block outbound connections on port 22 to prevent infected laptops from participating in SSH botnets.

How to Test for ISP Port Blocking:

Connect to portquiz.net, an open diagnostic server that listens on every port:

# Test Port 22:
curl http://portquiz.net:22

# Test Port 80 (standard web):
curl http://portquiz.net:80

If port 80 connects but port 22 hangs and times out, your local network or ISP is actively blocking port 22.

How to Bypass:

Configure your server's SSH daemon to listen on port 443 (HTTPS) or port 2222. Firewalls never block port 443. Check out our step-by-step tutorial: How to Change Default SSH Port on Linux.

Cause 3: The Remote Server Has Crashed or Has No Network

If ICMP ping also fails and times out, the virtual machine itself may have panicked, ran out of memory (OOM kernel crash), or lost its network interface.

Access your cloud provider's out-of-band console:

  • AWS EC2: Right click instance → Monitor and troubleshoot → Get system log or EC2 Serial Console.
  • DigitalOcean: Click Access → Launch Droplet Console.
  • Hetzner: Cloud Console → VNC Console.

Look for kernel panic messages or run ip a to ensure the network interface has an assigned IPv4 address.

Cause 4: Server-Side Firewall Dropping Packets (UFW / iptables)

In Linux firewalls, a rule can either REJECT or DROP traffic.

  • REJECT: Sends a TCP RST packet back → Result: Connection refused.
  • DROP: Silently discards packets with zero response → Result: Connection timed out.

If an admin configured UFW with a default drop policy and forgot to open port 22, it results in an infinite timeout. Log in via your cloud web console and execute:

sudo ufw allow 22/tcp
sudo ufw reload

Cause 5: IP Address Changed After Cloud Server Reboot

Unless you assigned an Elastic IP (AWS) or Reserved Floating IP (DigitalOcean), stopping and starting a cloud VPS releases the old public IP and assigns a completely new IP address!

Check your cloud provider dashboard to verify you are connecting to the server's current IP address rather than its historical released IP.

Troubleshooting Decision Tree: Timed Out vs Refused

Error Output Diagnostic Meaning Most Probable Root Cause
Connection timed out (30s delay) Packets dropped in transit; zero response Cloud Security Group / ISP block / Firewall DROP
Connection refused (Instant) Packets reached host; port rejected sshd service stopped / listening on custom port
No route to host (Instant) Routing table has no path to destination Subnet routing table fault / VPN disconnected
Permission denied (publickey) TCP handshake succeeded; auth failed Key permissions or sshd_config error
