How to Fix "Too Many Open Files" in Linux: Complete 2026 Guide

During high-traffic flash sales or sudden web application surges, production servers frequently crash with socket: too many open files (errno: 24 / EMFILE). In Linux, every TCP connection, database query socket, and static asset consumes a file descriptor. When default limits (often set as low as 1,024) are reached, the kernel abruptly rejects new connections. Learn how to increase file descriptor limits permanently across the kernel, user sessions, and systemd services in 2026.

The Three Layers of Linux File Limits

To eliminate file descriptor bottlenecks completely, you must configure three distinct tiers:

  • Kernel-Wide Limit: fs.file-max (Governs the entire OS).
  • User Shell Limits: /etc/security/limits.conf (Governs interactive PAM/SSH sessions).
  • Systemd Service Limits: LimitNOFILE (Governs background daemons like Nginx, Node, and Docker).

Step 1: Increase Global Kernel Limit in sysctl.conf

Check current system-wide maximum and allocated file descriptors:

cat /proc/sys/fs/file-nr
# Output: 2432 (allocated)   0 (free)   2097152 (maximum)

If maximum is low, increase it in /etc/sysctl.conf:

echo "fs.file-max = 2097152" | sudo tee -a /etc/sysctl.conf
sudo sysctl -p

Step 2: Increase User & Session Limits in limits.conf

Edit /etc/security/limits.conf:

sudo nano /etc/security/limits.conf

Append soft and hard limits for all users:

* soft nofile 65535
* hard nofile 65535
root soft nofile 65535
root hard nofile 65535

Also verify that PAM enables limits in /etc/pam.d/common-session:

session required pam_limits.so

Step 3: Increase Systemd Service Limits (The Crucial Step!)

Because systemd ignores limits.conf, you must set LimitNOFILE on your background services:

For example, to fix Nginx or Node.js:

# Create a systemd override directory
sudo systemctl edit nginx

In the editor, add:

[Service]
LimitNOFILE=65535

Save and reload systemd:

sudo systemctl daemon-reload
sudo systemctl restart nginx

Step 4: Verify the New Limits on the Running Process

Inspect the live limits on the running daemon PID:

PID=$(pgrep -o nginx)
cat /proc/$PID/limits | grep "Max open files"

Verify that Soft Limit and Hard Limit both report 65535.

Frequently Asked Questions

Why does Linux throw "Too many open files" when physical disk space is available?

In UNIX/Linux, "everything is a file" — including TCP sockets, pipes, and event loops (epoll). When an application (like Nginx, Node.js, or PostgreSQL) handles thousands of concurrent visitors, it opens thousands of network file descriptors. Once the process hits its operating system limit (ulimit -n), the kernel rejects all new socket connections with error EMFILE.

Why doesn't modifying /etc/security/limits.conf affect systemd services?

Systemd completely ignores /etc/security/limits.conf for services it manages. To increase file descriptor limits for daemons started via systemctl, you must configure LimitNOFILE=65535 inside the service unit file or an override drop-in file.

How do I check the current file descriptor limit of a running process?

Find the process PID (e.g., pgrep nginx) and inspect /proc/$PID/limits: cat /proc/$PID/limits | grep "Max open files". This displays the exact Soft and Hard limits enforced on that active process.
