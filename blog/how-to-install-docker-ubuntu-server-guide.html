How to Install & Secure Docker on Ubuntu (2026 Guide)

Containerization is the backbone of modern cloud deployments. However, installing Docker with default settings often exposes servers to security vulnerabilities, root-equivalent socket exploits, and unconstrained container log growth that crashes host filesystems. Learn how to install, harden, and tune Docker Engine on Ubuntu 24.04 and 22.04 LTS in 2026.

Step 1: Remove Old Docker Versions

Clean out conflicting unofficial packages before installing the latest engine:

sudo apt remove -y docker docker-engine docker.io containerd runc

Step 2: Add the Official Docker GPG Key & Repository

Install prerequisites and set up the official APT source:

# Install dependencies
sudo apt update
sudo apt install -y ca-certificates curl gnupg

# Add official Docker GPG key
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Add repository to APT sources
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# Update index
sudo apt update

Step 3: Install Docker Engine and Compose Plugin

Install the core runtime, containerd, and CLI plugins:

sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Verify that the service is running:

sudo systemctl status docker

Step 4: Non-Root Execution & Daemon Hardening

Allow your standard Linux user to manage containers without sudo:

sudo usermod -aG docker $USER
# Activate group changes immediately
newgrp docker

Step 5: Configure Production Logging Limits in daemon.json

By default, Docker container logs grow indefinitely until disk space is exhausted. Enforce strict log rotation limits across all containers by creating /etc/docker/daemon.json: 

sudo nano /etc/docker/daemon.json

Paste the following production configuration:

{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "50m",
    "max-file": "3"
  },
  "live-restore": true,
  "no-new-privileges": true
}
  • live-restore: Keeps containers running even if the Docker daemon restarts or upgrades.
  • no-new-privileges: Prevents containers from acquiring additional privileges via setuid/setgid binaries.
  • max-size / max-file: Caps log files per container to 150MB total.

Apply changes:

sudo systemctl restart docker

Frequently Asked Questions

Why should I install Docker from the official Docker repository instead of Ubuntu apt?

The docker.io package in default Ubuntu repositories is frequently outdated and lacks modern security patches, BuildKit enhancements, and the Docker Compose v2 plugin. The official Docker repository provides the latest verified Docker Engine (CE) releases.

Is adding a user to the docker group a security risk?

Yes. The docker group grants root-equivalent privileges because anyone with access to the Docker socket can mount the root filesystem (docker run -v /:/host) and escalate privileges. For high-security environments, evaluate Rootless Docker or enforce strict SSH user permissions.

How do I prevent Docker container logs from filling up the entire server disk?

Configure the json-file logging driver with max-size and max-file parameters inside /etc/docker/daemon.json. For example: {"log-driver": "json-file", "log-opts": {"max-size": "50m", "max-file": "3"}}.
