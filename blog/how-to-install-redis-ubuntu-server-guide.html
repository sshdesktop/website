How to Install & Secure Redis Server on Ubuntu (2026 Guide)

Redis is the industry standard for high-performance in-memory caching, pub/sub messaging, and session storage. However, default out-of-the-box installations often lack basic authentication and memory limits, making them vulnerable to memory exhaustion and cryptojacking attacks. Learn how to install, harden, and optimize Redis on Ubuntu 24.04 and 22.04 LTS in 2026.

Step 1: Install Official Redis Packages

Install the latest stable Redis release from the official repository:

# Install prerequisites
sudo apt update
sudo apt install -y lsb-release curl gpg

# Add official Redis GPG key and APT repository
curl -fsSL https://packages.redis.io/gpg | sudo gpg --dearmor -o /usr/share/keyrings/redis-archive-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/redis-archive-keyring.gpg] https://packages.redis.io/deb $(lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/redis.list

# Update and install
sudo apt update
sudo apt install -y redis

Step 2: Configure Systemd Supervision & Memory Allocation

Edit the main Redis configuration file:

sudo nano /etc/redis/redis.conf

1. Enable systemd supervision:

# Change supervised no to systemd
supervised systemd

2. Set memory ceiling and eviction policy (e.g., 2GB on an 8GB server):

maxmemory 2gb
maxmemory-policy allkeys-lru

Step 3: Enforce Network Isolation & Password Authentication

Security is paramount. Never change the bind address to 0.0.0.0 without strict firewall rules: 

# Ensure Redis binds only to localhost
bind 127.0.0.1 -::1

# Set a strong, cryptographically generated password
requirepass "SuperSecureRandom64CharPassphrase"

Save changes and restart Redis:

sudo systemctl restart redis-server
sudo systemctl enable redis-server

Step 4: Verify Redis Operation

Test the installation with redis-cli:

redis-cli
127.0.0.1:6379> ping
(error) NOAUTH Authentication required.
127.0.0.1:6379> auth "SuperSecureRandom64CharPassphrase"
OK
127.0.0.1:6379> ping
PONG

Step 5: Linux Kernel Tuning for Redis

Redis requires two critical kernel optimizations to prevent memory overcommit errors and latency spikes: 

# Add overcommit_memory and somaxconn to sysctl.conf
echo "vm.overcommit_memory = 1" | sudo tee -a /etc/sysctl.conf
echo "net.core.somaxconn = 65535" | sudo tee -a /etc/sysctl.conf

# Apply immediately
sudo sysctl -p

# Disable Transparent Huge Pages (THP)
echo never | sudo tee /sys/kernel/mm/transparent_hugepage/enabled

Frequently Asked Questions

Why should I never expose Redis directly to the public internet on port 6379?

Redis is designed for maximum speed and lacks defensive hardening against brute-force attacks or network fuzzing. An exposed Redis instance with weak or no authentication allows attackers to write arbitrary SSH keys to /root/.ssh/authorized_keys or overwrite system files.

How do I securely connect to a remote Redis server from my local machine?

Keep Redis bound to 127.0.0.1 on the remote server and create an encrypted SSH tunnel: ssh -N -L 6379:localhost:6379 user@remote-server-ip. Your local Redis GUI (like SSH Desktop Database Explorer) can then connect to localhost:6379 safely.

What is the recommended maxmemory-policy for Redis caching?

For caching workloads, allkeys-lru (Least Recently Used) or volatile-lru is recommended. When RAM hits maxmemory, Redis automatically evicts older cached keys instead of throwing Out of Memory (OOM) write errors.
