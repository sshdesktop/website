How to Keep SSH Sessions Alive: nohup vs tmux vs screen (2026 Guide)

Published: November 2026 • 10 min read • By SSH Desktop Engineering Team

Every developer or sysadmin has experienced this nightmare: you start a 4-hour database backup, a massive code build, or an operating system upgrade on a remote Linux server. An hour in, your laptop goes to sleep, your Wi-Fi flickers, or your VPN disconnects.

When you reconnect, the terminal is gone, the build was killed midway through, and your database table is left in an inconsistent locked state.

Why does this happen? When an SSH connection drops, the operating system kernel sends a SIGHUP (Hangup Signal) to the active shell session, terminating every foreground child process attached to that terminal.

In this guide, you will learn the three essential techniques to immunize your processes against network drops: nohup, tmux, and GNU screen, plus how to manage background tasks visually with SSH Desktop.

Method 1: nohup & disown (For Simple Non-Interactive Scripts)

nohup stands for "No Hang Up". It intercepts the SIGHUP signal so that closing your terminal does not kill the process:

nohup python3 backup_database.py > backup.log 2>&1 &

Command Breakdown:

  • nohup: Ignores the hangup signal.
  • > backup.log: Redirects standard output (stdout) to a log file.
  • 2>&1: Redirects error output (stderr) to the same log file.
  • &: Runs the command immediately in the background, returning your shell prompt.

Checking and Killing nohup Processes:

# Find the process ID:
ps aux | grep backup_database.py

# Monitor live logs:
tail -f backup.log

# Kill the background process:
kill -9 <PID>

Method 2: tmux (The Industry Standard Multiplexer)

Unlike nohup, tmux runs a complete background terminal server. You can launch interactive text interfaces (like htop, Python REPLs, or database prompts), detach, close your laptop, fly to another city, and reattach to find your cursor blinking in the exact same spot!

1. Starting a Named Session:

tmux new -s deploy

2. Essential tmux Shortcuts (Prefix Key: Ctrl+b):

In tmux, all shortcuts begin with the prefix key combination Ctrl+b, followed by a command key:

  • Ctrl+b then d: Detach from the session (keeps it running safely in the background!).
  • Ctrl+b then %: Split window vertically into two side-by-side panes.
  • Ctrl+b then ": Split window horizontally.
  • Ctrl+b then arrow keys: Navigate between split panes.
  • Ctrl+b then c: Create a brand-new tab/window.
  • Ctrl+b then n: Switch to next window.

3. Listing & Reattaching Sessions:

# List all running background sessions:
tmux ls

# Reattach to your deploy session:
tmux attach -t deploy

# Or reattach to the most recent session:
tmux a

Method 3: GNU Screen (The Classic Alternative)

If your remote server is an older enterprise distribution (like CentOS 7 or Debian 9) without tmux, screen is virtually guaranteed to be available:

# Start a new screen session:
screen -S build_job

# Run your commands inside the session...
./long_running_build.sh

# Detach shortcut: Press Ctrl+a then d

# List running screens:
screen -ls

# Reattach:
screen -r build_job

Method 4: Systemd Service Units (For Permanent Services)

If you are running a Node.js API, Go web server, or background queue worker that must survive not only SSH drops but also server reboots and crashes, do not rely on tmux. Create a systemd service:

sudo nano /etc/systemd/system/myapp.service
[Unit]
Description=My Background Application
After=network.target

[Service]
User=ubuntu
WorkingDirectory=/opt/myapp
ExecStart=/usr/bin/node server.js
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target

Enable and start the service:

sudo systemctl daemon-reload
sudo systemctl enable --now myapp
sudo journalctl -u myapp -f
