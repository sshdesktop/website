How to Find & Kill Processes in Linux: kill, pkill, killall (2026 Guide)

Process Management By SSH Desktop Engineering Team • Updated November 2026 • 10 min read

Every sysadmin and developer encounters unresponsive processes on a Linux server: runaway memory leaks, crashed Node.js workers locking port 3000, or stale Python background jobs hogging 100% CPU. While reaching directly for kill -9 is a common reflex, doing so blindly can lead to corrupted databases, abandoned lockfiles, and data loss.

Executive Summary

Linux terminates processes by sending POSIX signals. SIGTERM (15) requests a graceful shutdown, giving the program time to close network sockets and flush disk buffers. SIGKILL (9) halts execution immediately at the kernel level. In this guide, we explore process discovery tools (ps, pgrep, lsof), signal protocols, and visual management via SSH Desktop Process Manager.

1. Finding the Target Process & PID

Before sending a termination signal, you must identify the Process ID (PID).

Finding Processes with ps and grep

# Display all active processes with user, PID, CPU%, memory%, and command
ps aux | grep nginx

# Filter out the grep command itself from the search results
ps aux | grep [n]ginx

Faster Lookups with pgrep and pidof

# Return only the PIDs matching the process name
pgrep nginx

# Return the PID and full command-line arguments
pgrep -a node

# Find the PID of a specific binary
pidof postgres

Finding the Process Locking a Specific Network Port

When starting a container or web server fails with "bind: address already in use", find which PID owns the listening port: 

# Find the process listening on port 8080
sudo lsof -i :8080

# Return only the numerical PID of the process on port 8080
sudo lsof -t -i :8080

# Alternative using ss (socket statistics)
sudo ss -tulpn | grep 8080

2. Linux Termination Signals Demystified

When you run kill <PID> without specifying an option, Linux sends signal 15 (SIGTERM). Here are the primary signals every engineer must understand:

Signal # Name Behavior Catchable by App?
1 SIGHUP Hang up / Reload configuration without restarting Yes
2 SIGINT Interrupt from keyboard (equivalent to Ctrl+C) Yes
15 (Default) SIGTERM Polite request to terminate; allows cleanup of locks and connections Yes
9 SIGKILL Immediate hard termination enforced by kernel; no cleanup No (Uncatchable)

Why Defaulting to kill -9 is Dangerous

When an application receives SIGKILL, it has zero milliseconds to respond. If a database is halfway through committing a transaction, or a cache daemon has unwritten memory blocks, the data is lost and state files on disk become corrupted. Always issue a graceful kill -15 first, wait 5–10 seconds, and only resort to kill -9 if the process remains frozen.

3. Precision Termination: kill vs pkill vs killall

Using kill (by PID)

# Step 1: Send graceful SIGTERM (Signal 15)
kill 14285

# Step 2: Force termination only if process ignores SIGTERM
kill -9 14285

Using pkill (by Name or Pattern)

pkill combines pgrep and kill into one atomic command: 

# Kill all processes matching 'celery'
pkill celery

# Kill processes owned by a specific user
pkill -u deploy celery

# Kill only processes matching exact full command path
pkill -f "python3 manage.py runserver"

Using killall (by Exact Executable Name)

# Terminate all running instances of nginx
sudo killall nginx

# Gracefully reload all workers
sudo killall -HUP nginx

4. What Are Zombie Processes & How to Eliminate Them

In top or htop, you may notice a count labeled Zombies. A zombie process (status Z) is a dead process whose execution has finished, but whose parent process (PPID) has not yet read its return exit code via wait(). 

# Find all zombie processes on the server
ps aux | awk '{if ($8 ~ /Z/) print $0}'

# Find the parent PID (PPID) of a zombie process (e.g., zombie PID 1849)
ps -o ppid= -p 1849

Because zombies are already dead, executing kill -9 <zombie_pid> does nothing! To eliminate a zombie, restart or terminate its Parent PID. Once the parent dies, systemd (PID 1) inherits the zombie and cleans it up immediately.

5. Frequently Asked Questions

Why shouldn't I always use kill -9 to terminate processes?

SIGKILL (signal 9) immediately halts the process at the kernel level without allowing it to clean up file handles, close database transactions, flush write buffers, or delete temporary socket/PID lock files. Always start with SIGTERM (kill -15 or bare kill) so the application can shut down gracefully.

How do I find and kill the process locking a specific port like 8080?

You can find the PID with sudo lsof -t -i:8080 or sudo ss -tulpn | grep 8080. To kill it in one command, execute sudo kill -15 $(sudo lsof -t -i:8080).

Can you kill a zombie process in Linux?

No, because a zombie process is already dead and has released its memory. It only remains in the kernel process table until its parent process reads its exit status using wait(). To remove a zombie, you must kill its parent process (PPID) or wait for systemd (PID 1) to adopt and reap it.
