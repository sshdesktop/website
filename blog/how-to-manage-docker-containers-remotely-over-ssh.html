How to Manage Remote Docker Containers over SSH (5 Best Methods in 2026)

Published: November 2026 • 9 min read • By SSH Desktop Engineering Team

Running Docker on cloud VPS instances (like AWS EC2, Hetzner, DigitalOcean, or Linode) is standard practice for modern microservices and web apps. However, controlling remote Docker containers from your local development machine poses a major security challenge: How do you manage containers without exposing vulnerable daemon ports to scanner bots?

Security Warning: Exposing the unencrypted Docker daemon TCP socket (port 2375 or port 2376) to the public internet is one of the leading causes of cryptojacking and server takeover. Anyone who can communicate with the Docker daemon effectively possesses root privileges on your host operating system.

The solution is to route all Docker management exclusively over OpenSSH (Port 22). Here are the 5 best methods ranked from command-line workflows to intuitive visual tools.

Method 1: Docker Context with Native SSH (Best for Local CLI)

Docker includes native support for SSH transport via the docker context command. It allows your local terminal to point directly to a remote host's Docker socket over an SSH tunnel.

Step 1: Create the Remote Context

docker context create prod-server --docker "host=ssh://ubuntu@198.51.100.25"

Step 2: Switch to the Context

docker context use prod-server

Now, whenever you run standard commands like docker ps, docker compose up -d, or docker logs -f my-app on your local laptop, they execute directly on the remote server over SSH!

Method 2: SSH UNIX Socket Forwarding

If your local Docker client doesn't support context switching or you use third-party Docker extensions, you can forward the remote Docker UNIX socket (/var/run/docker.sock) directly to your local computer:

ssh -nNT -L /tmp/remote-docker.sock:/var/run/docker.sock ubuntu@198.51.100.25

Then instruct your local Docker commands to target the forwarded socket:

export DOCKER_HOST="unix:///tmp/remote-docker.sock"
docker ps

While command-line tools work well for quick checks, diagnosing failing containers, reading multi-thousand line stack traces, and monitoring real-time RAM/CPU limits is significantly faster with a graphical interface.

Method 4: Quick Ad-Hoc Remote Executions via SSH

When you need a 1-off inspection from a script or CI/CD pipeline, execute docker directly through SSH non-interactively:

# View formatted running containers
ssh ubuntu@198.51.100.25 "docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'"

# Inspect container health status
ssh ubuntu@198.51.100.25 "docker inspect --format='{{.State.Health.Status}}' redis-db"

Method 5: SSH Bastion Jump Hosts for Private VPC Clusters

In production enterprise environments, Docker servers typically reside inside private subnets without public IP addresses. To manage them, route through an SSH bastion jump host:

docker context create prod-worker --docker "host=ssh://bastion.example.com" --description "Jump via Bastion"

Alternatively, configure your ~/.ssh/config:

Host docker-worker-01
  HostName 10.0.1.50
  User ubuntu
  ProxyJump bastion.example.com

Now ssh docker-worker-01 and SSH Desktop automatically navigate the jump host securely.
