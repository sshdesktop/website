How to Check & Manage Linux Disk Space: df, du, ncdu & LVM (2026 Guide)

Published: November 2026 • 10 min read • By SSH Desktop Engineering Team

"No space left on device." When this error appears in production, consequences are immediate: databases reject write queries, Docker containers crash, SSH authentication fails because temporary session files cannot be created, and cron jobs terminate.

Diagnosing disk exhaustion quickly, understanding why deleted files sometimes fail to free up storage, and safely expanding disk partitions using LVM (Logical Volume Manager) are essential skills.

In this guide, you will learn the command-line workflow to analyze disk usage, find runaway log files, resolve unlinked process locks, expand LVM partitions, and inspect storage visually.

1. High-Level Disk Space Check: df -h

The df command reports filesystem disk space usage across all mounted storage devices:

$ df -h
Filesystem Size Used Avail Use% Mounted on
/dev/mapper/ubuntu--vg-ubuntu--lv 48G 45G 1.2G 98% /
/dev/sda2 1.9G 210M 1.6G 12% /boot

Also check Inodes (file count limits) with df -i. If a server has millions of tiny session files, disk space might show 50% free while Inodes are at 100%, causing the exact same "No space left on device" error!

2. Pinpoint Large Directories with du and ncdu

Once you know which mount point is full (usually / or /var), track down the offending directories:

# Show the 10 largest folders inside /var:
sudo du -h --max-depth=1 /var | sort -hr | head -n 10

Interactive Navigation with ncdu:

ncdu (NCurses Disk Usage) is an indispensable visual terminal tool:

sudo apt install -y ncdu # Ubuntu/Debian
sudo dnf install -y ncdu # RHEL/CentOS

sudo ncdu /var

Use arrow keys to navigate down into nested folders. Press d to immediately delete useless log archives or temporary build files.

3. The Deleted File Trap: Recovering Space with lsof

A common frustration: you run rm access.log on a 20 GB log file, but df -h still shows 98% full!

In Linux, if a running service (like Nginx, Apache, or MySQL) still has an open file descriptor pointing to that file, the kernel keeps the disk blocks allocated.

# Find processes holding open unlinked/deleted files:
sudo lsof +L1

Output:

COMMAND PID USER FD TYPE DEVICE SIZE/OFF NLINK NAME
nginx 14282 root 4w REG 253,0 21474836480 0 /var/log/nginx/access.log (deleted)

Restart the offending process to instantly release the 20 GB:

sudo systemctl restart nginx

4. Expanding LVM Disks (Cloud VPS Resizing)

If your disk is genuinely out of physical space, modern cloud platforms (AWS EBS, DigitalOcean, Hetzner) allow you to increase disk size in the web console with zero downtime.

To expand the filesystem in Linux without rebooting:

# 1. Expand partition 1 on /dev/sda:
sudo growpart /dev/sda 1

# 2. Resize LVM Physical Volume:
sudo pvresize /dev/sda1

# 3. Extend Logical Volume and filesystem in 1 command:
sudo lvextend -r -l +100%FREE /dev/mapper/ubuntu--vg-ubuntu--lv

The -r flag automatically resizes ext4 or XFS filesystems on the fly. Verify with df -h!
