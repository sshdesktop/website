How to Manage Linux Packages: APT, DNF, Pacman & Snap (2026 Admin Guide)

Package Management By SSH Desktop Engineering Team • Updated November 2026 • 10 min read

Package managers are the backbone of Linux systems administration. Whether maintaining production web servers on Ubuntu or managing enterprise cloud instances on Rocky Linux, knowing how to install, update, lock, and troubleshoot packages without breaking system libraries is an essential skill.

Executive Summary

Debian and Ubuntu rely on apt and dpkg (.deb packages), RHEL and Fedora utilize dnf and rpm (.rpm packages), and Arch Linux uses pacman. In this comprehensive guide, we cover the exact syntax for each family, repository management, version pinning, dependency troubleshooting, and visual package inspection with SSH Desktop Package Manager.

1. The Linux Package Management Landscape

Linux distributions package precompiled software along with metadata such as dependencies, configuration templates, and cryptographic signatures. Here is how modern package formats and managers correspond across major Linux operating systems:

Distribution Family Low-Level Tool High-Level CLI Manager Package Format
Ubuntu / Debian / Mint dpkg apt / apt-get .deb
RHEL / CentOS / Rocky / Fedora rpm dnf (formerly yum) .rpm
Arch Linux / Manjaro pacman pacman .pkg.tar.zst
openSUSE / SLES rpm zypper .rpm

2. APT Mastery for Ubuntu & Debian Systems

Modern Debian-based systems use apt as the recommended CLI interface, replacing older scripts like apt-get and apt-cache for everyday interactive terminal usage.

Updating Package Indexes vs Upgrading Software

One of the most frequent beginner misconceptions is confusing update with upgrade: 

# Step 1: Refresh the repository catalog lists (does NOT install anything)
sudo apt update

# Step 2: Upgrade all installed packages to their latest versions
sudo apt upgrade -y

# Optional: Upgrade packages that require changing dependencies or removing obsolete packages
sudo apt full-upgrade -y

Searching and Inspecting Packages

# Search for a package in the remote repositories
apt search nginx

# Show detailed metadata, dependencies, and installed version
apt show nginx

# List all installed packages on the server
apt list --installed | grep nginx

Removing Packages and Cleaning Cache

When you remove software with standard apt remove, configuration files in /etc/ are retained. To completely wipe all residual configs and reclaim server disk space: 

# Remove package but keep configuration files
sudo apt remove nginx

# Remove package AND delete its configuration files
sudo apt purge nginx

# Remove orphaned dependencies that are no longer needed by any installed package
sudo apt autoremove --purge

# Clean out downloaded .deb installer files in /var/cache/apt/archives/
sudo apt clean

Pro-Tip: Locking Package Versions (apt-mark hold)

If your production web app requires an exact minor version of PHP or Node.js, prevent automated updates from upgrading it with apt-mark: 

sudo apt-mark hold nodejs
# To unhold later:
sudo apt-mark unhold nodejs
# View currently pinned packages:
apt-mark showhold

3. DNF & RPM Commands for RHEL, Rocky Linux & Fedora

Enterprise Red Hat derivatives use dnf (Dandified YUM) to manage .rpm packages. DNF offers superior dependency resolution, parallel downloads, and full transaction history rollback. 

# Check for available package updates without installing
sudo dnf check-update

# Upgrade all packages
sudo dnf upgrade -y

# Install a package
sudo dnf install -y nginx

# View transaction history
sudo dnf history

# Undo an erroneous upgrade or installation transaction (e.g., transaction #14)
sudo dnf history undo 14

4. Resolving Broken Dependencies & Corrupted Locks

Interrupted terminal sessions or conflicting third-party repositories can leave package databases in an inconsistent or locked state. Here is the diagnostic playbook:

Fixing "Could not get lock /var/lib/dpkg/lock-frontend"

This error occurs when an unattended upgrade or another background process is holding the database lock: 

# Check which process is holding the lock
sudo lsof /var/lib/dpkg/lock-frontend

# If an unattended-upgrade is running, wait a minute for it to finish.
# If a crashed terminal process is holding it, kill the PID:
sudo kill -9 <PID>

# Reconfigure interrupted package installations
sudo dpkg --configure -a

Fixing Unmet Dependencies in APT

# Force APT to repair broken dependency trees
sudo apt update --fix-missing
sudo apt --fix-broken install

5. Frequently Asked Questions

What is the difference between apt update and apt upgrade?

apt update fetches the latest package lists from all configured software repositories, refreshing local catalog indexes. It modifies zero software on disk. apt upgrade analyzes the updated lists and downloads and installs newer packages.

How do I prevent a specific package from being upgraded in Ubuntu or Debian?

You can lock a package at its current version using sudo apt-mark hold <package_name>. This prevents unattended security upgrades or manual apt upgrade runs from changing it. To unlock it later, run sudo apt-mark unhold <package_name>.

How do I fix unmet dependencies or broken packages in APT?

Run sudo apt update --fix-missing followed by sudo apt --fix-broken install. If issues persist, clean cached packages with sudo apt clean and check for half-installed states using sudo dpkg --configure -a.
