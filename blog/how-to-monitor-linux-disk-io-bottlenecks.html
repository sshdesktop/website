How to Monitor Linux Disk I/O Bottlenecks: Complete 2026 Guide

A server with 16 CPU cores and 64GB of RAM can still freeze completely if a single process saturates storage I/O throughput. When disks become overwhelmed, processes enter an uninterruptible sleep state (D state), causing load averages to skyrocket while CPU utilization appears almost idle. Learn how to pinpoint disk I/O bottlenecks in 2026 using iostat, iotop, and pidstat.

Recognizing Disk I/O Starvation

In top or htop, inspect the CPU state line. If %wa (iowait) is consistently above 10% to 15% and load average is significantly higher than the number of CPU cores, your server is bottlenecked by disk throughput or IOPS limits.

Step 1: Deep Disk Latency Analysis with iostat

Install the sysstat suite containing iostat:

sudo apt install -y sysstat   # Ubuntu / Debian
sudo dnf install -y sysstat   # RHEL / Fedora

Run extended I/O metrics refreshed every 1 second:

iostat -xz 1

Key metrics to evaluate:

  • r/s and w/s: Read and write operations per second (IOPS). Compare this with your cloud drive's provisioned IOPS limit.
  • rMB/s and wMB/s: Megabytes read and written per second (throughput).
  • await: Average time (in milliseconds) for I/O requests to be served. NVMe SSDs should be <1.0ms; enterprise SATA SSDs <5.0ms. If await exceeds 50ms, requests are queuing severely.
  • %util: Percentage of device saturation. Consistent 100% means the device is completely overwhelmed.

Step 2: Pinpoint the Offending Process with iotop

Once you know the disk is saturated, identify which specific process or thread is driving the traffic: 

# Install iotop
sudo apt install -y iotop

# Run iotop showing only active I/O consumers in accumulated mode
sudo iotop -oPa

Inspect the DISK READ and DISK WRITE columns. You can immediately spot whether PostgreSQL, Docker, Elasticsearch, or a rogue cron job is hammering the storage layer.

Step 3: Process-Level I/O Tracking with pidstat

To inspect I/O rates per process ID over a 2-second interval:

pidstat -d 2 5

This reveals kB_rd/s, kB_wr/s, and kB_ccwr/s (cancelled write bytes), highlighting processes that constantly rewrite temporary data.

Frequently Asked Questions

What is high iowait in top, and why does it cause high server load?

iowait (%wa) indicates the percentage of time CPU cores were idle while waiting for disk I/O requests to complete. When storage cannot keep up with write/read demand, threads block in uninterruptible sleep (D state), skyrocketing system load averages even when CPU usage is low.

What does %util mean in iostat -xz 1?

%util represents the percentage of elapsed time during which I/O requests were issued to the device (bandwidth utilization). If %util reaches 95%–100% on spinning disks or standard SSDs, the disk has reached saturation.

How do I find which exact process is thrashing my disk right now?

Run sudo iotop -oPa. The -o flag filters only processes actively doing I/O, -P shows threads as processes, and -a accumulates total read/write bytes over time to pinpoint the biggest offender.
