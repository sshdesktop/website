How to Protect SSH with Fail2ban on Linux (Ubuntu, Debian, RHEL): 2026 Guide

Server Security By SSH Desktop Engineering Team • Updated November 2026 • 10 min read

The moment any Linux server is connected to the public internet, automated botnets and malicious scanners begin bombarding port 22 with dictionary attacks. Left unmitigated, these attacks fill server auth logs with thousands of entries, exhaust CPU cycles, and risk unauthorized penetration if weak credentials exist on any user account.

Executive Summary

Fail2ban inspects authentication log files in real-time (such as /var/log/auth.log or systemd journal logs) and automatically updates firewall rules (using iptables, nftables, or ufw) to drop packets from offensive IP addresses. In this tutorial, you will configure custom bans, set up permanent whitelists, and monitor attacks visually with SSH Desktop Security Auditor.

1. Installing Fail2ban on Ubuntu, Debian & RHEL

# On Ubuntu & Debian:
sudo apt update && sudo apt install -y fail2ban

# On RHEL, CentOS, Rocky Linux & Fedora:
sudo dnf install -y epel-release
sudo dnf install -y fail2ban fail2ban-systemd

# Enable and start the systemd service
sudo systemctl enable --now fail2ban

2. Configuring jail.local for SSH Defense

Never modify the default jail.conf file directly, as package upgrades will overwrite your changes. Instead, create a jail.local file: 

# Copy base configuration to jail.local
sudo cp /etc/fail2ban/jail.conf /etc/fail2ban/jail.local

# Open jail.local in your editor or SSH Desktop Monaco editor
sudo nano /etc/fail2ban/jail.local

Recommended Production Configuration

Locate the [DEFAULT] and [sshd] sections and apply these hardened parameters: 

[DEFAULT]
# Whitelist localhost and your trusted office/home static IP
ignoreip = 127.0.0.1/8 ::1 198.51.100.25

# Time an IP remains banned (e.g. 1 hour or 24 hours)
bantime = 1h

# Window of time in which failed attempts are counted
findtime = 10m

# Number of failed login attempts before a ban is triggered
maxretry = 5

[sshd]
enabled = true
port = ssh
# If you changed your SSH port to 2222, specify: port = 2222
filter = sshd
logpath = %(sshd_log)s
backend = systemd
# Restart Fail2ban to load your new jail settings
sudo systemctl restart fail2ban

3. Monitoring and Managing Bans with fail2ban-client

Fail2ban includes a CLI utility to inspect jail status and unban IP addresses: 

# Check the overall status of active jails
sudo fail2ban-client status

# Check detailed status of the SSH jail (including banned IP list)
sudo fail2ban-client status sshd

# Manually ban an abusive IP address immediately
sudo fail2ban-client set sshd banip 203.0.113.199

# Unban an IP address (e.g., an employee locked out by accident)
sudo fail2ban-client set sshd unbanip 203.0.113.199

4. Integration with UFW (Uncomplicated Firewall)

If your Ubuntu host uses UFW, instruct Fail2ban to use the UFW action so banned IPs appear directly within ufw status: 

[sshd]
enabled = true
port = ssh
banaction = ufw

5. Frequently Asked Questions

How do I check which IPs are currently banned by Fail2ban?

Run sudo fail2ban-client status sshd. The output will display the total number of failed attempts, total banned IPs, and a list of currently active banned IP addresses.

How do I unban an accidentally banned IP address?

Execute sudo fail2ban-client set sshd unbanip <IP_ADDRESS>. You can also whitelist trusted static IP addresses permanently by adding them to the ignoreip directive in /etc/fail2ban/jail.local.

Why should I edit jail.local instead of jail.conf?

The /etc/fail2ban/jail.conf file is provided by the package maintainer and will be overwritten whenever Fail2ban is updated via apt or dnf. Any custom configuration in /etc/fail2ban/jail.local safely overrides jail.conf and persists across software updates.
