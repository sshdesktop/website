How to Set Environment Variables in Linux (PATH, .bashrc, export) 2026 Guide

Shell & Environment By SSH Desktop Engineering Team • Updated November 2026 • 10 min read

Environment variables govern how Linux shells, services, and applications behave. From pointing your shell to custom binaries via $PATH to configuring database connection strings in cloud environments, understanding how variables are created, exported, and persisted across reboots is fundamental to server administration.

Executive Summary

Shell variables created with NAME=value are private to the active shell. Adding export NAME=value makes them accessible to child processes. To persist variables permanently, they must be saved to files like ~/.bashrc (user scope) or /etc/environment (system-wide scope). In this guide, we review variable lifecycles, PATH management, systemd configurations, and visual management via SSH Desktop Environment Manager.

1. Shell Variables vs Environment Variables

In bash and zsh, there is a crucial difference between local shell variables and exported environment variables: 

# 1. Local Shell Variable (NOT visible to subprocesses or scripts)
MY_APP="ProductionApp"
python3 -c "import os; print(os.environ.get('MY_APP'))"
# Output: None

# 2. Exported Environment Variable (Inherited by subprocesses)
export MY_APP="ProductionApp"
python3 -c "import os; print(os.environ.get('MY_APP'))"
# Output: ProductionApp

Inspecting Active Environment Variables

# Print all active environment variables
printenv

# View specific variable
printenv PATH
# or
echo "$PATH"

# Search for specific variable key
env | grep NODE_ENV

2. Making Environment Variables Permanent

Running export VAR=value in the terminal only updates the current shell's transient memory. When you disconnect your SSH session, the variable vanishes. To persist variables, choose the correct configuration file:

Target Configuration File Scope When Loaded
~/.bashrc Current User Every interactive non-login shell (standard SSH terminal sessions)
~/.profile or ~/.bash_profile Current User Initial login shell
/etc/environment System-Wide (All Users) Loaded by PAM during login (Key=Value syntax only, no bash code)
/etc/profile.d/*.sh System-Wide (All Users) Executed for all users during login shells

Example: Persisting Variables for Your User

# Append export command to ~/.bashrc
echo 'export DATABASE_URL="postgres://user:pass@localhost:5432/db"' >> ~/.bashrc

# Reload the configuration in the current session
source ~/.bashrc

3. Safely Adding Directories to $PATH

The $PATH variable is a colon-separated list of directories searched when you execute a command. Modifying it incorrectly is one of the most common causes of broken terminal sessions.

The Right Way to Append to PATH

# Append directory to existing PATH:
export PATH="$PATH:/opt/custom/bin"

# Prepend directory (prioritizes your custom binary over system defaults):
export PATH="/opt/custom/bin:$PATH"

Critical Warning: Never Overwrite PATH

If you accidentally run export PATH="/opt/custom/bin" without including $PATH, standard commands like ls, sudo, and clear will immediately fail with "command not found". If this happens, restore it with: 

export PATH="/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin"

4. Environment Variables in systemd Services & Cron

A frequent source of bugs in production is finding that an app runs fine manually in SSH, but fails when launched as a systemd service or cron job. This happens because system services do not read ~/.bashrc or login profiles.

Configuring Environment in systemd Service Files

In your service unit file (e.g. /etc/systemd/system/myapp.service): 

[Service]
Type=simple
User=www-data
# Option 1: Direct key-value declarations
Environment="NODE_ENV=production" "PORT=3000"

# Option 2: Load from a secure .env file
EnvironmentFile=/etc/myapp/production.env
ExecStart=/usr/bin/node /opt/myapp/server.js

5. Frequently Asked Questions

What is the difference between a shell variable and an environment variable?

A shell variable (created with VAR=value) only exists within the current shell instance and is not inherited by child processes or background commands. An environment variable (created with export VAR=value) is exported into the process environment table and inherited by all subprocesses spawned by that shell.

Why do my environment variables disappear when I close SSH or reboot?

Using export VAR=value directly in the terminal only modifies the active shell session's memory. To make the variable permanent, you must append it to a startup configuration file such as ~/.bashrc (for your specific user) or /etc/environment (for all system users).

How do I add a new directory to my PATH without breaking existing commands?

Always include the existing $PATH in your assignment: export PATH="$PATH:/opt/custom/bin". Never run export PATH="/opt/custom/bin" alone, as this will overwrite system directories and break basic commands like ls, sudo, and clear.
