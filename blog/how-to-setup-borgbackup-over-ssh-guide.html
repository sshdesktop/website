How to Set Up BorgBackup Over SSH for Linux Servers: 2026 Guide

Traditional file backup scripts (like raw tar.gz or un-deduplicated rsync) consume massive amounts of storage space and bandwidth. When backing up daily database dumps or system configurations, 90% of the content is identical to the day before. BorgBackup (Borg) provides space-efficient chunk-level deduplication, authenticated client-side encryption, and seamless SSH streaming. Learn how to configure production Borg backups in 2026.

How Borg Chunk-Level Deduplication Works

Borg splits files into variable-length chunks using a rolling hash algorithm. It hashes each chunk, compares it against an index of previously stored chunks, and only transmits and writes new, unseen data blocks. As a result, 30 days of daily 50GB backups typically require less than 80GB of total storage space instead of 1.5TB.

Step 1: Install BorgBackup on Both Servers

Install Borg on your source server and your offsite backup target:

# Ubuntu / Debian
sudo apt update
sudo apt install -y borgbackup

# RHEL / Fedora
sudo dnf install -y epel-release
sudo dnf install -y borgbackup

Step 2: Initialize an Encrypted Remote Repository

Generate a dedicated SSH keypair for automated backups:

ssh-keygen -t ed25519 -f ~/.ssh/id_borg -C "borg-backup-agent"
ssh-copy-id -i ~/.ssh/id_borg.pub backup_user@backup-storage.internal

Initialize the repository with repokey-chacha20-poly1305 encryption:

export BORG_REPO="ssh://backup_user@backup-storage.internal:22/mnt/backups/web-01"
export BORG_PASSPHRASE="SuperSecretLongBackupPassphrase123"

borg init --encryption=repokey-chacha20-poly1305 $BORG_REPO
Important: Export and store your Borg key safely: borg key export $BORG_REPO ~/.ssh/borg_web01.key. If you lose this key, your encrypted backups cannot be decrypted!

Step 3: Create an Automated Backup & Pruning Script

Create /usr/local/bin/borg-backup.sh:

#!/usr/bin/env bash
set -euo pipefail

export BORG_REPO="ssh://backup_user@backup-storage.internal:22/mnt/backups/web-01"
export BORG_RSH="ssh -i /root/.ssh/id_borg -o StrictHostKeyChecking=accept-new"
export BORG_PASSPHRASE="SuperSecretLongBackupPassphrase123"

TIMESTAMP=$(date +"%Y-%m-%d_%H%M")

echo "Starting Borg backup at $(date)..."

# Create archive
borg create --stats --progress --compression lz4 \
    $BORG_REPO::"web01_${TIMESTAMP}" \
    /var/www \
    /etc \
    /var/backups \
    --exclude '/var/www/*/cache' \
    --exclude '/var/www/*/tmp'

# Prune old archives (7 daily, 4 weekly, 6 monthly)
borg prune -v --list --stats \
    --keep-daily=7 \
    --keep-weekly=4 \
    --keep-monthly=6 \
    $BORG_REPO

# Compact repository segments
borg compact $BORG_REPO

echo "Borg backup completed successfully!"
sudo chmod 700 /usr/local/bin/borg-backup.sh

Step 4: Restoring Files from an Archive

To inspect archives and restore individual files:

# List all archives
borg list $BORG_REPO

# Extract a specific directory from an archive
borg extract $BORG_REPO::web01_2026-11-16_0200 var/www/html/wp-config.php

Frequently Asked Questions

Why is BorgBackup superior to standard rsync or tar backups?

BorgBackup performs chunk-level deduplication. If 10 virtual machines or daily database dumps share 95% identical data, Borg only uploads and stores the unique 5% delta. Furthermore, every backup archive is client-side encrypted using Authenticated Encryption (AES-GCM or ChaCha20-Poly1305) before leaving the server.

How does Borg authenticate and stream data across SSH?

Borg connects to the remote storage server using standard OpenSSH keys and executes the borg serve command on the target. All communication, chunk verification, and locking happen securely over the SSH pipe.

How do I automatically prune older backups with Borg?

Use the borg prune command with retention flags: borg prune -v --list --keep-daily=7 --keep-weekly=4 --keep-monthly=6. This preserves a comprehensive historical snapshot timeline while automatically cleaning out redundant older archives.
