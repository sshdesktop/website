How to Set Up Nginx Brotli Compression: 2026 Speed Guide

Page weight directly dictates mobile load times, bounce rates, and Google Core Web Vitals rankings. While Gzip has been the web standard for over two decades, Google's Brotli algorithm delivers significantly higher density compression with faster decompression times. Learn how to install and configure Brotli on Nginx web servers in 2026.

Why Brotli Outperforms Gzip

Brotli uses a 120KB static dictionary of common web words, HTML tags, and JavaScript keywords built directly into the decompressor. As a result, repetitive syntax in frontend bundles compresses up to 30% smaller than standard Gzip.

Step 1: Install Nginx with the Brotli Module

On Ubuntu and Debian, install the official dynamic Brotli module from the verified Ondřej Surý or Nginx PPA: 

# Add official PPA with pre-compiled modules
sudo add-apt-repository -y ppa:ondrej/nginx
sudo apt update
sudo apt install -y nginx libnginx-mod-brotli

Step 2: Configure Brotli Directives in nginx.conf

Edit /etc/nginx/nginx.conf inside the http { ... } block:

http {
    # Enable dynamic Brotli compression
    brotli on;
    brotli_comp_level 6; # Optimal balance between compression ratio and CPU usage

    # Enable pre-compressed static file serving (.br)
    brotli_static on;

    # Minimum response size to compress
    brotli_min_length 256;

    # MIME types to compress
    brotli_types
        text/plain
        text/css
        text/xml
        text/javascript
        application/javascript
        application/x-javascript
        application/json
        application/xml
        application/xml+rss
        image/svg+xml;
}

Step 3: Static Pre-Compression for Maximum Performance

For static production assets (CSS, JS, SVG), pre-compress files at build time using the brotli CLI utility at maximum compression level 11: 

# Pre-compress all CSS and JS files in production directory
find /var/www/html/assets -type f \( -name "*.css" -o -name "*.js" \) -exec brotli -f -k -q 11 {} \;

With brotli_static on;, Nginx serves the pre-generated .br file directly from disk, delivering maximum compression with zero runtime CPU usage.

Step 4: Test and Verify with curl

Send a request advertising Accept-Encoding: br:

curl -I -H "Accept-Encoding: br" https://example.com/assets/css/style.min.css

Verify that the response includes:

Content-Encoding: br

Frequently Asked Questions

How much better is Brotli compression compared to standard Gzip?

Developed by Google, Brotli achieves 15%–25% higher compression ratios on JavaScript and HTML, and up to 30% smaller files on CSS compared to Gzip at identical CPU overhead. This drastically accelerates First Contentful Paint (FCP) and Largest Contentful Paint (LCP).

What is the difference between dynamic Brotli and static pre-compressed Brotli?

Dynamic Brotli compresses HTTP responses on the fly as requests arrive (recommended level 4 to 6 for real-time speed). Static Brotli (brotli_static on) serves pre-compressed .br files generated during your build pipeline at maximum level 11 with 0% runtime CPU cost.

Do all modern web browsers support Brotli compression?

Yes. 98%+ of global web traffic across Chrome, Edge, Safari, and Firefox supports Brotli over HTTPS via the Accept-Encoding: br request header.
