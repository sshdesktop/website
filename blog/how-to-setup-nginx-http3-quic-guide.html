How to Set Up Nginx HTTP/3 (QUIC) on Ubuntu: 2026 Speed Guide

Even on modern HTTP/2 connections, mobile users switching between Wi-Fi and 5G cellular networks suffer from connection renegotiation and TCP head-of-line blocking. HTTP/3 revolutionizes web performance by replacing TCP with QUIC over UDP, offering zero round-trip connection resumption (0-RTT) and seamless connection migration. Learn how to configure native HTTP/3 on Nginx in 2026.

The Superpowers of QUIC & HTTP/3

  • No Head-of-Line Blocking: In HTTP/3, independent requests are independent streams inside UDP. A dropped packet on an image asset never stalls CSS or API responses.
  • 0-RTT Connection Establishment: Returning visitors transmit encrypted HTTP requests in the very first UDP datagram.
  • Connection Migration: If a client switches from office Wi-Fi to mobile 5G, the QUIC Connection ID maintains the session without tearing down the TLS handshake.

Step 1: Check Nginx QUIC Support

Modern Nginx versions (1.25.0+) include native HTTP/3 QUIC support. Verify your installed binary:

nginx -V 2>&1 | grep -o "--with-http_v3_module"

If you see --with-http_v3_module, your Nginx build supports HTTP/3 out of the box.

Step 2: Open UDP Port 443 in Your Firewall

Remember that QUIC runs over UDP, not TCP! Open UDP port 443 in UFW: 

sudo ufw allow 443/udp
sudo ufw status

Step 3: Configure HTTP/3 in Your Nginx Virtual Host

Edit your site configuration file (e.g., /etc/nginx/sites-available/example.com):

server {
    # Standard TCP Listeners for HTTP/1.1 and HTTP/2
    listen 443 ssl;
    listen [::]:443 ssl;

    # QUIC UDP Listeners for HTTP/3
    listen 443 quic reuseport;
    listen [::]:443 quic reuseport;

    server_name example.com www.example.com;

    # SSL Certificates (Mandatory for HTTP/3)
    ssl_certificate /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;
    ssl_protocols TLSv1.3; # HTTP/3 strictly requires TLS 1.3

    # Advertise HTTP/3 support to visiting browsers via Alt-Svc header
    add_header Alt-Svc 'h3=":443"; ma=86400';
    add_header X-Protocol $server_protocol always;

    location / {
        proxy_pass http://localhost:3000;
        include proxy_params;
    }
}

Step 4: Test Syntax and Reload Nginx

sudo nginx -t && sudo systemctl reload nginx

Step 5: Verify HTTP/3 Protocol Negotiation

Test your domain using curl with HTTP/3 support:

curl --http3 -I https://example.com

Verify that the top response line outputs:

HTTP/3 200

Frequently Asked Questions

What is the main difference between HTTP/2 and HTTP/3?

HTTP/2 multiplexes streams over a single TCP connection; however, if a single packet drops, all streams block until retransmission completes (TCP head-of-line blocking). HTTP/3 replaces TCP with QUIC over UDP, ensuring packet loss in one stream never delays or stalls other streams.

Why does HTTP/3 require opening UDP port 443 in the firewall?

QUIC runs exclusively on top of User Datagram Protocol (UDP). While standard HTTPS uses TCP port 443, HTTP/3 requires UDP port 443 to be opened in your UFW or iptables firewall; otherwise, web browsers fallback to HTTP/2.

How does a browser discover that my website supports HTTP/3?

The browser initially connects via TCP (HTTP/1.1 or HTTP/2). Nginx returns an Alt-Svc response header (e.g., Alt-Svc: h3=":443"; ma=86400). The browser caches this directive and initiates all subsequent requests over QUIC UDP.
