How to Set Up Nginx Reverse Proxy with SSL: Complete 2026 Guide

Web Servers By SSH Desktop Engineering Team • Updated November 2026 • 10 min read

Modern backend applications written in Node.js, Python (FastAPI/Django), Go, or Java rarely listen directly on public HTTP ports 80 or 443. Instead, standard production architecture places Nginx in front as an edge reverse proxy. Nginx handles SSL/TLS encryption, static asset caching, rate limiting, and HTTP-to-HTTPS redirection, forwarding clean requests to your application on localhost.

Executive Summary

Configuring an Nginx reverse proxy involves creating a virtual host in /etc/nginx/sites-available/, using proxy_pass to direct traffic to your upstream service port, and attaching trusted SSL certificates with Certbot. In this guide, we review header propagation, WebSocket upgrades, syntax verification, and visual proxy management with SSH Desktop Reverse Proxy Browser.

1. Installing Nginx and Firewall Verification

# On Ubuntu/Debian:
sudo apt update && sudo apt install -y nginx

# Open standard HTTP (80) and HTTPS (443) ports in UFW:
sudo ufw allow 'Nginx Full'
sudo systemctl enable --now nginx

2. Configuring the Reverse Proxy Virtual Host

Create a new server block configuration file (e.g., /etc/nginx/sites-available/myapp.conf): 

server {
    listen 80;
    server_name api.yourdomain.com;

    # Redirect all HTTP requests to HTTPS
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name api.yourdomain.com;

    # SSL Certificate Paths (Managed by Certbot or SSH Desktop SSL Manager)
    ssl_certificate /etc/letsencrypt/live/api.yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/api.yourdomain.com/privkey.pem;

    # Modern TLS Security Protocols
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
    ssl_prefer_server_ciphers on;

    # Reverse Proxy Location Block
    location / {
        # Upstream service listening on localhost (e.g. Node.js on port 3000)
        proxy_pass http://127.0.0.1:3000;

        # Forward real client headers to upstream application
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # WebSocket support (Prevents connection dropouts)
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        # Timeouts and buffer sizes
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }
}

3. Enabling the Configuration and Testing Syntax

On Debian-based systems, configurations are activated by creating a symbolic link into sites-enabled: 

# Enable site configuration
sudo ln -s /etc/nginx/sites-available/myapp.conf /etc/nginx/sites-enabled/

# ALWAYS test configuration syntax before reloading!
sudo nginx -t
# Output must display: syntax is ok / test is successful

# Reload Nginx without dropping active connections
sudo systemctl reload nginx

4. Securing Free Automated SSL with Certbot

If you haven't yet provisioned an SSL certificate, Let's Encrypt Certbot will inject the certificates into your virtual host automatically: 

# Install Certbot Nginx plugin
sudo apt install -y certbot python3-certbot-nginx

# Obtain and install SSL certificate automatically
sudo certbot --nginx -d api.yourdomain.com

5. Frequently Asked Questions

What is the difference between a forward proxy and a reverse proxy?

A forward proxy sits in front of client devices to protect, anonymize, or filter their outbound internet requests. A reverse proxy sits in front of backend web servers to accept incoming internet traffic and distribute requests to internal services (such as Node.js, Python, or Docker containers) while providing SSL termination and load balancing.

Why is my backend application seeing 127.0.0.1 instead of the real client IP?

By default, Nginx terminates the TCP connection and establishes a fresh internal connection to the upstream service. To pass the visitor's real IP address, you must configure proxy_set_header X-Real-IP $remote_addr; and proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; in your server location block.

How do I proxy WebSockets through Nginx without connection dropouts?

WebSockets require HTTP/1.1 and hop-by-hop headers. Add proxy_http_version 1.1;, proxy_set_header Upgrade $http_upgrade;, and proxy_set_header Connection "upgrade"; inside the location block to prevent disconnection.
