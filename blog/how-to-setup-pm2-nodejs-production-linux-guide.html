How to Set Up PM2 for Node.js in Production on Linux: 2026 Guide

Node.js is blazingly fast for asynchronous I/O, but by default it runs as a single-threaded process. If an unhandled exception triggers a crash or if heavy CPU work blocks the event loop, your entire application goes down. PM2 is the production process manager of choice for Node.js, providing built-in clustering across CPU cores, zero-downtime hot reloads, automatic systemd resurrection, and log rotation. Learn how to configure PM2 on Linux in 2026.

Step 1: Install PM2 Globally via npm

Ensure Node.js and npm are installed, then install PM2 globally:

sudo npm install -g pm2

# Verify version
pm2 -v

Step 2: Start Application in Cluster Mode

Instead of running in single-threaded fork mode, launch your application utilizing all available CPU cores: 

# Start application using all CPU cores with automatic load balancing
pm2 start server.js --name "api-backend" -i max

Or create a declarative production configuration file (ecosystem.config.js):

module.exports = {
  apps: [{
    name: 'api-backend',
    script: './dist/index.js',
    instances: 'max',
    exec_mode: 'cluster',
    max_memory_restart: '1G',
    env_production: {
      NODE_ENV: 'production',
      PORT: 3000
    }
  }]
};

Start using the ecosystem file:

pm2 start ecosystem.config.js --env production

Step 3: Enable Zero-Downtime Hot Reloads

When deploying new code releases, never use pm2 restart which drops connections. Use rolling reloads: 

# Rolling reload: zero dropped HTTP packets
pm2 reload api-backend

Step 4: Configure Automatic Reboot Persistence with Systemd

To ensure PM2 resurrects your Node.js processes automatically after server reboots or kernel upgrades: 

# Generate and install systemd startup hook
pm2 startup systemd

# (Copy and execute the sudo command PM2 outputs, for example:)
# sudo env PATH=$PATH:/usr/bin pm2 startup systemd -u youruser --hp /home/youruser

# Save current active process list
pm2 save

Step 5: Production Log Rotation

PM2 writes application stdout and stderr logs to ~/.pm2/logs/. Install the official logrotate module to prevent disk exhaustion: 

pm2 install pm2-logrotate
pm2 set pm2-logrotate:max_size 50M
pm2 set pm2-logrotate:retain 10
pm2 set pm2-logrotate:compress true

Step 6: Real-Time Process Monitoring

View CPU and memory metrics per worker in real time:

pm2 monit

Frequently Asked Questions

Why should I run Node.js with PM2 in Cluster Mode instead of Fork Mode?

Node.js runs on a single thread by default. On a 4-core or 8-core CPU, Fork mode only utilizes 1 core, wasting 75%–87% of server compute capacity. PM2 Cluster mode (pm2 start app.js -i max) spawns worker processes across all available CPU cores, sharing the network port and multiplying request throughput.

What is the difference between pm2 restart and pm2 reload?

pm2 restart terminates all worker processes simultaneously and restarts them, causing brief downtime. pm2 reload performs a rolling zero-downtime reload: it spawns a new worker, waits for it to listen, and then shuts down the old worker sequentially.

How do I ensure PM2 restarts all Node.js applications after a server reboot?

Run pm2 startup to generate and configure a systemd service unit. Then run pm2 save to freeze your current active process list into ~/.pm2/dump.pm2. Upon system reboot, systemd automatically resurrects your entire process tree.
