How to Set Up SSH Two-Factor Authentication (2FA) on Linux: 2026 Guide

Even robust SSH key authentication can be compromised if an administrator's laptop is stolen, infected with malware, or if an unencrypted private key is leaked. Implementing Two-Factor Authentication (2FA / MFA) using Time-based One-Time Passwords (TOTP) ensures that physical possession of an authenticator device is mandatory for every login. Learn how to configure SSH 2FA on Ubuntu, Debian, and RHEL in 2026.

How Pluggable Authentication Modules (PAM) Secure SSH

OpenSSH delegates secondary authentication challenges to Linux PAM (Pluggable Authentication Modules). By pairing the pam_google_authenticator module with the OpenSSH daemon (sshd), Linux validates cryptographic SSH keys and time-synchronized 6-digit TOTP codes seamlessly.

Warning: Always keep an active SSH terminal session open in a separate window while configuring 2FA so you can revert settings if an error occurs.

Step 1: Install the Google Authenticator PAM Module

Install the libpam module on Ubuntu / Debian:

sudo apt update
sudo apt install -y libpam-google-authenticator

On RHEL, Fedora, or Rocky Linux:

sudo dnf install -y epel-release
sudo dnf install -y google-authenticator

Step 2: Generate TOTP Secret Keys & Emergency Codes

Run the configuration wizard as the specific Linux user you want to protect:

google-authenticator

The interactive wizard will prompt you with critical security questions:

  • Make tokens time-based (y/n)? Select y.
  • Update your ~/.google_authenticator file? Select y.
  • Disallow multiple uses of the same token? Select y (prevents replay attacks).
  • Permit 3 tokens (window of 1:30 min)? Select n to maintain strict 30-second time drift windows.
  • Enable rate-limiting (3 logins every 30 seconds)? Select y.

The terminal will print a large QR code and 5 emergency scratch codes. Scan the QR code using Google Authenticator, 1Password, Aegis, or Authy, and save the scratch codes safely.

Step 3: Configure PAM for OpenSSH

Edit the PAM configuration for SSH at /etc/pam.d/sshd:

sudo nano /etc/pam.d/sshd

Add the following line at the top or bottom depending on whether you want password + 2FA or key + 2FA:

auth required pam_google_authenticator.so nullok

The nullok parameter allows users who have not yet configured 2FA to log in without being permanently locked out. Remove nullok once all users complete setup.

Step 4: Update sshd_config to Enforce 2FA

Edit /etc/ssh/sshd_config:

sudo nano /etc/ssh/sshd_config

Ensure these directives are active:

# Enable keyboard-interactive authentication for TOTP prompts
KbdInteractiveAuthentication yes

# Require BOTH public key and 2FA code
AuthenticationMethods publickey,keyboard-interactive

Test the syntax and restart OpenSSH:

# Test syntax
sudo sshd -t

# Restart SSH service
sudo systemctl restart ssh || sudo systemctl restart sshd

Step 5: Verify the 2FA Workflow

Open a new terminal window and connect to the server:

ssh username@your-server-ip

The server will authenticate your private key, then prompt:

Verification code: [Enter 6-digit TOTP code]

Frequently Asked Questions

Can I require both an SSH key AND a TOTP verification code?

Yes. By configuring AuthenticationMethods publickey,keyboard-interactive inside /etc/ssh/sshd_config, OpenSSH will require a valid cryptographic SSH key first, followed immediately by a 6-digit TOTP code generated by Google Authenticator.

What happens if I lose my phone with the 2FA app?

During initial setup, google-authenticator generates 5 emergency scratch codes. Store these in an encrypted password manager. Alternatively, if locked out, access the server via your cloud provider VPS emergency console to reset ~/.google_authenticator.

Will enabling SSH 2FA break SFTP file transfers or automated scripts?

If you require keyboard-interactive globally, non-interactive SFTP or automated rsync cron scripts will fail unless you authenticate via an SSH key in an ssh-agent session, or create a dedicated Match block in sshd_config exempting specific backup users.
