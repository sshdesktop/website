How to Set Up SSH Port Knocking with knockd: 2026 Security Guide

Leaving OpenSSH port 22 open to the world invites tens of thousands of automated credential-stuffing bot scans every day, cluttering /var/log/auth.log and indexing your server on search engines like Shodan and Censys. Port Knocking provides stealth security by keeping port 22 completely closed until a secret sequence of network knocks opens it dynamically for your IP. Learn how to configure knockd and iptables in 2026.

How knockd Operates via Packet Sniffing

Unlike web services that bind to open sockets, knockd uses libpcap to inspect raw network packet headers on your interface. Because the ports it monitors are closed at the firewall level, port scanners receive no response. Only when the exact sequence of SYN packets arrives does knockd execute an iptables rule allowing your IP through.

Step 1: Install knockd and iptables-persistent

Install the daemon on Ubuntu or Debian:

sudo apt update
sudo apt install -y knockd iptables-persistent

Step 2: Configure the knockd Daemon

Edit the configuration file at /etc/knockd.conf:

sudo nano /etc/knockd.conf

Configure open and close knock sequences:

[options]
    UseSyslog
    Interface = eth0   # Change to your public interface (check with: ip route)

[openSSH]
    sequence    = 7000:tcp,8000:tcp,9000:tcp
    seq_timeout = 5
    command     = /sbin/iptables -I INPUT -s %IP% -p tcp --dport 22 -j ACCEPT
    tcpflags    = syn

[closeSSH]
    sequence    = 9000:tcp,8000:tcp,7000:tcp
    seq_timeout = 5
    command     = /sbin/iptables -D INPUT -s %IP% -p tcp --dport 22 -j ACCEPT
    tcpflags    = syn

Enable the daemon in /etc/default/knockd:

# Set START_KNOCKD=1
START_KNOCKD=1

Step 3: Lock Down the Firewall

Warning: Keep your current SSH terminal session open while testing firewall rules to prevent locking yourself out!

Allow existing connections, then block all new unsolicited connections to port 22:

# Allow established connections so you do not get disconnected
sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT

# Allow loopback
sudo iptables -A INPUT -i lo -j ACCEPT

# Drop all standard port 22 attempts
sudo iptables -A INPUT -p tcp --dport 22 -j DROP

# Save iptables rules
sudo netfilter-persistent save

Step 4: Start knockd and Test Connection

Start and enable the service:

sudo systemctl enable --now knockd

From your local machine, try connecting to SSH (it will hang or time out):

ssh user@your-server-ip   # Connection hangs!

Send the secret knock sequence:

knock your-server-ip 7000:tcp 8000:tcp 9000:tcp

Immediately connect via SSH:

ssh user@your-server-ip   # Connected successfully!

Frequently Asked Questions

What is SSH port knocking, and how does it protect Linux servers?

Port knocking keeps SSH port 22 completely closed and filtered in the firewall by default. A background daemon (knockd) listens on network interfaces for a secret sequence of connection attempts to closed ports (e.g., TCP 7000, 8000, 9000). Upon receiving the valid knock sequence, the firewall opens port 22 dynamically only for the sender's IP address.

Can automated bots or Shodan scan and discover knocked ports?

No. To port scanners, all ports appear closed or filtered. The odds of a random scanner guessing a 3-port sequence with exact protocol flags within a 5-second window is less than 1 in 280 trillion.

How do I send a knock sequence from Windows, Mac, or Linux?

On Linux/macOS, use the knock utility: knock server-ip 7000:tcp 8000:tcp 9000:tcp. On Windows, use PowerShell with Test-NetConnection or dedicated SSH clients with pre-connection knock triggers.
