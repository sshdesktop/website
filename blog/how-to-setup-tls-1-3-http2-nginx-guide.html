How to Set Up TLS 1.3 & HTTP/2 on Nginx (2026 Security Guide)

Modern web applications require both cutting-edge cryptographic security and sub-second delivery. Legacy cryptographic protocols introduce dangerous downgrade vulnerabilities and add unnecessary round-trip latency to every TLS handshake. Learn how to configure modern TLS 1.3, HTTP/2 multiplexing, and hardened cipher suites on Nginx in 2026 to achieve an A+ score on SSL Labs.

The Benefits of TLS 1.3 & HTTP/2

  • Reduced Latency (1-RTT Handshake): TLS 1.3 cuts connection setup time in half, shaving 50ms–150ms off initial page load speeds.
  • Stream Multiplexing: HTTP/2 eliminates head-of-line blocking by transmitting multiple CSS, JS, and image assets concurrently over a single TCP connection.
  • PFS by Default: TLS 1.3 removes RSA static key exchanges entirely, mandating Ephemeral Diffie-Hellman (ECDHE) for Perfect Forward Secrecy.

Step 1: Check OpenSSL and Nginx Version Support

Ensure your server has OpenSSL 1.1.1+ (or 3.x) and Nginx 1.13.0+:

nginx -V 2>&1 | grep -o "built with OpenSSL [^ ]*"

Modern Ubuntu 22.04 and 24.04 LTS installations ship with OpenSSL 3.0+ by default.

Step 2: Generate Strong Diffie-Hellman Parameters

Generate a unique 2048-bit (or 4096-bit) DH group to harden TLS 1.2 backwards compatibility:

sudo openssl dhparam -out /etc/nginx/dhparam.pem 2048

Step 3: Configure Modern SSL Directives in Nginx

Create a dedicated security snippet at /etc/nginx/snippets/ssl-params.conf:

# Enable only TLS 1.2 and TLS 1.3
ssl_protocols TLSv1.2 TLSv1.3;

# Prioritize server ciphers
ssl_prefer_server_ciphers on;

# Hardened TLS 1.3 and TLS 1.2 Cipher Suites
ssl_ciphers 'ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384:DHE-RSA-AES128-GCM-SHA256:DHE-RSA-AES256-GCM-SHA384';

# DH Parameters
ssl_dhparam /etc/nginx/dhparam.pem;

# SSL Session Caching
ssl_session_timeout 1d;
ssl_session_cache shared:SSL:10m;
ssl_session_tickets off;

# OCSP Stapling
ssl_stapling on;
ssl_stapling_verify on;
resolver 1.1.1.1 8.8.8.8 valid=300s;
resolver_timeout 5s;

# HSTS (Strict-Transport-Security)
add_header Strict-Transport-Security "max-age=63072000; includeSubDomains; preload" always;

Step 4: Enable HTTP/2 on Server Block

In your site virtual host (e.g., /etc/nginx/sites-available/example.com), enable the http2 parameter:

server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name example.com www.example.com;

    ssl_certificate /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;
    include snippets/ssl-params.conf;

    location / {
        proxy_pass http://localhost:3000;
        include proxy_params;
    }
}

Test configuration and reload:

sudo nginx -t && sudo systemctl reload nginx

Step 5: Verify TLS 1.3 & HTTP/2 with curl

Verify protocol negotiation directly from the command line:

curl -I --http2 https://example.com

You should see HTTP/2 200 in the top response header line.

Frequently Asked Questions

Why should I disable TLS 1.0 and TLS 1.1 on my web servers?

TLS 1.0 and 1.1 rely on obsolete cryptographic hash algorithms (MD5, SHA-1) vulnerable to POODLE, BEAST, and Sweet32 attacks. Major web browsers and PCI-DSS compliance standards officially deprecate and reject TLS 1.0/1.1.

What is the performance advantage of TLS 1.3 over TLS 1.2?

TLS 1.3 cuts handshake latency in half by completing the cryptographic negotiation in a single round-trip (1-RTT) instead of two (2-RTT). For returning visitors, zero round-trip resumption (0-RTT) transmits application data immediately on the very first packet.

How do I test if my Nginx server is actively using TLS 1.3?

Run openssl s_client -connect yourdomain.com:443 -tls1_3. Look for Protocol: TLSv1.3 and Cipher: TLS_AES_256_GCM_SHA384 in the terminal output.
