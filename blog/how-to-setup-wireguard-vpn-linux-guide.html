How to Set Up WireGuard VPN on Linux Server: Complete 2026 Guide

Networking & VPNs By SSH Desktop Engineering Team • Updated November 2026 • 10 min read

Virtual Private Networks (VPNs) have long been synonymous with complex, monolithic suites like OpenVPN and IPSec—plagued with slow connection handshakes, high CPU overhead, and sprawling configuration files. WireGuard has revolutionized Linux networking with an ultra-lean, kernel-level implementation that establishes tunnels instantly while maximizing throughput.

Executive Summary

WireGuard operates via public-key cryptography (similar to SSH keys). In this guide, you will install WireGuard on Ubuntu/Debian, generate Curve25519 keypairs, configure the wg0 interface, enable kernel IPv4 packet forwarding, and route client traffic securely.

1. Installing WireGuard and Enabling Packet Forwarding

# Install WireGuard on Ubuntu/Debian:
sudo apt update && sudo apt install -y wireguard

# Enable IPv4 packet forwarding in the Linux kernel:
echo "net.ipv4.ip_forward=1" | sudo tee -a /etc/sysctl.conf
sudo sysctl -p

2. Generating Server and Peer Cryptographic Keys

Navigate to /etc/wireguard/ with root privileges and generate your server keys: 

cd /etc/wireguard
umask 077

# Generate server private and public keys:
wg genkey | tee server_private.key | wg pubkey > server_public.key

# Generate client private and public keys:
wg genkey | tee client_private.key | wg pubkey > client_public.key

3. Configuring the Server Interface (/etc/wireguard/wg0.conf)

Create the server configuration file: 

[Interface]
Address = 10.0.0.1/24
ListenPort = 51820
PrivateKey = <CONTENTS_OF_SERVER_PRIVATE_KEY>

# Enable NAT masquerading when the interface comes UP, disable on DOWN:
PostUp = iptables -A FORWARD -i wg0 -j ACCEPT; iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
PostDown = iptables -D FORWARD -i wg0 -j ACCEPT; iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE

# Client Peer Section
[Peer]
PublicKey = <CONTENTS_OF_CLIENT_PUBLIC_KEY>
AllowedIPs = 10.0.0.2/32

4. Client Configuration (laptop.conf)

On your client workstation (or mobile phone): 

[Interface]
Address = 10.0.0.2/24
PrivateKey = <CONTENTS_OF_CLIENT_PRIVATE_KEY>
DNS = 1.1.1.1

[Peer]
PublicKey = <CONTENTS_OF_SERVER_PUBLIC_KEY>
Endpoint = 203.0.113.50:51820
# 0.0.0.0/0 routes all traffic through the VPN:
AllowedIPs = 0.0.0.0/0
PersistentKeepalive = 25

5. Starting the WireGuard Service

# Start and enable wg0 on boot:
sudo systemctl enable --now wg-quick@wg0

# Check tunnel status and transfer statistics:
sudo wg show

6. Frequently Asked Questions

Why is WireGuard faster than OpenVPN or IPSec?

WireGuard runs directly inside the Linux kernel space, avoiding the high overhead of context switching between user-space and kernel-space required by OpenVPN. It also relies on modern, highly optimized cryptography (Curve25519, ChaCha20-Poly1305, BLAKE2s) and maintains an ultra-lean codebase (~4,000 lines vs 100,000+ lines in OpenVPN).

Which UDP port does WireGuard use by default?

WireGuard typically listens on UDP port 51820. Because WireGuard is silent and does not respond to unauthenticated packets, port scanners cannot detect that the port is open.

How does WireGuard compare to an SSH SOCKS5 tunnel?

An SSH SOCKS5 tunnel operates at the application layer (TCP only) and must be configured per application (e.g. inside browser settings). WireGuard creates a true virtual network interface (wg0) that routes ALL operating system traffic, including UDP, DNS, ICMP, and VoIP packets.
