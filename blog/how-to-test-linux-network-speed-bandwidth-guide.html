How to Test Linux Server Network Speed & Bandwidth (iperf3, iftop, speedtest) 2026

Network Diagnostics By SSH Desktop Engineering Team • Updated November 2026 • 10 min read

Whether you are validating cloud provider SLA throughput, troubleshooting sluggish database queries between two virtual private clouds (VPCs), or diagnosing why user uploads are crawling, knowing how to accurately test and measure Linux server bandwidth is a critical skill.

Executive Summary

Testing network performance requires different tools depending on the problem: iperf3 measures raw point-to-point throughput, jitter, and packet loss between two servers; speedtest-cli tests public internet WAN bandwidth; and iftop / nethogs identify real-time bandwidth hogs per socket and process. In this guide, we review all three workflows alongside visual monitoring with SSH Desktop System Monitor.

1. Benchmarking Point-to-Point Throughput with iperf3

iperf3 is the gold standard for measuring maximum TCP and UDP throughput across network links without the disk I/O bottlenecks of file transfers: 

# Install iperf3 on Ubuntu/Debian:
sudo apt update && sudo apt install -y iperf3

# Step 1: Start iperf3 in server mode on the remote host (listens on port 5201):
iperf3 -s

# Step 2: Run benchmark from the client host (tests 10 seconds of TCP transfer):
iperf3 -c 203.0.113.50

Advanced iperf3 Flags

# Test with 4 parallel streams to saturate multi-gigabit links:
iperf3 -c 203.0.113.50 -P 4

# Test bidirectional transfer (upload and download simultaneously):
iperf3 -c 203.0.113.50 -d

# Benchmark UDP throughput and packet loss (target 1 Gbps):
iperf3 -c 203.0.113.50 -u -b 1G

2. Testing WAN Internet Speed with speedtest-cli

To test the public upload and download speed of your cloud server against nearby CDN servers: 

# Install speedtest-cli via apt or pip:
sudo apt install -y speedtest-cli

# Run complete bandwidth and latency test:
speedtest-cli --secure --share

3. Monitoring Real-Time Bandwidth Hogs with iftop & nethogs

When network traffic suddenly spikes, use real-time interactive tools to find out which IP address or PID is saturating your connection: 

# Install monitoring utilities:
sudo apt install -y iftop nethogs

# Inspect traffic by IP address and listening port:
sudo iftop -n -P

# Inspect bandwidth consumed per Linux Process ID (PID):
sudo nethogs eth0

4. Frequently Asked Questions

What is the difference between iperf3 and speedtest-cli?

speedtest-cli tests internet WAN throughput against public Ookla servers, measuring download/upload speeds to the wider internet. iperf3 is a raw client-server benchmarking tool designed to measure the maximum theoretical throughput, packet loss, and jitter between two specific private servers, VPCs, or cloud regions.

How do I find which process or IP is consuming all my bandwidth in real time?

Run sudo iftop -n -P to view live socket connections sorted by bandwidth consumption. To inspect which specific Linux Process ID (PID) owns that network socket, run sudo nethogs.

How can I test UDP throughput and jitter instead of TCP?

Add the -u flag to your iperf3 client command along with a target bitrate: iperf3 -c <server_ip> -u -b 100M. The output will display exact jitter in milliseconds and percentage of dropped UDP packets.
