How to Transfer Files Over SSH: SCP vs SFTP vs Rsync (2026 Complete Guide)

Published: November 2026 • 11 min read • By SSH Desktop Engineering Team

Transferring files between your local development machine and remote Linux servers is one of the most foundational tasks in DevOps, software engineering, and system administration.

However, with three different protocols available over SSH — SCP (Secure Copy Protocol), SFTP (SSH File Transfer Protocol), and Rsync — developers frequently ask: Which protocol is fastest? Why is OpenSSH deprecating SCP? And what is the best way to move large directories without cryptic command-line flags?

In this guide, we break down each tool's syntax, compare their real-world transfer performance, explain security vulnerabilities, and show how to use modern graphical SFTP clients for effortless drag-and-drop transfers.

Method 1: SCP (Secure Copy Protocol) — Commands & Quirks

Historically, scp was the go-to tool for quick terminal file copies. Its syntax mirrors the standard Unix cp command:

1. Copy a File from Local Laptop to Remote Server:

scp -i ~/.ssh/id_ed25519 local_file.tar.gz user@198.51.100.42:/var/www/uploads/

2. Copy a File from Remote Server to Local Laptop:

scp user@198.51.100.42:/var/log/nginx/access.log ./nginx-access.log

3. Recursively Copy an Entire Directory:

scp -r -P 2222 ./my_project/ user@198.51.100.42:/opt/apps/
Why OpenSSH Deprecated Legacy SCP: The legacy SCP protocol is fundamentally flawed. It executes the remote shell to expand wildcard arguments (e.g. scp user@host:* .). Malicious or compromised servers can manipulate filenames in transit to overwrite arbitrary client files (CVE-2019-6111). Starting in OpenSSH 9.0, the scp binary automatically uses the safer SFTP protocol under the hood.

Method 2: SFTP (SSH File Transfer Protocol) — Interactive CLI

SFTP is not FTP wrapped in SSH; it is an independent binary protocol designed specifically for SSH version 2. It supports interactive sessions, remote directory navigation, and file attribute manipulation.

Starting an SFTP Session:

sftp -i ~/.ssh/id_ed25519 user@198.51.100.42

Common SFTP Interactive Commands:

  • ls: List files in the remote directory.
  • lls: List files in your local directory.
  • cd /var/www: Change directory on the remote server.
  • lcd ~/Documents: Change directory on your local machine.
  • put filename.zip: Upload a file to the remote server.
  • get remote_file.csv: Download a file to your local machine.
  • reput file.iso: Resume an interrupted upload.
  • chmod 644 config.json: Modify remote file permissions directly.

Method 3: Rsync over SSH — The King of Large File Sync

When syncing multi-gigabyte media directories, website backups, or codebases, Rsync beats both SCP and SFTP hands down.

Rsync uses a patented rolling checksum algorithm to inspect existing files on the destination. If a 10 GB database backup only changed by 50 MB, Rsync transmits only the altered 50 MB chunks!

The Golden Rsync Command:

rsync -avzP -e "ssh -i ~/.ssh/id_ed25519" ./build/ user@198.51.100.42:/var/www/html/

Flags Decoded:

  • -a (archive): Preserves file timestamps, permissions, symlinks, and ownership recursively.
  • -v (verbose): Displays files being transferred.
  • -z (compress): Compresses data packets in transit to save network bandwidth.
  • -P (progress + partial): Shows a real-time progress bar and keeps partially transferred files so interrupted transfers can resume seamlessly.
  • -e "ssh ...": Specifies custom SSH port, keys, or options.
The Trailing Slash Trailing Trap: In Rsync, ./folder (without trailing slash) copies the directory itself (creating /path/folder/). Adding a trailing slash ./folder/ copies the contents of the directory into the destination.
