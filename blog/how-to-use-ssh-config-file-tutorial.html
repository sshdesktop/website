The Complete SSH Config File Tutorial: Shortcuts, Jump Hosts & Multi-Server Setup (2026)

Published: November 2026 • 10 min read • By SSH Desktop Engineering Team

Do you still connect to your remote servers by manually typing commands like this every single day?

ssh -i ~/.ssh/id_production_ed25519 -p 2222 ubuntu@198.51.100.42

Remembering IP addresses, custom ports, and unique private key files for dozens of virtual machines, staging servers, and production clusters is a recipe for frustration and typos.

By creating an SSH client configuration file (~/.ssh/config), you can transform that long, tedious command into a simple two-word shortcut:

ssh prod

In this definitive guide, you will master the syntax of ~/.ssh/config, configure multi-key mappings, automate bastion jump hosts with ProxyJump, prevent frozen connection timeouts, and learn how to manage configurations visually in SSH Desktop.

File Location & Initial Creation

The SSH config file is read automatically by OpenSSH on every connection attempt.

File Paths Across Operating Systems:

  • Linux & macOS: ~/.ssh/config (expanded: /home/username/.ssh/config)
  • Windows 11 & 10: C:Users<Username>.sshconfig (or $env:USERPROFILE.sshconfig in PowerShell)

Creating the File & Setting Permissions:

On Linux and macOS:

touch ~/.ssh/config
chmod 600 ~/.ssh/config

On Windows 11 PowerShell:

New-Item -ItemType File -Path "$env:USERPROFILE.sshconfig" -Force

Basic Syntax: Creating Your First Host Alias

A basic SSH config block consists of a Host identifier followed by indented directives:

Host prod
HostName 198.51.100.42
User ubuntu
Port 2222
IdentityFile ~/.ssh/id_production_ed25519

Now, whenever you run ssh prod, OpenSSH automatically uses the correct IP address, username, port, and key. Furthermore, tools like SCP, SFTP, and Rsync instantly inherit this alias:

scp local_archive.zip prod:/var/www/uploads/
sftp prod
rsync -avz ./dist/ prod:/var/www/html/

Core Directives Explained

Directive Description Example
Host Nickname or pattern used on the command line Host staging
HostName The real IP address or domain name HostName 203.0.113.8 or db.internal
User Remote Linux username User ec2-user
Port Remote SSH port (default is 22) Port 49152
IdentityFile Path to your specific private key IdentityFile ~/.ssh/id_ed25519
IdentitiesOnly Prevents offering unwanted ssh-agent keys IdentitiesOnly yes
ProxyJump Route through a bastion / jump host ProxyJump bastion
LocalForward Automatic port forwarding tunnel LocalForward 5432 127.0.0.1:5432

Advanced Pattern 1: Separate Keys for GitHub, Work & Personal

If you have multiple GitHub or GitLab accounts (e.g. personal vs company), you cannot use the same SSH key. You can create virtual hosts in your config:

# Work GitHub Account
Host github.com-work
HostName github.com
User git
IdentityFile ~/.ssh/id_work_ed25519
IdentitiesOnly yes

# Personal GitHub Account
Host github.com-personal
HostName github.com
User git
IdentityFile ~/.ssh/id_personal_ed25519
IdentitiesOnly yes

To clone a repository using your work credentials:

git clone git@github.com-work:company/internal-api.git

Advanced Pattern 2: Bastion Jump Hosts with ProxyJump

In cloud environments (AWS, GCP), production database and API servers reside in Private Subnets with no public IPs. To access them, you must route through a public Bastion / Jump Host.

Without ProxyJump, you had to manually SSH into the bastion, forward keys, and run a second SSH session. With ProxyJump, it happens transparently:

# 1. The Public Bastion Host
Host bastion
HostName 198.51.100.10
User ec2-user
IdentityFile ~/.ssh/bastion_key.pem

# 2. The Internal Private Server
Host internal-db
HostName 10.0.2.45
User ubuntu
IdentityFile ~/.ssh/db_cluster_key.pem
ProxyJump bastion

Now, simply run:

ssh internal-db

OpenSSH will connect to the bastion, establish an encrypted tunnel over the AWS private VPC, and deliver you straight to the internal prompt!

Advanced Pattern 3: Prevent Broken & Frozen Connections (KeepAlive)

Have you ever switched windows for 5 minutes, only to find your SSH terminal completely frozen because a router or NAT firewall silently dropped the idle TCP socket?

Add a global wildcard block at the bottom of your ~/.ssh/config:

# Global Settings for ALL Hosts
Host *
ServerAliveInterval 60
ServerAliveCountMax 3
TCPKeepAlive yes
Compression yes
AddKeysToAgent yes
  • ServerAliveInterval 60: Sends a cryptographic ping every 60 seconds to keep firewalls and cloud NAT gateways active.
  • ServerAliveCountMax 3: If the server fails to reply to 3 consecutive pings, SSH terminates the socket cleanly instead of locking your cursor.
  • AddKeysToAgent yes: Automatically adds keys to ssh-agent when used so you only enter passphrases once.
