Nginx Security Headers: The Ultimate Production Checklist (2026 Guide)

Web Security By SSH Desktop Engineering Team • Updated November 2026 • 10 min read

Deploying an SSL certificate via Let's Encrypt encrypts data in transit, but HTTPS alone does not protect your visitors from Cross-Site Scripting (XSS), clickjacking, MIME-type confusion attacks, or man-in-the-middle SSL stripping. Securing your web application requires sending standardized HTTP Security Headers with every response.

Executive Summary

By creating a reusable security headers snippet in /etc/nginx/snippets/security-headers.conf, you can harden every website on your server to earn an A+ Grade on SecurityHeaders.com and Qualys SSL Labs. In this guide, we review HSTS, CSP, X-Frame-Options, and visual SSL inspection via SSH Desktop SSL Manager.

1. The Complete Production Security Headers Snippet

Create a centralized snippet file at /etc/nginx/snippets/security-headers.conf: 

# 1. HTTP Strict Transport Security (HSTS): Enforce HTTPS for 1 year including subdomains
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains; preload" always;

# 2. Prevent Clickjacking: Disallow embedding this site inside iframes
add_header X-Frame-Options "DENY" always;

# 3. Prevent MIME Sniffing: Force browser to honor declared Content-Type
add_header X-Content-Type-Options "nosniff" always;

# 4. Control Referrer Information: Send full URL on same-origin, domain-only on cross-origin
add_header Referrer-Policy "strict-origin-when-cross-origin" always;

# 5. Restrict Browser Features: Disable access to microphone, camera, and geolocation
add_header Permissions-Policy "camera=(), microphone=(), geolocation=(), payment=()" always;

# 6. Content Security Policy (CSP): Mitigate XSS and unauthorized script injection
add_header Content-Security-Policy "default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com; img-src 'self' data: https:; connect-src 'self';" always;

# 7. Hide Nginx Version from headers and error pages:
server_tokens off;

2. Including the Snippet in Your Virtual Hosts

Include your snippet inside the server block of your website configuration (e.g. /etc/nginx/sites-available/default): 

server {
    listen 443 ssl http2;
    server_name example.com;

    ssl_certificate /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;

    # Include centralized security headers:
    include /etc/nginx/snippets/security-headers.conf;

    location / {
        try_files $uri $uri/ =404;
    }
}

Watch Out for add_header Scope Inheritance

In Nginx, if a location block defines its own add_header directive, it will NOT inherit headers from the parent server block! Always place include /etc/nginx/snippets/security-headers.conf; inside location blocks if custom headers are defined there.

3. Verifying Your Security Headers

# Test Nginx syntax and reload:
sudo nginx -t && sudo systemctl reload nginx

# Inspect response headers with curl:
curl -I https://example.com

4. Frequently Asked Questions

Why does 'add_header' in a location block overwrite parent server headers in Nginx?

In Nginx architecture, if a location block declares ANY add_header directive, it does NOT inherit headers defined in the enclosing server or http block; it completely clears and replaces them. To prevent this, either put all common security headers in a snippet file and include it inside every location block, or only define add_header at the location level.

What is the purpose of the 'always' flag in add_header?

By default, Nginx only sends custom headers for successful 2xx and 3xx HTTP response codes. Adding the always parameter ensures the security headers are attached to error pages (such as 404 Not Found, 403 Forbidden, and 500 Server Error) as well.

What does server_tokens off do in Nginx?

Setting server_tokens off; instructs Nginx to suppress version numbers in default error pages and in the Server: nginx HTTP response header, preventing attackers from fingerprinting outdated software with known CVE vulnerabilities.
