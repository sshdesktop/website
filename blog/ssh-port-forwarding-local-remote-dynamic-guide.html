The Complete Visual Guide to SSH Port Forwarding: Local, Remote & Dynamic (SOCKS5)

Published: November 2026 • 10 min read • By SSH Desktop Engineering Team

SSH port forwarding (often called SSH tunneling) is one of the most powerful networking features built into the OpenSSH protocol. It creates an encrypted tunnel between your local computer and a remote server, allowing arbitrary TCP network traffic to traverse firewalls, NAT routers, and public networks with military-grade 256-bit AES encryption.

Whether you want to query a private remote PostgreSQL database, share a local web development server with a client, or bypass a restrictive public Wi-Fi network, mastering SSH port forwarding is an indispensable skill.

The 3 Types of SSH Port Forwarding

Type Flag Where it listens Common Use Case
Local Forwarding -L Local Client PC Connect to remote internal DBs (Postgres, MySQL, Redis)
Remote Forwarding -R Remote Server Expose local dev server (port 3000) to the internet
Dynamic Forwarding -D Local Client PC Encrypted SOCKS5 proxy for all web browser traffic

1. Local Port Forwarding (-L)

Scenario: You have a PostgreSQL database running on a remote Ubuntu cloud server listening on 127.0.0.1:5432. For security, you keep port 5432 completely closed on the firewall. You want to connect to it using pgAdmin, DBeaver, or SSH Desktop Database Studio on your laptop.

[Your Laptop] : Port 5433 → (Encrypted SSH Port 22 Tunnel) → [Ubuntu Server] → Postgres (127.0.0.1:5432)

Syntax & Example

ssh -L [local_port]:[target_host]:[target_port] [user]@[server_ip] -N

To forward local port 5433 to the remote database:

ssh -L 5433:127.0.0.1:5432 ubuntu@198.51.100.25 -N

Note: The -N flag instructs SSH not to execute any remote command or open a shell, which is ideal when you only need the tunnel.

Now open your database client and connect to:
Host: 127.0.0.1 | Port: 5433

2. Remote (Reverse) Port Forwarding (-R)

Scenario: You are developing a Node.js or Python API locally on your laptop on localhost:3000. A teammate or a third-party webhook service (like Stripe or GitHub) needs to reach your local app.

[Public Internet] → [Remote VPS] : Port 8080 → (Encrypted Reverse SSH Tunnel) → [Your Laptop] : Port 3000

Syntax & Example

ssh -R [remote_port]:[target_host]:[target_port] [user]@[server_ip] -N

To forward requests from the remote server's port 8080 to your local port 3000:

ssh -R 8080:127.0.0.1:3000 ubuntu@198.51.100.25 -N
Important Server Config: To allow remote external users to connect to that port, ensure GatewayPorts yes is enabled in /etc/ssh/sshd_config on the remote server.

3. Dynamic Port Forwarding (-D) & SOCKS5 Proxy

Scenario: You are connected to an untrusted public airport or coffee shop Wi-Fi network. You want all your web browser traffic routed securely through your trusted Linux cloud server, as if you were running a private VPN.

Syntax & Example

ssh -D 1080 ubuntu@198.51.100.25 -N

This opens a local SOCKS5 proxy on port 1080. In Google Chrome, Firefox, or macOS/Windows network settings, configure your SOCKS proxy to 127.0.0.1:1080. All your web traffic will now travel through your encrypted SSH tunnel!
