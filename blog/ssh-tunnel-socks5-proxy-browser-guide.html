How to Use SSH as a SOCKS5 Proxy: Secure Your Browser & Traffic (2026 Guide)

Published: November 2026 • 11 min read • By SSH Desktop Engineering Team

Whether working from a public coffee shop Wi-Fi network, traveling internationally, or needing to bypass strict corporate firewalls, paying for commercial third-party VPN subscriptions can be costly and concerning from a privacy perspective.

If you already have access to any remote Linux server (a $4/mo DigitalOcean Droplet, AWS EC2 instance, or home Raspberry Pi), you already own a private, zero-log encrypted proxy.

Using SSH's built-in Dynamic Port Forwarding (-D), you can turn your SSH client into a full-fledged SOCKS5 proxy that routes web browsing, API calls, and application traffic securely through your remote server.

How SSH Dynamic Forwarding (SOCKS5) Works

Standard local port forwarding (ssh -L) requires knowing the destination IP and port in advance (e.g. forward port 5432 to a database).

With Dynamic Port Forwarding, your SSH client acts as an intelligent SOCKS proxy:

  1. Your SSH client opens a local listening port on your laptop (e.g. localhost:1080).
  2. Your browser (Chrome, Firefox) connects to 127.0.0.1:1080 and requests any website (e.g. https://example.com).
  3. The SSH client encrypts the web request and sends it through the existing SSH tunnel over port 22.
  4. The remote server decrypts the request, fetches the website from the public internet, and sends the response back through the encrypted tunnel.

To anyone monitoring your local network (hackers on public Wi-Fi, hotel routers, ISPs), they see nothing except an impenetrable stream of encrypted SSH traffic.

Step 1: Launch the SOCKS5 Proxy from Your Terminal

Open your terminal (PowerShell, macOS, or Linux) and run:

ssh -N -D 1080 user@your-server-ip

Flag Breakdown:

  • -D 1080: Starts a dynamic port forwarder listening on local port 1080.
  • -N: Tells OpenSSH not to execute a remote shell. It only handles traffic forwarding, saving memory and bandwidth.
  • -C (Optional): Enables gzip compression on all data packets for faster web browsing on slow connections.
# Optimized command with compression & keepalive:
ssh -N -C -D 1080 -o ServerAliveInterval=60 user@your-server-ip

Step 2: Configure Firefox (Zero Extension Needed)

Firefox is the best browser for SOCKS5 proxies because it supports standalone proxy settings and remote DNS routing without altering your whole operating system:

  1. Open Firefox Settings → Scroll to Network Settings → Click Settings...
  2. Select Manual proxy configuration.
  3. In the SOCKS Host field, enter 127.0.0.1 and Port 1080.
  4. Select SOCKS v5.
  5. Crucial Security Step: Check the box Proxy DNS when using SOCKS v5. (This ensures your DNS queries cannot be intercepted by your local network provider!).
  6. Click OK.

Step 3: Configure Google Chrome / Microsoft Edge

Chrome and Edge use the system proxy settings by default. To launch a private Chrome window routed exclusively through your SOCKS5 proxy without altering system-wide settings, launch it from the command line:

On Windows 11 (PowerShell):

Start-Process "chrome.exe" --proxy-server="socks5://127.0.0.1:1080"

On macOS:

/Applications/Google Chrome.app/Contents/MacOS/Google Chrome --proxy-server="socks5://127.0.0.1:1080" &

Alternatively, install free browser extensions like Proxy SwitchyOmega or FoxyProxy to toggle between Direct and SOCKS5 proxy with a single toolbar click.

Step 4: Route CLI Tools & Scripts Through SOCKS5 (curl & git)

You can route developer tools through your SSH SOCKS5 proxy with simple command-line arguments:

1. Test with curl:

# Without proxy (shows your real home IP):
curl ifconfig.me

# Through SOCKS5 proxy (shows your remote server's IP):
curl --socks5-hostname 127.0.0.1:1080 ifconfig.me

2. Route Git over SOCKS5:

git config --global http.proxy 'socks5://127.0.0.1:1080'
