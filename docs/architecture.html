Getting Started & Core

🏗️ Architecture & Security Model

Architectural blueprint and security model of SSH Desktop. Discover how our asynchronous Rust Tauri 2.0 backend and React 19 frontend multiplex standard OpenSSH channels without requiring remote agents.

Figure: Real-time visual interface of Architecture & Security Model in SSH Desktop.

What is this Application & Why Do You Need It?

SSH Desktop is engineered with a strict two-tier architecture: a compiled Rust backend (Tauri 2.0) and a hardware-accelerated React 19 frontend. Unlike Electron-based tools that bundle entire Chromium browsers and Node.js runtimes (consuming 300MB+ RAM), Tauri leverages native OS webviews (WebKit on macOS, WebView2 on Windows, WebKitGTK on Linux), maintaining a total client binary size under 15MB and less than 45MB idle memory.

Traditional server management web panels (cPanel, Webmin, Cockpit, Portainer) run as persistent daemons on the remote server itself. These daemons consume remote server memory 24/7, run with root privileges, expose open HTTP ports vulnerable to remote code execution (RCE), and require constant patching. SSH Desktop flips the model: all rendering and parsing occur on your local machine, keeping your remote servers untouched.

Legacy Tools Replaced: Heavy daemon agents (Portainer Agent, Webmin daemon, Cockpit-ws)

🖥️ Interface Overview & Visual Controls

The Architecture & Diagnostics Inspector displays the live status of the local Rust-Tauri runtime and multiplexed OpenSSH channels. The left panel shows active virtual channels (PTY sessions, SFTP streams, Direct-TCPIP tunnels, and background telemetry readers). The center metrics monitor displays local client memory footprint (typically under 45 MB), CPU usage, and network throughput across the multiplexed SSH connection.

Key Capabilities & Features

  • Rust Tauri 2.0 Engine: Fast, memory-safe backend compiled to native machine code with zero garbage collection pauses.
  • React 19 Concurrent UI: Sub-millisecond state updates, concurrent transitions, and hardware-accelerated CSS transforms.
  • Zero-Copy Stream Parsers: Raw output streams from Linux utilities parsed in Rust memory using nom and regex before handing off to React.
  • Hardware-Enforced Security: Passwords and private key passphrases stored in OS Keychain, Windows DPAPI, or Linux Secret Service.
  • Zero Cloud Telemetry: Zero tracking scripts, zero Google Analytics, zero phone-home servers. Your infrastructure data never leaves your device.

📋 Prerequisites & Remote Host Requirements

  • Standard OpenSSH server (sshd) running on the remote host.
  • AllowTcpForwarding enabled in remote sshd_config (enabled by default in OpenSSH).
  • For developers building from source: Rust 1.75+, Node.js 20+, and Tauri CLI.

Step-by-Step How-To Tutorial

1. Asynchronous SSH Multiplexing Pipeline

When connected, SSH Desktop establishes a single authenticated TCP connection. Over this connection, the Rust backend opens multiple logical virtual channels:
  • Channel 1 (Interactive PTY): Full pseudo-terminal session running login shell (bash/zsh) for the Terminal app.
  • Channel 2 (SFTP Binary Subsystem): Dedicated binary channel for SFTP file navigation and file streaming.
  • Channel 3 (Telemetry Stream): Lightweight reader channel querying /proc performance counters.
  • Channel 4+ (Direct-TCPIP): Dynamic forwarding channels for Docker UNIX socket (/var/run/docker.sock) and database ports.

2. Client-Side Parsing Engine

Instead of running an agent on the server to convert metrics into JSON, SSH Desktop executes standard POSIX commands (e.g. systemctl list-units, docker ps, ss -tulpn) and streams raw stdout directly to your local PC. The Rust backend parses these raw streams with sub-millisecond efficiency.

3. Complete Privacy & Zero Cloud Telemetry

SSH Desktop contains zero telemetry trackers. All server connection configurations, SSH key references, and command histories reside strictly in your local operating system directory (~/.config/sshdesktop/ on macOS/Linux or %APPDATA%\sshdesktop\ on Windows).

💡 Pro-Tips & Best Practices

  • Zero Server Footprint: SSH Desktop never installs background daemons, cron jobs, or monitoring agents on your servers. Closing the app closes all multiplexed SSH sessions cleanly.
  • Single Port Simplicity: All 25 applications communicate exclusively through standard OpenSSH port 22. No additional firewall ports need to be opened on your server.
  • Native OS Keychain Security: Private keys and passphrases are stored in macOS Keychain, Windows DPAPI, or Linux Secret Service — never in unencrypted configuration files.
  • True Zero-Cloud Privacy: No analytics, telemetry, or user data is ever sent to external cloud servers. The client communicates solely with your configured hosts.

Under the Hood: Linux Commands & Architecture

Backend IPC uses Tauri's binary message serialization bridge. Commands are executed over libssh2/russh channels, ensuring maximum throughput and minimal latency.

❓ Troubleshooting & Frequently Asked Questions

High latency or laggy UI over slow connections

Enable "Low Bandwidth Mode" in Preferences to reduce telemetry polling frequency from 1000ms to 5000ms and compress SFTP directory listings.

AllowTcpForwarding disabled on server

If database tunnels or Docker socket forwarders fail to connect, check /etc/ssh/sshd_config on the server and ensure AllowTcpForwarding yes is enabled, then reload sshd.
