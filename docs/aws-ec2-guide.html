☁️ AWS EC2 SSH Connection Guide

Step-by-step guide to connecting and managing AWS EC2 instances with SSH Desktop. Learn how to use .pem keys, configure VPC Security Groups, and connect through Bastion jump hosts.

Figure: Real-time visual interface of AWS EC2 SSH Connection Guide in SSH Desktop.

What is this Application & Why Do You Need It?

The AWS EC2 Guide provides an end-to-end tutorial on integrating SSH Desktop with Amazon Web Services (AWS) Elastic Compute Cloud (EC2). It covers creating host profiles with `.pem` keypairs, configuring Amazon VPC Security Groups for secure port 22 access, connecting to private VPC instances through an EC2 Bastion host, and managing fleets of cloud servers.

Managing AWS EC2 instances via the AWS Management Console requires constant browser logins, slow EC2 Instance Connect web terminals, and manual session tracking. SSH Desktop lets you connect directly to EC2 instances from your desktop with native performance, multi-tab terminal split panes, and visual Docker/database management.

Legacy Tools Replaced: AWS EC2 Instance Connect browser lag, PuTTYgen .pem to .ppk conversion

🖥️ Interface Overview & Visual Controls

The AWS Cloud Workspace organizes EC2 instances with visual region badges (us-east-1, eu-central-1, ap-southeast-1). Quick action cards allow launching interactive bash shells, inspecting Docker containers, and managing systemd services agentlessly.

Key Capabilities & Features

  • Direct .pem Key Support: Connect directly using standard AWS `.pem` private keys without running PuTTYgen conversions.
  • Amazon Linux & Ubuntu Optimization: Native compatibility with default EC2 usernames (`ec2-user`, `ubuntu`, `admin`, `centos`).
  • Private VPC Bastion Routing: Seamlessly jump into private EC2 database instances that have no public IP addresses.
  • Cloud Fleet Tagging: Group your EC2 servers by AWS region (e.g. `us-east-1`, `eu-west-1`) and environment tags.

📋 Prerequisites & Remote Host Requirements

  • Active AWS account with running EC2 instance (Ubuntu, Amazon Linux 2023, Debian, or RHEL).
  • AWS Key Pair private key file (`.pem`).
  • EC2 Security Group configured with inbound rule allowing SSH (port 22) from your IP address.
  • Public IPv4 address or Elastic IP attached to the EC2 instance.

Step-by-Step How-To Tutorial

1. Locating EC2 Public IP & Key Pair

In the AWS EC2 Console, select your instance and locate its Public IPv4 address (or Elastic IP). Ensure you have downloaded the .pem keypair created during instance launch.

2. Configuring AWS VPC Security Group

Select your EC2 instance's Security Group → Edit inbound rules. Add an Inbound Rule:
  • Type: SSH
  • Port: 22
  • Source: My IP (recommended for security) or your office CIDR range.
  • Click Save rules.

3. Adding the EC2 Profile in SSH Desktop

Click + New Connection in SSH Desktop:
  • Host / IP: Your EC2 Public IPv4 address
  • Username: ubuntu (for Ubuntu AMIs), ec2-user (for Amazon Linux / RHEL), or admin (for Debian)
  • Auth Mode: Choose Private Key and browse to your downloaded .pem file.
  • Click Connect.

4. Routing to Private EC2 Instances via Bastion

For database instances located in private subnets, toggle Bastion / Jump Host in the connection settings. Set the public Bastion EC2 instance as the jump box. SSH Desktop opens an encrypted tunnel through the bastion into your private node.

💡 Pro-Tips & Best Practices

  • Use Elastic IPs: Standard EC2 public IPv4 addresses change whenever an instance is stopped and restarted. Attach an Elastic IP to keep a permanent static IP address.
  • Protect .pem Key Permissions: Ensure your .pem file is protected locally: chmod 400 ~/.ssh/my-aws-key.pem.
  • Tag by Environment: Use tags like aws-prod and aws-staging to filter instances instantly in Spotlight (Cmd+K).

Under the Hood: Linux Commands & Architecture

Authenticates using RSA 2048/4096 or Ed25519 AWS keypairs and multiplexes channels over AWS VPC network interfaces.

Primary Commands / Virtual Files Executed Over SSH:
chmod 400 key.pem, ssh -i key.pem ec2-user@ec2-ip, VPC Security Group 22

❓ Troubleshooting & Frequently Asked Questions

Connection timed out to EC2 instance

A timeout almost always indicates an AWS Security Group misconfiguration. Verify that your Security Group's Inbound Rules allow port 22 from your current public IP address.

Please login as the user "ubuntu" rather than the user "root"

AWS AMIs disable direct root login by default. Connect using the AMI's default user (e.g. ubuntu or ec2-user) and use sudo for elevated commands.
