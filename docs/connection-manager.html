Getting Started & Core

🔑 Connection Manager & SSH Keys

Master the SSH Connection Manager. Learn how to add host profiles, import ~/.ssh/config, configure Bastion jump hosts, and manage Ed25519 cryptographic keys.

Figure: Real-time visual interface of Connection Manager & SSH Keys in SSH Desktop.

What is this Application & Why Do You Need It?

The Connection Manager is the central directory for all your remote servers. It lets you organize servers with color-coded tags, manage credentials safely in OS hardware keychains, configure transparent ProxyJump routes through bastion jump hosts, and launch visual desktop sessions with a single click.

Sysadmins and DevOps engineers frequently manage dozens of servers across AWS, Hetzner, DigitalOcean, and on-premise hardware. Memorizing IP addresses, port numbers, usernames, and key file paths in shell aliases leads to configuration drift and connection errors. The Connection Manager brings order with instant search, auto-discovery, and safe key management.

Legacy Tools Replaced: Manual ssh CLI configs, complex ~/.ssh/config files, PuTTY saved sessions

🖥️ Interface Overview & Visual Controls

The Connection Manager Window displays a left sidebar with tag groups (All Servers, Production, Staging, Favorites, Jump Hosts). The main panel presents server profile cards with status indicators (Green = Reachable, Red = Unreachable), IP addresses, assigned usernames, and quick action buttons (Connect, Edit, Duplicate, Delete). The top search bar filters across hundreds of servers instantly by name, tag, or IP.

Key Capabilities & Features

  • Smart ~/.ssh/config Import: Detects existing OpenSSH config files and imports hosts with complete HostName, User, Port, and IdentityFile mappings.
  • Color-Coded Server Tags: Group servers by environment (Production, Staging, QA) or architecture (Web, Database, Cache, Storage).
  • Transparent Bastion ProxyJump: Connect to private subnet servers with zero public IP addresses through an SSH jump host in one click.
  • Hardware Keychain Storage: Sensitive private key passphrases are stored in macOS Keychain, Windows DPAPI, or Linux Secret Service.

📋 Prerequisites & Remote Host Requirements

  • Remote server IP address or domain name.
  • SSH port (default 22 or custom port).
  • Authentication credentials: SSH Private Key (Ed25519, ECDSA, RSA) or password.
  • For bastion setups: Hostname and credentials for the jump server.

Step-by-Step How-To Tutorial

1. Adding a New Server Connection Profile

Click + New Connection in the top toolbar. Enter a friendly nickname (e.g. Production Web VPS), the target hostname or IPv4/IPv6 address, and the SSH port (default 22).

2. Configuring Cryptographic Authentication

Choose your authentication mode:
  • SSH Private Key (Recommended): Browse to your local ~/.ssh/id_ed25519 or ~/.ssh/id_rsa file. If your key is protected by a passphrase, enter it once to store it securely in your OS keychain.
  • Password: Enter your remote user password. Credentials are encrypted locally using AES-256 before storage.

3. Configuring Bastion / ProxyJump Routing

For private VPC servers located behind a firewall gateway, expand Advanced SSH Settings and toggle Bastion / Jump Host. Select an existing bastion profile or enter the jump server IP and credentials. SSH Desktop transparently tunnels the connection through the bastion.

4. Connecting and Launching the Desktop Session

Click Connect. The Rust backend negotiates cryptographic key exchange, validates host fingerprints against known_hosts, and launches the full visual desktop shell in under 200 milliseconds.

💡 Pro-Tips & Best Practices

  • Always Prefer Ed25519 Keys: Generate Ed25519 keys with ssh-keygen -t ed25519 for maximum security and faster connection handshakes.
  • Organize by Tags: Use tags like aws, prod, database to quickly filter servers in Spotlight (Cmd+K).
  • Duplicate Profiles for Testing: Right-click any existing profile and select Duplicate to quickly clone settings for a staging replica.

Under the Hood: Linux Commands & Architecture

Validates SSH cryptographic handshakes and parses ~/.ssh/known_hosts fingerprints to prevent Man-in-the-Middle (MITM) attacks.

Primary Commands / Virtual Files Executed Over SSH:
ssh-keygen -t ed25519, ssh-copy-id, ProxyJump, ~/.ssh/known_hosts

❓ Troubleshooting & Frequently Asked Questions

Permission denied (publickey) on connect

Verify that your public key has been appended to ~/.ssh/authorized_keys on the remote server and that file permissions are set to 600.

Host key verification failed warning

This occurs when a server was reinstalled and has a new host key. Click "Update Host Fingerprint" in the security alert modal to accept the new fingerprint safely.
