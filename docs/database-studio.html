🗄️ Multi-Engine Database Studio

Visual database studio with automatic SSH port forwarding. Run queries, inspect schemas, edit table rows, and export data without exposing DB ports.

Figure: Real-time visual interface of Multi-Engine Database Studio in SSH Desktop.

What is this Application & Why Do You Need It?

The Multi-Engine Database Studio is a native database management environment supporting PostgreSQL, MySQL, MariaDB, Redis, SQLite, and MongoDB. It automatically establishes encrypted SSH port forward tunnels to your remote database instances so your database ports (5432, 3306, 6379) remain closed to the public internet.

Exposing database ports to the internet creates severe security vulnerabilities, while configuring external GUI clients like DBeaver or pgAdmin with SSH bastions is tedious and slow. SSH Desktop provides a zero-setup, built-in database studio that works automatically through your existing SSH connection.

Legacy Tools Replaced: DBeaver, pgAdmin, phpMyAdmin, TablePlus, Redis Insight

🖥️ Interface Overview & Visual Controls

The Database Studio provides a complete visual SQL query workspace and schema browser with automatic, transparent SSH port forwarding. The left sidebar displays connected database engines (PostgreSQL, MySQL, MariaDB, SQLite, Redis, MongoDB), database lists, and table trees. The center area features a Monaco SQL query editor with auto-completion, keyword syntax highlighting, and execution timers. The bottom panel displays an interactive data grid with sorting, pagination, and inline cell editing.

Key Capabilities & Features

  • Multi-Engine Support: Connect to PostgreSQL, MySQL, MariaDB, Redis, SQLite, and MongoDB.
  • Automatic Port Forwarding: Tunnels database connections over SSH; no need to open firewall ports or expose 3306/5432.
  • Monaco SQL Editor: Autocompletion for table and column names, syntax highlighting, query history, and execution timers.
  • Editable Data Grid: Browse table rows, apply filters and sorting, edit cell values inline, and commit changes with one click.
  • Export & Backup: Export query results and table data to CSV, JSON, and SQL dump formats.

📋 Prerequisites & Remote Host Requirements

  • Remote database instance running on localhost or internal VPC network (PostgreSQL, MySQL, MariaDB, Redis, SQLite, MongoDB).
  • Database user credentials (username, password, database name).

Step-by-Step How-To Tutorial

1. Connecting to a Remote Database

Click the Database icon in the Dock. Select your database engine (e.g. PostgreSQL or MySQL):
  • Host: Enter 127.0.0.1 (or internal VPC IP).
  • Port: Default 5432 (Postgres) or 3306 (MySQL).
  • Database Name: Name of the database to open.
  • Username & Password: Database user credentials.
  • Click Connect. SSH Desktop opens an encrypted SSH tunnel in the background and connects immediately.

2. Running SQL Queries

The upper panel provides a full SQL query editor with syntax highlighting and autocomplete. Type your query (e.g. SELECT * FROM users WHERE active = true ORDER BY created_at DESC;) and click Execute (Cmd+Enter). Results appear instantly in the lower data table with execution time in milliseconds.

3. Editing Table Rows & Modifying Data

Browse tables in the left sidebar. Clicking a table loads its schema and data rows. Double-click any cell to modify its value inline, or click + Add Row to insert records. Click Commit Changes to apply updates with SQL transaction safety.

4. Redis Key-Value & Memory Inspector

When connecting to Redis, the studio switches to a Key-Value browser: inspect string, hash, set, and list keys, view TTLs, execute raw CLI commands, and monitor real-time memory usage.

💡 Pro-Tips & Best Practices

  • Zero Port Exposure: Connect to private database ports (e.g. 5432, 3306, 6379) listening only on 127.0.0.1 over encrypted SSH tunnels without exposing ports publicly.
  • Inline Cell Editing: Double-click any cell in the table viewer to edit values directly and click "Apply Changes" to generate and run safe UPDATE queries.
  • Export Data: Export query results or complete tables to CSV, JSON, or SQL INSERT dump formats with one click.
  • Redis Key Browser: Inspect Redis key hierarchies, view string/hash/list values, and monitor key TTLs visually.

Under the Hood: Linux Commands & Architecture

SSH Desktop opens an internal Direct-TCPIP channel over your SSH session, binding a dynamic local port to the remote database port. Client protocol drivers speak the wire protocol (PostgreSQL frontend/backend protocol, MySQL packet stream, Redis RESP) directly over this secure channel.

Primary Commands / Virtual Files Executed Over SSH:
Local port forwarding (ssh -L), PostgreSQL wire, MySQL protocol, Redis RESP

❓ Troubleshooting & Frequently Asked Questions

Database connection failed: Access denied

Verify database user credentials and host permissions. Ensure the database user is permitted to connect from localhost or 127.0.0.1.

Tunnel connection dropped on long-running queries

Enable "Keep-Alive Watchdog" in Database Connection settings to send heartbeat packets and prevent firewall NAT timeouts on inactive connections.
