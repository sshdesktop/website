💾 Disk, LVM & S.M.A.R.T. Manager

Inspect partition maps, filesystem mount points, LVM volume groups, and drive health metrics (temperature, reallocated sectors, wear level).

Figure: Real-time visual interface of Disk, LVM & S.M.A.R.T. Manager in SSH Desktop.

What is this Application & Why Do You Need It?

The Disk, LVM & S.M.A.R.T. Manager gives you complete visibility into your server's storage hierarchy: physical block devices, partitions, filesystem mount points, LVM (Logical Volume Manager) volumes, inode consumption, and hardware drive health.

Running out of disk space or having an SSD fail unexpectedly can cause catastrophic database corruption and downtime. Commands like fdisk -l, lsblk, and smartctl produce complex text outputs. SSH Desktop provides visual capacity bars, health warnings, and LVM graphs.

Legacy Tools Replaced: df -h, lsblk, fdisk, smartctl CLI, gparted

🖥️ Interface Overview & Visual Controls

The Disk & S.M.A.R.T. Manager provides comprehensive storage diagnostics and partition management. The Overview Tab visualizes disk usage across mount points with color-coded capacity bars. The Partitions Tab displays drive partition tables (GPT/MBR), filesystem types (ext4, xfs, btrfs), and mount options. The S.M.A.R.T. Tab shows drive hardware health metrics (drive temperature, power-on hours, reallocated sector counts, wear level indicators). The Space Hogs Tab scans remote directories to identify oversized files and folders quickly.

Key Capabilities & Features

  • 6 Storage Views: Overview, Partitions (lsblk), S.M.A.R.T. Health, Swap & /tmp Cleaner, Fstab Editor, and Space Hogs (Large File Finder).
  • Space Hogs Visualizer: Fast ncdu/du visual tree map highlighting the largest space-consuming folders and log dumps.
  • Inode Usage Inspector: Detect situations where disk space appears free but files cannot be created due to exhausted inodes.
  • S.M.A.R.T. Drive Health: Monitor drive temperature, reallocated sector counts, power-on hours, and SSD wear percentage.
  • Swap & /tmp Manager: Inspect swap memory usage, swappiness setting, and safely purge `/tmp` and `/var/tmp`.

📋 Prerequisites & Remote Host Requirements

  • Linux server with block devices (NVMe, SATA SSD, HDD, or cloud virtual volumes).
  • smartmontools package (smartctl) installed for S.M.A.R.T. hardware telemetry.

Step-by-Step How-To Tutorial

1. Inspecting Partition Capacity & Inodes

Open the Disk Manager. The main dashboard displays cards for each mount point (e.g. /, /home, /var). Warning badges appear when capacity exceeds 85% or when inodes are running low.

2. Checking S.M.A.R.T. Drive Health

Click the Drive Health (S.M.A.R.T.) tab. Select a physical drive (e.g. /dev/nvme0n1 or /dev/sda). View drive model, serial number, health status (PASSED), temperature, and raw error counters.

3. Finding Large Files with Space Hogs

Switch to the Space Hogs tab to scan any directory. The visual tree map highlights the largest directories and files consuming disk space, allowing you to delete orphaned backup archives with one click.

💡 Pro-Tips & Best Practices

  • Locate Large Files Instantly: Switch to the "Space Hogs" tab and click "Scan Directory" to identify gigabyte-sized log archives, docker cache, or forgotten backups without running slow du -sh commands.
  • Monitor Disk Temperature: Regularly check the S.M.A.R.T. tab for server drive temperatures above 50°C to prevent premature SSD/HDD hardware failure.
  • Inspect Inode Usage: If your server reports "No space left on device" despite having free gigabytes, check the Inode Capacity meter to detect millions of tiny session files.
  • Safe Mount Management: View /etc/fstab entries visually and verify UUIDs before rebooting after adding new storage volumes.

Under the Hood: Linux Commands & Architecture

Executes lsblk -J -o NAME,SIZE,TYPE,MOUNTPOINT,FSTYPE, df -hT, df -i, and smartctl -a -j /dev/<device>. JSON outputs are parsed and bound to responsive data visualizations.

Primary Commands / Virtual Files Executed Over SSH:
lsblk -J, df -hT, smartctl -a, lvs, vgs, pvs

❓ Troubleshooting & Frequently Asked Questions

S.M.A.R.T. data unavailable for virtual disk

Cloud VPS providers (AWS EC2, DigitalOcean, Hetzner, Linode) use virtualized block storage (EBS, Ceph) that does not expose physical S.M.A.R.T. registers to guest operating systems.

Filesystem is mounted as Read-Only (ro)

This typically indicates filesystem corruption detected by the Linux kernel. Review kernel messages in Log Analysis (dmesg | grep -i error) and schedule an fsck.
