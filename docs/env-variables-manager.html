🔑 Environment Variables & Secrets

Manage application .env files and system environment variables safely. Features masked password fields, syntax validation, and instant service reloads.

Figure: Real-time visual interface of Environment Variables & Secrets in SSH Desktop.

What is this Application & Why Do You Need It?

The Environment Variables & Secrets Manager is a dedicated visual tool for creating, editing, and auditing `.env` files and system-wide environment variables. Safely configure database connection strings, API secrets, OAuth tokens, and runtime flags with masked input fields and atomic writes.

Developers frequently leak API tokens by echoing them into terminal bash history or editing `.env` files with plain text editors on screen during screen shares. Furthermore, formatting errors (unquoted spaces, missing equals signs) break applications at boot. Environment Manager secures secret handling with masking and automated syntax validation.

Legacy Tools Replaced: Scattered .env files, manual export commands, leaking secrets in bash history

🖥️ Interface Overview & Visual Controls

The Environment Variables & Secrets Manager organizes environment configurations safely. The left sidebar lists discovered application .env files across your project directories as well as system-wide environment files (/etc/environment). The main table displays Key-Value pairs with inline Mask/Reveal Toggles (••••••••) for passwords and API tokens. The top toolbar provides Add Variable, Validate Syntax, Import/Export, and Save Changes.

Key Capabilities & Features

  • Masked Secret Fields: Passwords, private keys, and tokens are rendered with security bullets; click the eye icon to reveal.
  • MultiPath Variable Editor: Visual drag-and-drop reordering for colon-delimited variables like PATH and LD_LIBRARY_PATH.
  • System vs User Scopes: Toggle between project `.env` files, user shell profiles (~/.bashrc), and /etc/environment.
  • Automated Syntax Checking: Validates quotes, escaped characters, and key formatting before saving to disk.
  • File Permission Hardening: Automatically enforces chmod 600 on saved `.env` files so only the owner can read secrets.

📋 Prerequisites & Remote Host Requirements

  • Target application directory with read/write access for `.env` files.
  • Sudo privileges if modifying system environment files like /etc/environment.

Step-by-Step How-To Tutorial

1. Opening a .env File

Launch the Environment Manager. Select an existing .env file from the recent projects dropdown or click Open .env Path... to browse your remote file tree.

2. Adding and Editing Secrets

Click + Add Variable. Enter the key name (e.g. STRIPE_SECRET_KEY) and paste the value. Values identified as tokens or passwords are automatically masked.

3. Testing and Saving Safely

Click Save & Apply. SSH Desktop writes to a temporary file, verifies syntax, enforces strict file permissions (chmod 600 so only the application owner can read secrets), and commits the update.

💡 Pro-Tips & Best Practices

  • Masked Secrets Protection: Sensitive variables (e.g. DB_PASSWORD, AWS_SECRET_KEY, STRIPE_TOKEN) are masked automatically to prevent shoulder-surfing and accidental stream leaks.
  • Visual PATH Editor: Edit the system or user $PATH variable with a tokenized drag-and-drop list instead of dealing with error-prone colon-separated strings.
  • Syntax Validation on Save: SSH Desktop validates quotes, escaped characters, and newline syntax before writing changes to prevent application startup crashes.
  • Keep Local Backups: Use the "Backup .env" button before making major changes to keep a dated snapshot in case an environment variable change needs to be rolled back.

Under the Hood: Linux Commands & Architecture

Parses dotenv format supporting standard POSIX expansion and `#` comments. Saves via atomic rename to ensure running applications never read a half-written file.

Primary Commands / Virtual Files Executed Over SSH:
dotenv parser, /etc/environment, systemctl show-environment

❓ Troubleshooting & Frequently Asked Questions

Application does not recognize updated environment variables

Running processes do not automatically reload environment changes. Restart your application process, Docker container, or systemd service after editing environment files.
