Getting Started & Core

🚀 Getting Started & SSH Keys

Official setup and onboarding guide for SSH Desktop. Learn how to install the native desktop binary, generate high-security Ed25519 cryptographic keys, automatically import ~/.ssh/config hosts, configure Bastion / ProxyJump tunnels, and launch your first macOS Sonoma-style cloud desktop.

Figure: Real-time visual interface of Getting Started & SSH Keys in SSH Desktop.

What is this Application & Why Do You Need It?

SSH Desktop is an agentless, open-source desktop client built with Rust (Tauri 2.0) and React 19. It connects to any remote Linux server over standard OpenSSH (Port 22) and renders a full macOS Sonoma-style visual desktop environment with 25 native management applications. Unlike legacy web control panels (cPanel, Webmin, Cockpit, Portainer), SSH Desktop requires ZERO software installed on your remote server.

Managing multiple remote servers usually requires juggling dozens of terminal windows, memorizing obscure command flags, writing error-prone config files, or running heavy web control panels that consume 200MB-500MB of remote RAM and expose vulnerable HTTP ports to the public internet. SSH Desktop eliminates this friction: all parsing, rendering, and window management occur locally on your PC, while executing standard POSIX commands over encrypted SSH channels.

Legacy Tools Replaced: PuTTY, Termius, manual ssh CLI configs

🖥️ Interface Overview & Visual Controls

The Connection Manager is the initial hub of SSH Desktop. The left sidebar displays saved server profiles organized by tags (Production, Staging, Homelab, Edge). The main view shows connection status indicators (Active, Inactive, Unreachable), server nicknames, IP addresses, and SSH port numbers. The top toolbar provides + New Connection, Import ~/.ssh/config, Quick Connect, and Settings. Double-clicking any server profile launches the desktop session immediately.

Key Capabilities & Features

  • Universal Cross-Platform: Native compiled binaries for macOS, Windows, and Linux with native OS Keychain/DPAPI credential storage.
  • Modern Cryptography: Support for Ed25519, ECDSA (nistp256/384/521), RSA (2048-4096 bit), and hardware security tokens.
  • Automated ~/.ssh/config Parser: Auto-detects existing OpenSSH hosts, parsing HostName, User, Port, IdentityFile, and ProxyJump.
  • Bastion & Jump Host Support: Transparent multi-hop SSH routing (ProxyJump bastion.example.com) for private VPC servers.
  • 100% Agentless & Zero Footprint: Leaves 0 MB RAM footprint and 0 persistent daemon processes on remote machines.

📋 Prerequisites & Remote Host Requirements

  • Local PC: macOS (Universal M1-M4 Apple Silicon & Intel x86_64), Windows 10/11 (64-bit), or Linux Desktop (AppImage, deb, rpm).
  • Remote Server: Any Linux distribution (Ubuntu 18.04+, Debian 10+, CentOS/RHEL 7+, Rocky, Alma, Fedora, Arch, Alpine, openSUSE).
  • OpenSSH Server (sshd) active and listening on port 22 or custom port on remote machine.
  • Credentials: Root or non-root user credentials with either an SSH Private Key (Ed25519/RSA) or password.

Step-by-Step How-To Tutorial

Step 1: Download & Install the Native Binary

Download the official package matching your operating system:
  • macOS: Open the Universal .dmg and drag SSH Desktop into your /Applications directory.
  • Windows: Run the signed .msi or standalone .exe installer and follow the setup wizard.
  • Linux Desktop: Execute chmod +x sshdesktop*.AppImage && ./sshdesktop*.AppImage or install via sudo dpkg -i sshdesktop*.deb.

Step 2: Generate or Configure SSH Cryptographic Keys

For optimal security, generate an Ed25519 elliptic curve keypair rather than using passwords:
# Generate a modern Ed25519 keypair ssh-keygen -t ed25519 -C "admin@sshdesktop" # Copy public key to remote host ssh-copy-id -i ~/.ssh/id_ed25519.pub user@server.example.com
SSH Desktop detects keys in ~/.ssh/ automatically.

Step 3: Establish Your First Server Connection

Click + New Connection in the top-left toolbar:
  1. Label: Enter a friendly nickname (e.g. Production Web VPS).
  2. Host / IP: Public IP or domain (e.g. 198.51.100.42 or api.example.com).
  3. Port: Default 22 or your custom SSH port.
  4. Username: Remote user (e.g. ubuntu, debian, root).
  5. Auth Mode: Choose Private Key (browse to id_ed25519) or Password.
  6. Click Connect. The Rust backend negotiates key exchange and launches your desktop session.

Step 4: Connecting Through a Bastion / Jump Server

For internal VPC servers without public IP addresses:
  1. In the connection modal, expand Advanced SSH Settings.
  2. Toggle ProxyJump / Bastion.
  3. Enter the Bastion Host IP, Port, Username, and Bastion Private Key.
  4. SSH Desktop transparently opens an encrypted channel through the bastion and connects to the private node.

💡 Pro-Tips & Best Practices

  • Use Ed25519 Keys: Ed25519 elliptic-curve keys provide stronger cryptographic security, faster handshakes, and smaller key lengths compared to legacy RSA 2048/4096 keys.
  • Tag Your Servers: Assign color-coded tags (e.g. Prod, Dev, DB) to group and search servers instantly via the top search bar.
  • ProxyJump for Private VPCs: Configure a Bastion host once in the Advanced settings to seamlessly connect to internal VPC instances without public IPv4 addresses.
  • Pin Frequent Servers: Right-click a server profile to pin it to the Quick Switcher dropdown in the top macOS-style menu bar.

Under the Hood: Linux Commands & Architecture

Negotiates key exchange using modern ciphers (curve25519-sha256, chacha20-poly1305@openssh.com, aes256-gcm@openssh.com). Fingerprints are validated against ~/.ssh/known_hosts. Channels for PTY, SFTP, and TCP sockets are multiplexed asynchronously over a single TCP stream.

Primary Commands / Virtual Files Executed Over SSH:
ssh-keygen, ssh-copy-id, ~/.ssh/config parser

❓ Troubleshooting & Frequently Asked Questions

Connection refused on port 22

Ensure the OpenSSH server daemon is running on the target machine (sudo systemctl status ssh or sshd) and that your firewall allows inbound traffic on port 22 (or your custom SSH port).

Permission denied (publickey)

Verify that your public key has been added to the remote user's ~/.ssh/authorized_keys file and that correct permissions are set on the remote host (chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys).

Host key verification failed

This occurs if the remote server was reinstalled or its SSH host key changed. In SSH Desktop, click Connection Settings → Reset Known Host Key to accept the new server fingerprint safely.
