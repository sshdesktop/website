📊 Hardware Telemetry & Monitor

Real-time CPU, Memory, Swap, Disk I/O, and Network bandwidth charts (60 FPS). Sort active processes and terminate rogue tasks with one click.

Figure: Real-time visual interface of Hardware Telemetry & Monitor in SSH Desktop.

What is this Application & Why Do You Need It?

The Hardware Telemetry & Real-Time Monitor is a 60 FPS performance monitoring dashboard. It visualizes CPU core utilization, RAM breakdown (active, cached, buffers), Swap usage, Disk I/O throughput, and Network interface bandwidth, coupled with an interactive process manager.

Terminal tools like top and htop lack historical time-series charts, while heavy monitoring agents like Datadog, New Relic, or Netdata consume significant CPU/RAM and cost hundreds of dollars monthly. SSH Desktop reads Linux performance counters with virtually zero overhead.

Legacy Tools Replaced: htop, btop, Glances, Datadog/Netdata heavy agents

🖥️ Interface Overview & Visual Controls

The Hardware Telemetry Monitor displays real-time 60 FPS performance gauges for your server. The top row features visual circular gauges for CPU Utilization, RAM Usage, Swap Activity, and Disk Root Filesystem Capacity. The middle section shows historical time-series graphs for CPU frequency and temperature, network bandwidth (rx/tx Mbps), and disk I/O throughput (read/write IOPS). The bottom section shows the top 10 resource-consuming processes with quick-terminate controls.

Key Capabilities & Features

  • 60 FPS Visual Charts: Smooth hardware-accelerated time-series graphs for CPU, RAM, Disk I/O, and Network traffic.
  • Per-Core CPU Utilization: View individual utilization across multi-core systems (up to 128 cores).
  • Detailed Memory Breakdown: Clear visualization of Used, Cached, Buffers, and Available memory.
  • Interactive Process Table: Sort processes by CPU %, Memory %, PID, or User; filter by executable name.
  • 1-Click Task Termination: Send SIGTERM (15) or forceful SIGKILL (9) to runaway or zombie processes.

📋 Prerequisites & Remote Host Requirements

  • Standard Linux OS with /proc virtual filesystem enabled (universal across all distros).
  • No root access required for basic monitoring; sudo required only to kill processes owned by other users.

Step-by-Step How-To Tutorial

1. Reading the Telemetry Dashboard

Open the Monitor app from the Dock. The top gauges display instantaneous CPU Load Average (1m, 5m, 15m), RAM usage percentage, Swap usage, and active network throughput in MB/s.

2. Sorting and Finding Heavy Processes

The bottom half features an interactive process manager. Click the CPU % or Memory % column header to sort descending. Type in the search box to filter for specific processes (e.g. node, python, mysqld).

3. Killing a Rogue Process

Select any process and click Kill Process. Choose between Graceful Shutdown (SIGTERM) to allow the app to clean up, or Force Kill (SIGKILL) to terminate it immediately.

💡 Pro-Tips & Best Practices

  • Zero Agent Overhead: Telemetry is sampled by reading Linux virtual files (/proc/stat, /proc/meminfo, /proc/net/dev) directly over SSH with zero background daemon overhead.
  • Adjust Sampling Rate: Choose between 1000ms (high detail), 3000ms (standard), or 5000ms (low bandwidth) depending on your network connection.
  • Identify Memory Leaks: Watch the RAM historical graph to detect steady memory leaks before the Linux kernel Out-Of-Memory (OOM) killer terminates critical services.
  • Inspect Thermal Sensors: The monitor automatically detects CPU thermal zones on supported hardware (Intel Core, AMD Ryzen, Raspberry Pi) to alert you to overheating.

Under the Hood: Linux Commands & Architecture

Instead of running heavy python scripts, SSH Desktop streams lightweight reads of /proc/stat, /proc/meminfo, /proc/diskstats, and /proc/net/dev. Deltas are calculated client-side to minimize remote server CPU impact.

Primary Commands / Virtual Files Executed Over SSH:
/proc/stat, /proc/meminfo, /proc/net/dev, ps aux, kill -9

❓ Troubleshooting & Frequently Asked Questions

Telemetry graphs show "Waiting for data"

Verify your SSH connection is active and that your user account has standard read permissions to /proc/stat and /proc/meminfo (readable by all users by default).
