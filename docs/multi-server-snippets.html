🌐 Multi-Server Automation

Execute shell snippets across dozens of servers simultaneously. Manage your bash script library and view real-time aggregated output side by side.

Figure: Real-time visual interface of Multi-Server Automation in SSH Desktop.

What is this Application & Why Do You Need It?

The Multi-Server Snippets & Command Broadcast tool allows you to organize a personal library of reusable shell scripts and broadcast them across multiple remote servers in parallel. Compare execution results, track exit codes, and manage infrastructure in bulk.

Performing routine maintenance (e.g. updating packages, checking disk usage, rotating logs) across 10 or 20 servers by logging into each one individually is slow and repetitive. Tools like Ansible have steep learning curves for simple tasks. Multi-Server Snippets gives you instant parallel execution with zero setup.

Legacy Tools Replaced: Ansible ad-hoc commands for simple tasks, pssh, cluster-ssh

🖥️ Interface Overview & Visual Controls

The Multi-Server Automation Hub allows executing shell snippets across dozens of servers simultaneously. The left sidebar houses your categorized Bash Snippet Library (Deployment, Maintenance, Diagnostics, Security). The center area features a parameterized script editor with variable placeholders (e.g. {{PORT}}, {{DOMAIN}}). The bottom Target Fleet Selector lets you select multiple servers or tag groups. Clicking Execute on Fleet opens an aggregated split-screen terminal showing parallel execution output.

Key Capabilities & Features

  • 4 Automation Tabs: Ad-hoc Runner, Recipes Library, Fleet Matrix, and Audit History.
  • Parallel Async Broadcast: Execute commands across 5, 20, or 50 servers simultaneously over parallel SSH channels.
  • Pre-Built DevOps Recipes: Includes ready-to-run recipes for Docker cleanup, SSL check, disk alert, and security patch.
  • Aggregated Split Output: View side-by-side terminal outputs for each server with clear Pass/Fail badges.
  • Parameterized Templates: Define placeholders in your scripts (e.g. {{PACKAGE_NAME}}) that prompt for input prior to execution.

📋 Prerequisites & Remote Host Requirements

  • Two or more configured server connections in SSH Desktop.
  • Target user accounts with permissions to run the desired commands.

Step-by-Step How-To Tutorial

1. Saving a Snippet to Your Library

Click + New Snippet. Enter a title (e.g. Check Disk & Memory) and enter your script:
echo "=== Disk Usage ===" df -h / | tail -n 1 echo "=== Memory Usage ===" free -h | grep Mem

2. Selecting Target Servers and Broadcasting

Check the servers you want to run the script on, or click Select All. Click Broadcast (Cmd+Enter). SSH Desktop opens parallel SSH connections and streams output in real time.

3. Inspecting Results Side by Side

The results view shows a grid of terminal outputs. Green checkmarks indicate an exit code of 0, while red badges highlight servers that encountered errors.

💡 Pro-Tips & Best Practices

  • Parameter Templates: Use double-curly syntax ({{VARIABLE}}) to prompt for interactive input before executing snippets on your fleet.
  • Fleet Health Checks: Create a diagnostic snippet (e.g. checking uptime, disk usage, and failed services) and run it across all production servers in 2 seconds.
  • Stop on First Error: Enable the "Halt on Error" toggle to prevent a multi-step snippet from executing subsequent commands on a server if an earlier command exits with a non-zero code.
  • Export Aggregated Logs: Save the combined execution output of all servers to a timestamped Markdown or text file for compliance reporting.

Under the Hood: Linux Commands & Architecture

Leverages Rust's async runtime (Tokio) to fan out SSH sessions concurrently. Results are streamed asynchronously into separate output buffers without blocking the UI.

Primary Commands / Virtual Files Executed Over SSH:
Parallel async SSH channels, parameterized bash templates

❓ Troubleshooting & Frequently Asked Questions

Snippet hangs on one unreachable server

SSH Desktop enforces a per-server connection timeout (default 10s). You can adjust this timeout in Automation Settings to skip unreachable servers faster.
