📦 Multi-Distro Package Manager

Visual package manager supporting APT (Ubuntu/Debian), DNF/YUM (RHEL/CentOS/Rocky), and Pacman (Arch). Search, install, update, and remove packages.

Figure: Real-time visual interface of Multi-Distro Package Manager in SSH Desktop.

What is this Application & Why Do You Need It?

The Multi-Distro Package Manager provides a unified visual interface for software management across all major Linux distributions. It automatically detects whether your server uses APT, DNF, YUM, or Pacman, allowing you to search software catalogs, inspect installed libraries, and apply security upgrades.

Managing packages across different Linux distributions means remembering distinct CLI commands (apt install vs dnf install vs pacman -S). It is easy to overlook security patches or break dependencies. SSH Desktop standardizes package operations into an intuitive, safe workflow.

Legacy Tools Replaced: Manual apt/dnf/pacman CLI commands, unattended-upgrades confusion

🖥️ Interface Overview & Visual Controls

The Package Manager auto-detects your Linux distribution and provides a unified interface for APT (Ubuntu/Debian), DNF/YUM (RHEL/CentOS/Rocky), and Pacman (Arch). The interface features 4 tabs: Installed Packages (searchable inventory with version numbers and architectures), Updates Available (security patches and upgrade candidates with changelogs), Search & Install (repository search engine with package descriptions), and Repository Sources (view and toggle APT sources or DNF repos).

Key Capabilities & Features

  • 4 Comprehensive Tabs: Curated App Catalog, Installed Packages, Pending Upgrades, and Repository Search.
  • Curated App Store: 1-click installation for popular server tools: Docker, Nginx, PostgreSQL, Redis, Node.js, Python, Git.
  • Available Upgrades Inspector: View all pending security patches and package updates with version comparisons.
  • 1-Click System Update: Run full system updates with real-time terminal output streaming.
  • Orphan & Cache Cleanup: Free disk space by running autoremove and cleaning package caches.

📋 Prerequisites & Remote Host Requirements

  • Debian/Ubuntu (APT), RHEL/CentOS/Rocky/Alma/Fedora (DNF/YUM), or Arch Linux (Pacman).
  • Sudo or root privileges to install, update, or remove system packages.

Step-by-Step How-To Tutorial

1. Checking for System Updates

Open the Package Manager. Click Check Updates. SSH Desktop updates the package repository index and lists all packages with available updates (e.g. openssl, linux-image, curl).

2. Applying Updates Safely

Select individual packages to update or click Upgrade All (System Update). A live output drawer streams the package manager's execution logs, showing progress percentages and dependency resolutions.

3. Searching and Installing New Packages

Type a package name (e.g. htop, redis-server, git) into the search bar. Click Install to install with all required dependencies.

💡 Pro-Tips & Best Practices

  • One-Click Security Updates: Navigate to the "Updates Available" tab and click "Apply Upgrades" to install security patches safely without memorizing distro commands.
  • Distro-Agnostic Operation: Manage Ubuntu, Debian, Rocky Linux, Fedora, and Arch servers using the exact same visual workflow.
  • Clean Package Cache: Use the "Clean Cache" button to safely run apt-get clean or dnf clean all and free up space in /var/cache/.
  • Review Changelogs Before Upgrading: Click on any package update candidate to view the maintainer changelog and identify potential breaking changes before applying updates.

Under the Hood: Linux Commands & Architecture

SSH Desktop runs the distro's native CLI utilities with non-interactive flags (e.g. DEBIAN_FRONTEND=noninteractive apt-get update, dnf check-update, pacman -Sy). It parses output streams and updates the package inventory.

Primary Commands / Virtual Files Executed Over SSH:
apt update && apt list --upgradable, dnf check-update, pacman -Syu

❓ Troubleshooting & Frequently Asked Questions

Could not get lock /var/lib/dpkg/lock-frontend

Another package operation (such as unattended-upgrades) is running in the background. Wait a couple of minutes or inspect active package processes in the Process Manager.

Repository signature verification failed

An external repository PGP key has expired or changed. Open the Repository Sources tab to review or update the repository configuration.
