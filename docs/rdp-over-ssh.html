🔒 RDP Over SSH Tunneling Guide

How to securely tunnel Remote Desktop Protocol (RDP port 3389) over encrypted SSH port 22. Access remote Windows servers and Linux XRDP desktops without exposing port 3389 publicly.

Figure: Real-time visual interface of RDP Over SSH Tunneling Guide in SSH Desktop.

What is this Application & Why Do You Need It?

The RDP Over SSH guide explains how to route Microsoft Remote Desktop Protocol (port 3389) traffic through an encrypted SSH tunnel created by SSH Desktop. This allows you to manage Windows VPS instances or Linux XRDP desktops securely from anywhere in the world.

Exposing raw RDP port 3389 directly to the public internet is a major security vulnerability: automated ransomware bots continuously brute-force exposed RDP ports. Tunneling RDP through SSH port 22 encrypts all session traffic, conceals port 3389 from external scanners, and requires strong SSH cryptographic key authentication to access.

Legacy Tools Replaced: Exposing raw RDP port 3389 to internet ransomware bots, complex VPN clients

🖥️ Interface Overview & Visual Controls

The Tunnel Canvas displays active tunnels with live visual traffic flow meters. Clicking the RDP tunnel card reveals connection counts, packet latency, and an Auto-Reconnect toggle that keeps the RDP tunnel alive during Wi-Fi drops.

Key Capabilities & Features

  • Complete Port Cloaking: Keep port 3389 closed in your public cloud firewall; all traffic flows over port 22.
  • End-to-End Cryptography: Protect legacy RDP ciphers with modern SSH AES-256-GCM or ChaCha20-Poly1305 encryption.
  • One-Click Tunnel Profile: Save the RDP tunnel configuration in SSH Desktop to launch it automatically on demand.
  • Cross-Platform Support: Connect to Windows Server 2019/2022/2025, Windows 10/11 Pro, and Ubuntu XRDP desktops.

📋 Prerequisites & Remote Host Requirements

  • Remote server running OpenSSH server and an RDP service (Windows Remote Desktop or Linux `xrdp`).
  • Local RDP client installed (Microsoft Remote Desktop on macOS/Windows, Remmina on Linux).
  • SSH credentials to the target host or an intermediate Linux gateway.

Step-by-Step How-To Tutorial

1. Opening SSH Port Forwarding in SSH Desktop

Connect to your remote server or gateway in SSH Desktop. Open the SSH Port Forwarding & Tunnels app from the Dock or Spotlight (Cmd+K).

2. Creating the Local RDP Tunnel Rule

Click + New Tunnel and configure:
  • Tunnel Type: Local (-L)
  • Local Port: 3389 (or 13389 if you are running a local Windows desktop)
  • Destination Host: 127.0.0.1 (or the internal LAN IP of your Windows machine)
  • Destination Port: 3389
  • Click Save & Start Tunnel.

3. Connecting with Microsoft Remote Desktop

Open your local RDP client (Microsoft Remote Desktop or mstsc.exe). In the Computer / PC Name field, enter 127.0.0.1:3389 (or the custom local port you chose). Enter your Windows username and password and click Connect.

4. Verifying Encrypted Traffic in SSH Desktop

Switch back to SSH Desktop. The RDP tunnel card shows active connection status, current bandwidth throughput, and transferred bytes flowing securely through your encrypted SSH connection.

💡 Pro-Tips & Best Practices

  • Use High Port for Multiple Desktops: If tunneling to multiple Windows machines, assign distinct local ports like 13389, 23389, and 33389.
  • Enable Network Level Authentication (NLA): Keep NLA enabled in Windows for dual-layer authentication (SSH key first, then Windows credentials).
  • Auto-Start Tunnels: Toggle "Auto-Start on Connection" so your RDP tunnel initializes automatically whenever you connect to your server profile.

Under the Hood: Linux Commands & Architecture

Multiplexes Direct-TCPIP stream over the established OpenSSH session, forwarding local TCP packets to the remote loopback interface.

Primary Commands / Virtual Files Executed Over SSH:
ssh -L 3389:localhost:3389, mstsc.exe 127.0.0.1:3389, xrdp

❓ Troubleshooting & Frequently Asked Questions

Local port 3389 already in use on Windows client

If your local PC is running Windows Pro, its local RDP service is already using port 3389. Simply set the Local Port to 13389 in SSH Desktop and connect Microsoft Remote Desktop to 127.0.0.1:13389.
