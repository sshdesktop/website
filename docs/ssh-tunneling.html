🔀 SSH Port Forwarding & Tunnels

Manage Local (-L), Remote (-R), and Dynamic SOCKS5 (-D) SSH tunnels with visual status indicators, auto-reconnect watchdog, and port conflict detection.

Figure: Real-time visual interface of SSH Port Forwarding & Tunnels in SSH Desktop.

What is this Application & Why Do You Need It?

The SSH Port Forwarding & Tunnels Manager is a visual hub for creating, monitoring, and maintaining encrypted network tunnels. It supports Local port forwarding (access remote services on localhost), Remote port forwarding (expose local ports to remote servers), and Dynamic SOCKS5 proxying.

Typing complex tunnel commands like ssh -L 8080:internal-service:80 user@server -N -f is difficult to remember and offers no monitoring when tunnels silently drop. SSH Desktop provides a visual dashboard with status indicators, bandwidth gauges, and automatic reconnection watchdogs.

Legacy Tools Replaced: Complex ssh -L / -R CLI commands, ngrok, manual tunnel scripts

🖥️ Interface Overview & Visual Controls

The SSH Tunnel Manager visualizes and controls all your background SSH port forwardings. The top toolbar provides + New Tunnel, Start All, and Stop All buttons. The tunnel table lists active tunnels with type badges (Local -L, Remote -R, Dynamic SOCKS5 -D), local listening port, remote target destination, active connection count, data transfer throughput, and a live toggle switch.

Key Capabilities & Features

  • Local Forwarding (-L): Forward remote internal services (Elasticsearch, Redis, staging websites) to a local port on your laptop.
  • Remote Forwarding (-R): Share local development servers (e.g. localhost:3000) with a remote server or team.
  • Dynamic SOCKS5 Proxy (-D): Route your local browser traffic through the remote server to bypass firewalls or inspect internal networks.
  • Auto-Reconnect Watchdog: Automatically detects broken connections and re-establishes dropped tunnels with exponential backoff.
  • Port Conflict Detection: Alerts you immediately if a requested local port is already in use by another application.

📋 Prerequisites & Remote Host Requirements

  • AllowTcpForwarding enabled in remote sshd_config (enabled by default in OpenSSH).
  • For remote reverse forwarding (-R), GatewayPorts enabled if listening on public interfaces.

Step-by-Step How-To Tutorial

1. Creating a Local Tunnel (-L)

To access an internal service running on the remote server (e.g. an internal dashboard on port 8080):
  1. Click + New Tunnel.
  2. Select Type: Local Forwarding (-L).
  3. Local Port: 8080 (port on your machine).
  4. Remote Host: 127.0.0.1, Remote Port: 8080.
  5. Click Start Tunnel. You can now open http://localhost:8080 in your browser!

2. Setting Up Dynamic SOCKS5 Proxy (-D)

Select Dynamic Proxy (-D) and enter a local port (e.g. 1080). Start the tunnel, then configure your browser or network settings to use SOCKS5 proxy 127.0.0.1:1080. All internet traffic now routes securely through your remote server.

3. Monitoring Tunnel Health & Traffic

Each active tunnel card displays real-time connection status (Green = Active, Orange = Reconnecting, Red = Error) along with transferred bytes and latency.

💡 Pro-Tips & Best Practices

  • Local Forwarding for Web Consoles: Use Local Forwarding (-L 8080:localhost:8080) to access private admin dashboards (Grafana, RabbitMQ, Jenkins) securely in your local browser.
  • Dynamic SOCKS5 Proxy: Create a Dynamic tunnel (-D 1080) and configure your local browser to route web traffic through the remote server to access internal network subnets.
  • Auto-Reconnect Watchdog: Enable "Auto-Reconnect" on critical tunnels so SSH Desktop automatically restores dropped connections if your Wi-Fi or laptop sleeps.
  • Port Conflict Detection: SSH Desktop automatically tests local ports before binding and alerts you if another local application is already occupying the port.

Under the Hood: Linux Commands & Architecture

Tunnels utilize OpenSSH's direct-tcpip and tcpip-forward channel requests. The Rust backend manages a non-blocking asynchronous event loop that forwards raw TCP sockets to SSH channels using zero-copy stream piping.

Primary Commands / Virtual Files Executed Over SSH:
ssh -L [bind]:port:host:port, ssh -D [port], tcpip-forward

❓ Troubleshooting & Frequently Asked Questions

Port already in use on local machine

Another local application is using that port. Change the local binding port (e.g. from 8080 to 8081) in the tunnel configuration modal.

Remote port forwarding (-R) refused

Ensure GatewayPorts yes is enabled in /etc/ssh/sshd_config on the remote server if you need remote forwarding accessible outside localhost.
