🔒 SSL/TLS Certificates (Certbot)

Inspect SSL certificates, monitor expiration dates, request new Let's Encrypt certificates, and automate Nginx/Apache reload on certificate renewal.

Figure: Real-time visual interface of SSL/TLS Certificates (Certbot) in SSH Desktop.

What is this Application & Why Do You Need It?

The SSL/TLS Certificates Manager provides an automated dashboard for Let's Encrypt (Certbot) and custom SSL certificates. Monitor certificate validity, inspect Subject Alternative Names (SANs), check expiration countdowns, and issue or renew certificates with automated web server reloads.

Expired SSL certificates cause browser security warnings, breaking website traffic and API integrations. Checking certificate expiration via OpenSSL CLI (openssl x509 -enddate -noout) across multiple domains is slow and error-prone. SSH Desktop displays expiration alerts before certificates lapse.

Legacy Tools Replaced: certbot renew CLI, openssl x509 -text manual inspection

🖥️ Interface Overview & Visual Controls

The SSL/TLS Certificate Manager tracks website certificates and simplifies Let's Encrypt / Certbot management. The Certificates Inventory lists all installed certificates, domain names (SANs), Issuer (Let's Encrypt, DigiCert, Cloudflare), Expiration Date, and an Expiration Countdown badge (Green = Healthy, Yellow = Expiring Soon, Red = Expired). The Issue Certificate Tab provides a visual form to request new Let's Encrypt certificates with HTTP-01 or DNS-01 challenges. The Diagnostics Tab tests live SSL handshakes and verifies TLS cipher suites.

Key Capabilities & Features

  • 5 SSL Management Tabs: Certificates Overview, Issue New Cert, Automated Renewal Hub, Self-Signed Generator, and Diagnostics.
  • Expiration Countdown Badges: Visual badges show days remaining until certificate expiration (Green > 30d, Orange < 30d, Red < 7d).
  • 1-Click Let's Encrypt Issuance: Request new certificates with HTTP-01 or DNS-01 challenges directly from the GUI.
  • Automated Web Server Reload: Automatically tests and reloads Nginx, Apache, or Caddy upon successful renewal.
  • Self-Signed SSL Generator: Issue self-signed certificates in seconds for internal testing and staging environments.

📋 Prerequisites & Remote Host Requirements

  • Certbot or OpenSSL installed on the remote server.
  • DNS records properly pointing to the server for Let's Encrypt domain validation.

Step-by-Step How-To Tutorial

1. Monitoring Certificate Validity

Launch the SSL Manager. All detected certificates across /etc/letsencrypt/live/ and custom paths are displayed with their domain names and expiration countdowns.

2. Renewing Certificates with 1 Click

Click Renew All or select an individual certificate and click Renew. SSH Desktop executes certbot renew, streams output, and triggers a web server reload upon success.

3. Requesting a New Let's Encrypt Certificate

Click + New Certificate. Enter your domain names (e.g. example.com, www.example.com), select your web server (Nginx or Apache), and enter your notification email. Click Issue Certificate to run automated provisioning.

💡 Pro-Tips & Best Practices

  • Automated Web Server Reload: When issuing or renewing certificates through the UI, SSH Desktop automatically tests web server configs (nginx -t) and reloads the server safely.
  • Multi-Domain SANs: Enter comma-separated domain names (e.g. example.com, www.example.com, api.example.com) to combine multiple hostnames into a single certificate.
  • Wildcard Certificates via DNS: Select the DNS-01 challenge mode to generate wildcard certificates (*.example.com) without exposing port 80 to the public web.
  • Expiration Alerts: Badges turn yellow at 30 days remaining and red at 7 days remaining, providing ample warning before certificates expire and cause browser errors.

Under the Hood: Linux Commands & Architecture

Runs certbot certificates and openssl x509 -in <cert> -text -noout. Parses validity timestamps and compares them against system UTC time to compute days remaining.

Primary Commands / Virtual Files Executed Over SSH:
certbot certificates, certbot renew, openssl x509 -in cert.pem -text

❓ Troubleshooting & Frequently Asked Questions

Let's Encrypt challenge failed (404 Not Found)

Ensure domain DNS records point correctly to your server's public IP and that port 80 (HTTP) is open in your firewall so ACME verification requests can reach your server.

Certbot rate limit reached

Let's Encrypt limits certificate issuance to 5 identical certificates per week. Use the "Staging Environment" toggle in settings to test issuing configurations without burning rate limits.
