⚙️ Systemd Services & Timers

Visual management for Linux systemd units. Start, stop, restart, enable, or disable services, inspect unit files, and stream live journalctl logs.

Figure: Real-time visual interface of Systemd Services & Timers in SSH Desktop.

What is this Application & Why Do You Need It?

The Systemd Services & Timers Manager is a graphical interface for inspecting and controlling all systemd services, sockets, and timers running on your Linux host. View service health, toggle boot behavior, and read logs without memorizing systemctl CLI flags.

Diagnosing failed services in systemd often requires running multiple commands: systemctl status <unit>, journalctl -u <unit> -e, and checking unit files in /etc/systemd/system/. SSH Desktop consolidates unit states, controls, unit file editing, and log streaming into one clean dashboard.

Legacy Tools Replaced: systemctl CLI, journalctl manual tailing, service status scripts

🖥️ Interface Overview & Visual Controls

The Systemd Services Manager provides a complete graphical interface for Linux systemd units. The top filter bar includes a search box, category tabs (Services, Timers, Sockets, Targets), and status filters (All, Running, Failed, Disabled). The main units list displays service unit names, descriptions, load states, active states, and sub-states. Right-clicking any unit opens quick controls: Start, Stop, Restart, Enable, Disable, View Journal Logs, and Edit Unit File.

Key Capabilities & Features

  • Real-Time Unit States: Instantly filter services by Active, Inactive, Failed, or Masked status.
  • 1-Click Lifecycle Controls: Start, Stop, Restart, and Reload services with safety confirmation.
  • Enable on Boot: Toggle whether a service launches automatically at server startup with one switch.
  • Live Journalctl Log Stream: Stream live unit logs with colorized error levels and timestamp filtering.
  • Visual Unit File Editor: Inspect and edit .service definitions with automatic systemctl daemon-reload.

📋 Prerequisites & Remote Host Requirements

  • Linux distribution using systemd (Ubuntu, Debian, RHEL, CentOS, Rocky, Fedora, Arch, openSUSE).
  • Sudo or root permissions to start, stop, restart, or enable services.

Step-by-Step How-To Tutorial

1. Inspecting Services and Filtering Failed Units

Launch the Services app. The top summary counters display Total Units, Running Units, and Failed Units. Click the red Failed badge to instantly filter all services that crashed or failed to start.

2. Starting, Stopping and Restarting Services

Click any service (e.g. nginx.service, postgresql.service, docker.service). Click Restart to restart the process. A progress spinner appears while systemd reboots the daemon.

3. Streaming Live Service Logs (journalctl)

Click the Logs tab inside any unit card. SSH Desktop streams output directly from journalctl -u <service> -f. Errors and warnings are highlighted in red and yellow.

4. Editing Service Definitions

Click Edit Unit File to view the unit's configuration in the Monaco editor. Modify ExecStart, environment variables, or restart policies, and click Save & Reload to automatically execute systemctl daemon-reload.

💡 Pro-Tips & Best Practices

  • Failed Units Filter: Click the "Failed" badge in the filter bar to immediately isolate crashed services across your server after reboot or system updates.
  • Live Journalctl Streaming: Click the log icon next to any service to stream live journalctl -u <service> -f output with real-time autoscroll.
  • Safe Unit Editing: Edit systemd service unit files directly in Monaco; saving automatically triggers systemctl daemon-reload in the background.
  • Inspect Systemd Timers: Switch to the Timers tab to see when scheduled systemd cron-replacement jobs next trigger and how long until execution.

Under the Hood: Linux Commands & Architecture

Runs systemctl list-units --type=service --all --no-pager --output=json. Log streaming connects to journalctl -u <unit> -n 100 -f -o short-iso over an asynchronous SSH stream.

Primary Commands / Virtual Files Executed Over SSH:
systemctl list-units --type=service, systemctl restart, journalctl -u -f

❓ Troubleshooting & Frequently Asked Questions

Service restart fails with "exit-code"

Click "View Journal Logs" next to the service to review systemd stderr output and locate the specific configuration syntax or permission error.

Changes to unit file not taking effect

SSH Desktop executes systemctl daemon-reload automatically on save. If editing manually in terminal, always run sudo systemctl daemon-reload.
