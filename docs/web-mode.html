Getting Started & Core

🌐 Web Mode & Headless Daemon

Deploy SSH Desktop as a lightweight headless daemon on any Linux VPS using our audited 1-line script. Access your complete cloud desktop GUI securely from any browser on phones, tablets, or laptops.

Figure: Real-time visual interface of Web Mode & Headless Daemon in SSH Desktop.

What is this Application & Why Do You Need It?

Web Mode is the headless daemon version of SSH Desktop. It compiles the Rust backend into a standalone binary with an embedded HTTP/WebSocket server. It serves the complete macOS Sonoma cloud desktop and all 25 native applications directly in any modern browser (Chrome, Safari, Firefox, Edge) without installing client software on your device.

Engineers often need to manage servers from locked corporate laptops, iPads, Chromebooks, or mobile devices where installing desktop applications or storing private keys is prohibited. Web Mode allows you to log in via browser with end-to-end HTTPS encryption and manage your servers with zero setup on the client device.

Legacy Tools Replaced: cPanel, Cockpit, Guacamole, Cloud Commander

🖥️ Interface Overview & Visual Controls

The Web Mode Interface delivers the complete macOS Sonoma-style cloud desktop inside any modern web browser (Chrome, Safari, Firefox, Edge). The browser window displays the top menu bar with server switcher, clock, and battery/network status, the floating window workspace in the center, and the macOS-inspired Dock at the bottom. A side quick-access drawer allows toggling between multi-server sessions with touch gestures on mobile devices and tablets.

Key Capabilities & Features

  • 30-Second 1-Line Installer: Automated bash installer that downloads pre-compiled binaries, configures systemd, and starts the service.
  • Full Mobile & Tablet Support: Responsive touch controls, virtual on-screen keys, and fluid mobile window management for iPad and Android tablets.
  • WebSocket PTY Streaming: Zero-latency interactive terminal emulation powered by Xterm.js over secure WebSockets (WSS).
  • Low Resource Consumption: Consumes less than 28MB of RAM on the host server.
  • Nginx / SSL Integration: Easily secure Web Mode behind Let's Encrypt SSL/TLS using standard Nginx reverse proxy directives.

📋 Prerequisites & Remote Host Requirements

  • Any remote Linux server or VPS (Ubuntu 20.04+, Debian 11+, CentOS/RHEL 8+, Rocky, Alma, Arch).
  • Root or sudo access to install the systemd service.
  • Ports 2222 (Web UI) and 2020 (API backend) available, or an existing reverse proxy (Nginx/Caddy).

Step-by-Step How-To Tutorial

Step 1: Run the 1-Line Installation Script

SSH into your server and run our audited installation command:
curl -fsSL https://sshdesktop.com/install.sh | sudo bash
This script detects your Linux distribution and architecture (x86_64 or aarch64/ARM64), installs the binary to /usr/local/bin/sshdesktop-daemon, creates the systemd unit, and enables it on boot.

Step 2: Verify the Systemd Service

Check that the daemon is active and running:
sudo systemctl status sshdesktop.service
You should see Active: active (running). By default, the web interface listens on port 2222 and the API backend on port 2020.

Step 3: Access via Web Browser

Open your web browser and navigate to:
http://YOUR_SERVER_IP:2222
Log in with your Linux system credentials. Once logged in, your full cloud desktop shell opens in the browser window!

Step 4: Securing Web Mode with SSL & Nginx (Recommended)

To secure your Web Mode instance with HTTPS and a custom domain (e.g. panel.example.com), configure Nginx as a reverse proxy:
server { listen 80; server_name panel.example.com; return 301 https://$host$request_uri; } server { listen 443 ssl http2; server_name panel.example.com; ssl_certificate /etc/letsencrypt/live/panel.example.com/fullchain.pem; ssl_certificate_key /etc/letsencrypt/live/panel.example.com/privkey.pem; location / { proxy_pass http://127.0.0.1:2222; proxy_http_version 1.1; proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade"; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto $scheme; } }

💡 Pro-Tips & Best Practices

  • Run Behind Nginx or Caddy: Always deploy Web Mode behind a reverse proxy with Let's Encrypt SSL/TLS enabled to ensure end-to-end encrypted WebSocket traffic.
  • Enable HTTP Basic or OAuth Auth: Protect your Web Mode instance with HTTP authentication or Cloudflare Access for an extra layer of perimeter defense.
  • Mobile Tablet Optimization: Add the SSH Desktop Web Mode URL to your iPad or Android tablet home screen for a full-screen, native-feeling remote cloud workstation.
  • Headless Daemon Management: Use systemctl status sshdesktop to monitor daemon health and inspect execution logs directly.

Under the Hood: Linux Commands & Architecture

The Web Mode daemon runs as a sandboxed daemon exposing an Axum/Actix HTTP server for static assets and WebSocket endpoints for binary PTY streams. Client authentication verifies Linux PAM credentials.

Primary Commands / Virtual Files Executed Over SSH:
curl -fsSL install.sh, systemctl start sshdesktop, Nginx reverse proxy

❓ Troubleshooting & Frequently Asked Questions

WebSocket connection closed immediately

Ensure your reverse proxy (Nginx or Caddy) is configured to upgrade WebSocket connections with Upgrade $http_upgrade and Connection "upgrade" headers.

Web daemon fails to bind port 2222

Verify no other service is using port 2222 with sudo ss -tulpn | grep 2222. You can change the port in /etc/sshdesktop/config.json and restart the service.
