Systemd Architecture

The Single Service File Architecture

Inspect the standard service definition located at /etc/systemd/system/sshdesktop.service.

[Unit] Description=SSH Desktop Server Daemon (Frontend: 2222, Backend: 2020) After=network.target ssh.service sshd.service Wants=network.target [Service] Type=simple ExecStart=/usr/local/bin/sshdesktop --server --frontend-port 2222 --backend-port 2020 Restart=always RestartSec=5s LimitNOFILE=65535 Environment="FRONTEND_PORT=2222" Environment="BACKEND_PORT=2020" [Install] WantedBy=multi-user.target

FAQ

Frequently Asked Questions

What ports does SSH Desktop Web Mode use?

SSH Desktop Web Mode uses Frontend Port 2222 for the browser graphical interface and Backend Port 2020 for the core API and WebSocket terminal bridge. Both are coordinated by a single systemd service.

Do I need to install any client-side software on my laptop or tablet?

No. SSH Desktop Web Mode is 100% client-free. It renders the authentic macOS Sonoma desktop shell, terminal, and all 25 administration tools directly inside any modern web browser using HTML5, WebGL, and WebSockets.

Can I configure custom ports other than 2222 and 2020?

Yes. You can override the ports at any time using command flags: sshdesktop --server --frontend-port <port> --backend-port <port> or by editing the Environment variables in /etc/systemd/system/sshdesktop.service.

How does authentication work in Web Mode?

During initial setup, SSH Desktop generates a cryptographically secure admin token and password stored locally in /var/lib/sshdesktop/initial-admin-credentials.txt. You log in via this token and can create role-based users or integrate with Linux PAM.
